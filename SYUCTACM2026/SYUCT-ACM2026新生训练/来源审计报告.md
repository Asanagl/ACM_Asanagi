## 二、证据来源与方法

只使用可复核的本地证据，不依赖记忆或推断：

1. **版本控制**：`git log --all -- problemsets`、`git check-ignore -v`、`.gitignore` 内容。
2. **验证记录**：`验证记录/eropch-blog-.tmp/`（5065 个文件）中的盲审提示词 `prompt*.md`、模型会话 `*.jsonl`（含 session_id、限流/配额错误）、返回稿 `response*`、验证笔记 `verification*.md`，以及其中写入的题面 SHA-256。
3. **内容指纹**：对每个文件计算 SHA-256，与记录中的哈希、工具链模板哈希比对。
4. **生成链元数据**：29 份 `exported-tests/manifest.json` 的 `exportedAt` / `caseCount` / `workspace`；Hydro 包内 `problem.yaml` 的 `pid`。
5. **复现实验**：重新编译 generator，按 config 的 `(type, seed)` 生成并与导出文件逐字节比对。

> 由于题目文件均为本地生成，“来源”记录的是**生成方式 + 可核验依据**，而不是外部仓库路径。凡无法用上述证据闭环的，一律标低置信度并在第五节单列。

## 三、全局性发现

### 3.1 无版本控制历史

```text
$ git -C eropch-blog log --all --oneline -- problemsets     # 空输出
$ git -C eropch-blog check-ignore -v problemsets/...       # .gitignore:22:problemsets/
$ git -C eropch-blog status --porcelain --ignored -- problemsets   # !! problemsets/
```

题目目录被显式忽略，**不存在任何提交记录**。所有文件的时间只能取文件系统 mtime，而 mtime 在 2026-10-26 的迁移中已被重写（见 5.5），不能用于推断原始创建时间。

### 3.2 工具链同样无 git 元数据

`工具链/icpc-problem-creator/` 内没有 `.git`，只有 `.github/`、`LICENSE`、`ThirdPartyLicenses/`。该工具链自身的上游仓库与提交无法从本地确认。

### 3.3 生成链是唯一能完全闭环的部分

对 29 题各抽 3 个 case（覆盖 sample 与 secret），用当前 generator 重新生成：**87/87 与导出文件字节一致**。因此 `exported-tests/**` 的 2080 个数据文件全部可由 `config.json` 的 `(type, seed)` 确定性重建。

### 3.4 会话与模型标识（可核验）

从记录文本中可提取到以下可直接复核的标识：

| 标识 | 出现次数 | 说明 |
| --- | ---: | --- |
| `kimi version 2.2.0` | 40 | 盲审是通过 Kimi CLI 2.2.0 发起的，会话日志为 `*.jsonl` / `stderr.log` |
| `wb2api/deepseek-v4.1-flash` | 20 | 部分会话显式绑定了该模型（写在验证笔记正文里） |
| `claude-code` | 2 | 少量记录来自另一套 CLI |
| `session_<uuid>` | 45 个不同会话 | 每个盲审/验证会话都有独立 ID，可用 `kimi -r <id>` 追溯 |
| 含 `429` / `Insufficient user quota` 的文件 | 211 | 限流与配额耗尽频繁发生，是部分记录残缺、需要重跑的直接原因 |

结论：**同一批文件由多套工具链、多个模型会话共同产出**，没有统一署名，也没有提交记录。能追到的是“哪个会话、哪个模型客户端”，追不到“哪个作者、哪个 commit”。
