题面输入格式漏了 `n`。只给 `k` 和跳跃区间无法确定答案，例如相同跳跃数据下，终点是 10 和 100 的答案不同。下面按第一行输入 `n k` 实现；若题目保证 `n=max(b)`，可在读入时取最大 `b`。

核心是维护“操作数与能量”的 Pareto 最优状态：

- 到达位置 `x` 时定义 `D=操作数-x`、`E=能量-x`。
- 普通行走后 `D、E` 都不变。
- 从 `a` 跳到 `b`：
  - 需要 `E >= 1-a`
  - `D -= b-a-1`
  - `E -= b-a+1`
- 若一个状态操作更少且能量更多，它会永久优于另一个状态，可以删除。

```cpp
#include <algorithm>
#include <iostream>
#include <limits>
#include <map>
#include <utility>
#include <vector>

using namespace std;
using i64 = long long;

// frontier: key 为 E，value 为 D。
// 按 E 递增时，D 也严格递增。
void addLabel(map<i64, i64>& frontier, i64 e, i64 d) {
    auto it = frontier.lower_bound(e);

    // E 不小于 e 且 D 不大于 d，说明新状态被支配。
    if (it != frontier.end() && it->second <= d) {
        return;
    }

    // 相同 E 的旧状态更差。
    if (it != frontier.end() && it->first == e) {
        it = frontier.erase(it);
    }

    // 删除被新状态支配的状态。
    while (it != frontier.begin()) {
        auto prevIt = prev(it);
        if (prevIt->second < d) {
            break;
        }
        frontier.erase(prevIt);
    }

    frontier.emplace_hint(it, e, d);
}

bool isDominated(const map<i64, i64>& frontier, i64 e, i64 d) {
    auto it = frontier.lower_bound(e);
    return it != frontier.end() && it->second <= d;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    i64 n;
    int k;
    cin >> n >> k;

    vector<pair<i64, i64>> edges(k);
    vector<i64> coordinates = {1, n};

    for (auto& [a, b] : edges) {
        cin >> a >> b;
        coordinates.push_back(a);
        coordinates.push_back(b);
    }

    sort(coordinates.begin(), coordinates.end());
    coordinates.erase(
        unique(coordinates.begin(), coordinates.end()),
        coordinates.end()
    );

    int m = static_cast<int>(coordinates.size());

    // outgoing[i] 保存从 coordinates[i] 出发的跳跃终点下标。
    vector<vector<int>> outgoing(m);

    for (auto [a, b] : edges) {
        int ai = lower_bound(coordinates.begin(), coordinates.end(), a)
                 - coordinates.begin();
        int bi = lower_bound(coordinates.begin(), coordinates.end(), b)
                 - coordinates.begin();
        outgoing[ai].push_back(bi);
    }

    // pending[i] 是跳跃后在 coordinates[i] 才能生效的状态。
    vector<map<i64, i64>> pending(m);
    map<i64, i64> active;

    // 位置 1：操作数 0、能量 0，因此 D=E=-1。
    addLabel(active, -1, -1);

    for (int i = 0; i < m; ++i) {
        i64 x = coordinates[i];

        // 激活恰好到达 x 的跳跃状态。
        for (auto [e, d] : pending[i]) {
            addLabel(active, e, d);
        }
        pending[i].clear();

        // 尝试所有从 x 出发的跳跃。
        for (int destination : outgoing[i]) {
            i64 length = coordinates[destination] - x;

            // 实际能量为 x+E，至少需要 1。
            auto it = active.lower_bound(1 - x);

            for (; it != active.end(); ++it) {
                i64 oldE = it->first;
                i64 oldD = it->second;

                i64 newD = oldD - (length - 1);
                i64 newE = oldE - (length + 1);

                // 当前已有状态可以直接走到终点并支配它。
                if (isDominated(active, newE, newD)) {
                    continue;
                }

                addLabel(pending[destination], newE, newD);
            }
        }
    }

    i64 bestD = numeric_limits<i64>::max();
    for (auto [e, d] : active) {
        bestD = min(bestD, d);
    }

    cout << n + bestD << '\n';
    return 0;
}
```

设任意时刻最多有 `F` 个不被支配的状态：

- 时间复杂度：`O(kF log F + k log k)`
- 空间复杂度：最坏 `O(kF)`
- 因为能量和位置均为整数且 `-n <= E <= -1`，所以 `F <= n`，最坏时间为 `O(kn log n)`。

该实现不需要遍历没有跳跃的站点，因此当 `n` 很大而 `k` 较小时，比直接建立 `(位置, 能量)` 二维 DP 更合适。

> 详细讲解思路

先说明一个题面问题：输入中必须提供 `n`。只给 `k` 和跳跃区间，无法知道终点在哪里。下面默认输入为：

```text
n k
a1 b1
a2 b2
...
ak bk
```

## 1. 为什么普通最短路不够

到达同一个站点时，只记录“最少操作数”是不正确的。

例如某条路径可以很快到达站点 `x`，但能量为 `0`；另一条路径虽然多走了几步，却积累了很多能量，可以继续进行多次跳跃。因此在每个位置，需要同时考虑：

- 已经使用的操作数
- 当前拥有的能量

直接使用状态 `(位置, 能量)` 做 DP，可能需要 `O(n²)` 个状态。我们可以利用“普通行走同时增加位置、操作数和能量”的特点压缩状态。

## 2. 消除普通行走的影响

假设当前位于 `x`：

- 已使用操作数为 `cost`
- 当前能量为 `energy`

定义两个新变量：

```text
D = cost - x
E = energy - x
```

如果普通行走一步：

```text
x      -> x + 1
cost   -> cost + 1
energy -> energy + 1
```

于是：

```text
D' = (cost + 1) - (x + 1) = D
E' = (energy + 1) - (x + 1) = E
```

也就是说，普通行走不会改变 `(D,E)`。

因此，一条路径到达某个位置后，无论继续普通行走多少步，它的 `(D,E)` 都保持不变。我们不再需要逐个枚举没有跳跃的站点。

## 3. 跳跃如何改变状态

考虑从 `a` 跳到 `b`，令：

```text
length = b - a
```

跳跃前：

```text
cost = a + D
energy = a + E
```

跳跃需要至少一点能量，所以必须满足：

```text
a + E >= 1
E >= 1 - a
```

跳跃后操作数增加 `1`，能量减少 `1`：

```text
newCost   = a + D + 1
newEnergy = a + E - 1
```

在位置 `b` 对应的新状态为：

```text
newD = newCost - b
     = D - (b - a - 1)

newE = newEnergy - b
     = E - (b - a + 1)
```

所以跳跃转移为：

```text
D -= length - 1
E -= length + 1
```

## 4. 状态支配关系

假设有两个已经可以走到当前位置的状态：

```text
A = (D1,E1)
B = (D2,E2)
```

如果：

```text
D1 <= D2
E1 >= E2
```

那么状态 `A` 一定优于状态 `B`：

- 在任何位置，`A` 使用的操作数都不更多
- 在任何位置，`A` 拥有的能量都不少
- `B` 能执行的后续跳跃，`A` 也一定能执行

因此可以直接删除 `B`。

保留下来的状态称为 Pareto 前沿。使用 `map<E,D>` 保存时，随着 `E` 增大，`D` 必须严格增大，否则就会出现支配关系。

代码中的 `addLabel()` 完成三件事：

1. 判断新状态是否已被支配。
2. 删除相同 `E` 下操作数更多的状态。
3. 删除所有被新状态支配的旧状态。

## 5. 为什么需要 pending

假设从 `a` 跳到了 `b`，这个新状态只能在位置 `b` 开始使用。

不能在处理位置 `a` 时立即把它加入全局状态，否则可能错误地使用起点位于 `(a,b)` 内的跳跃。实际上，我们已经直接越过了这些站点。

因此维护：

```text
active      已经到达当前位置，可以继续普通行走的状态
pending[b]  通过跳跃到达 b，但在处理 b 前不能使用的状态
```

按位置从小到大扫描事件点。事件点只需要包括：

```text
1、n、所有跳跃起点、所有跳跃终点
```

处理位置 `x` 时：

```text
1. 将 pending[x] 合并到 active
2. 遍历所有从 x 出发的跳跃
3. 从 active 中选择 E >= 1-x 的状态
4. 计算跳跃后的新状态
5. 放入 pending[b]
```

普通行走不改变 `(D,E)`，所以两个事件点之间不需要做任何处理。

## 6. 初始状态和答案

起点为 `1`，初始操作数和能量都是 `0`：

```text
D = 0 - 1 = -1
E = 0 - 1 = -1
```

所以初始状态为：

```text
(-1,-1)
```

到达终点 `n` 时：

```text
D = cost - n
cost = n + D
```

因此最终答案为：

```text
n + active 中最小的 D
```

不使用任何跳跃时 `D=-1`，答案就是 `n-1`，与普通行走结果一致。

## 7. 正确性依据

扫描到位置 `x` 时，`active` 保存所有能够到达 `x` 的非支配状态：

- 普通行走不改变状态，所以已激活状态可以一直保留。
- 所有到达 `x` 的跳跃状态都会在 `pending[x]` 中被激活。
- 每条从 `x` 出发的跳跃都会枚举所有能量足够的非支配状态。
- 被删除的状态已有操作更少、能量更多的状态替代，不可能产生更优答案。
- 跳跃结果只在终点激活，因此不会使用被跳过区间中的跳跃。

由位置递增归纳，可以保证没有遗漏任何可能成为最优解的路径。

## 8. 复杂度

设任意时刻 Pareto 前沿最多有 `F` 个状态，所有跳跃总共枚举了 `G` 个状态：

```text
时间：O(k log k + G log F)
空间：O(kF)
```

每条边最多枚举 `F` 个状态，因此：

```text
G <= kF
```

对任意有效状态都有：

```text
-n <= E <= -1
```

所以 `F <= n`，最坏时间复杂度为：

```text
O(kn log n)
```

实际数据中大量状态会被支配删除，`F` 通常远小于 `n`。相比直接建立 `(位置,能量)` 二维 DP，这个方法还避免了遍历所有没有跳跃的站点。
