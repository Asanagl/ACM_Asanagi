# 大小写互换题解

## 思路

设输入字符串为 $s$，长度为 $n$。题目要求对每个位置独立地改写字符，所以只需要一次从左到右的扫描，对每个字符 $c$ 分三种情况：

- 若 `A` $\le c\le$ `Z`，把它换成 `c + 32`，即对应的小写字母；
- 否则若 `a` $\le c\le$ `z`，把它换成 `c - 32`，即对应的大写字母；
- 否则（空格、数字、标点等）什么都不做。

处理完所有字符后输出整行。因为空格也是数据，读入时要用 `std::getline` 读整行，不能用 `cin >> s`。

本题有两条互不相同的实现路线，主解与独立参考解各用一条：

- 主解用 `<cctype>` 的 `std::isupper` / `std::islower` / `std::tolower` / `std::toupper`，并先把 `char` 转成 `unsigned char` 再传入（`cctype` 函数对负值实参是未定义行为）。
- 独立参考解不用任何库函数，直接比较 ASCII 区间并做加减 `32` 的算术。

两条路线执行的是同一个规则，因此输出必须完全一致。

## 正确性证明

记原字符串为 $s_0$，程序中的字符串为 $s$。我们证明如下的循环不变式：在处理第 $i$ 个字符之前（$0\le i\le n$），

> $s[0..i-1]$ 的每个字符等于 $s_0$ 对应位置的题目要求结果，且 $s[i..n-1]$ 仍等于 $s_0[i..n-1]$。

**初始化：** $i=0$ 时前半段为空，后半段就是整个 $s_0$，不变式成立。

**保持：** 假设处理到 $i$ 时不变式成立。这一步只看 $s[i]$，三种情况互斥且穷尽：

1. $s[i]$ 是 `A`–`Z`。ASCII 中大小写字母各连续排列且相差 $32$，所以 `s[i] + 32` 正好是同一个字母的小写形式，符合要求。
2. $s[i]$ 是 `a`–`z`。同理 `s[i] - 32` 正好是同一个字母的大写形式，符合要求。
3. $s[i]$ 不是英文字母。不变换，符合"其余字符保持原样"。

其余位置未被写入，所以处理后 $s[0..i]$ 都已是要求的结果，而 $s[i+1..n-1]$ 未动，不变式对 $i+1$ 成立。

**终止：** 循环在 $i=n$ 结束，不变式前半段覆盖整个字符串，即 $s$ 的每个位置都等于题目要求的结果。

**输入与输出：** `getline` 读取到行末换行符为止，保留所有空格，因此读入的字符串与题面中的 $s$ 完全相同；变换只做原地替换，不插入、不删除字符，所以输出长度等于 $n$。最后再输出一个换行，恰好构成题目要求的一行。由于每个位置的规则是确定的，正确答案唯一，上述论证说明程序输出就是这个唯一答案。

## 复杂度

- 时间复杂度：$O(n)$。读入、逐字符判断与输出各扫描一遍，每个字符只做常数次比较。
- 空间复杂度：$O(n)$ 用于存放字符串；除字符串外只用了常数个变量，额外辅助空间 $O(1)$。

$n\le 1000$，在 1000ms / 256MiB 下余量极大。任何正确算法都必须至少读入并检查全部 $n$ 个字符，因此线性时间是本题的渐进下界。

## 边界情况

- $|s|=1$：只有一个字符，循环必须执行一次。`for (size_t i = 0; i + 1 < s.size(); ++i)` 这类写法会让单字符输入完全不被处理。
- 全部由空格组成（如 $1000$ 个空格）：输出仍应是同样的 $1000$ 个空格加一个换行，不能变成空行。
- 首尾有空格：样例 2 的输入首尾各有两个空格，输出必须逐个保留，不能 `trim`。
- 纯数字、纯标点：全部原样输出，用来检验"无差别异或 $32$"这类错误。
- 字母边界：`A`、`Z`、`a`、`z` 必须分别正确转换，且 `Z`（90）与 `a`（97）之间的 `[ \ ] ^ _ \`` （91–96）六个字符不能被误改。
- $|s|=1000$ 上限、以及 $999$ 这种近上限长度，都要能正常处理。
- 输出只允许一行：多打一个空行或多余提示文字都会被判错。

## 三层错解与定向数据

按"思路 / 复杂度 / 实现"三层枚举本题特有的错误：

| 层次 | 错解 | 错误表现 | 击杀数据 |
|---|---|---|---|
| 思路 | `wrong-oneway` | 只把大写改小写，忘记反方向 | `kill-oneway`（`aAzZ09 !`）、`lower-alphabet`、`min-lower`、全部随机字母串 |
| 思路 | `wrong-position` | 按位置奇偶决定是否转换，而不是看字符本身 | `kill-position`（`aA0z`）、`alternating-*`、`repeated-*` |
| 复杂度 | —— | 本题必须读完全部 $n$ 个字符，正确算法已是 $O(n)$，没有可自然构造的超复杂度实现；人为死循环只是 TLE 噪音，不设此类错解 | —— |
| 实现 | `wrong-token` | 用 `cin >> s` 按空白读词，丢失空格与后半行 | `kill-token`（`a B`）、`leading-trailing-spaces`、`spaces-only`、所有含空格数据 |
| 实现 | `wrong-xor` | 对所有字符无差别异或 $32$，误改空格、数字、标点 | `kill-xor`（`09 !~`）、`nonletters-all`、`ascii-all` |
| 实现 | `wrong-skip-last` | 循环条件写错，漏掉最后一个字符 | `kill-last`（`!a`）、`min-*` 全部单字符数据 |
| 实现 | `wrong-range` | 把判断写成 `'A' <= c && c <= 'z'`，误改 91–96 的六个字符 | `kill-range`（`[`、`\`、`]`、`^`、`_`、反引号 加 `aZ`）、`ascii-all`、`max-cycle` |

六个错解都在静态 secret 数据上被 checker 稳定判为答案错误（WA），它们都能正常读到输入、正常结束进程，不依赖运行时异常或崩溃来"击杀"。其中 `wrong-range` 与 `wrong-oneway` 与 `kill-range`、`kill-oneway` 这两组定向数据是一一对应的最小反例。

## 校验器的行尾处理

本题的输入是一条会话行，行尾既可能是 LF，也可能是 CRLF。testlib 的 `registerValidation` 会把 `inf.strict` 置为 `true`，而在 Windows 上严格模式的 `InStream::eoln()` 只接受 CRLF：遇到纯 LF 输入时它把 LF 退回缓冲区、永远返回 `false`，于是 `while (!inf.eoln())` 再也无法推进，校验器会**挂死**而不是报错。因此本校验器在 `registerValidation` 之后显式设置 `inf.strict = false`，再用 `inf.readLine()` 读整行，这样 LF / CRLF / 无行尾三种输入都能被正常处理，长度与字符集检查照旧生效。

实测（`src/validator/validator.cpp` 编译为 `val.exe`，`<` 重定向喂入）：

| 输入 | 结果 |
|---|---|
| `abc` + LF | 通过（修复前挂死，`timeout` 返回 124） |
| `abc` + CRLF | 通过 |
| `abc`（无行尾） | 通过 |
| 空文件 | 拒绝：`s must contain at least 1 character` |
| 1001 个 `a` | 拒绝：`at most 1000 characters` |
| 含制表符 `a\tb` | 拒绝：`found 9` |
| 两行 `a\nb` | 拒绝：`Expected EOF` |
| 1000 个空格 | 通过 |

## 独立盲审

公开题面与约束冻结后，另起一个只读会话，仅向审阅者提供题面、样例、约束与评测语义，不提供工作区路径、算法、生成器或任何代码。审阅者独立复述了任务，给出的算法是"`getline` 读整行 + 对每个字符做 `A..Z` / `a..z` / 其它三分支替换"，与主解思路一致；其 C++17 实现直接比较 ASCII 区间，成为 `src/solution2.cpp` 的基础（本仓库版本去掉了对 `\r` 的额外兜底，因为 validator 已把字符限制在 32–126）。盲审还独立指出 `cin >> s` 丢空格、`'A' <= c <= 'z'` 误伤 91–96、以及无差别异或 $32$ 三个陷阱，与上表的错解设计吻合。

## 参考实现（C++17）

```cpp
#include <iostream>
#include <string>

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    std::string s;
    std::getline(std::cin, s);

    for (char &c : s) {
        if (c >= 'A' && c <= 'Z') {
            c = static_cast<char>(c - 'A' + 'a');
        } else if (c >= 'a' && c <= 'z') {
            c = static_cast<char>(c - 'a' + 'A');
        }
    }

    std::cout << s << '\n';
    return 0;
}
```
