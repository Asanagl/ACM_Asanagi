# 数字串求和题解

## 思路

设数字串为 $s=c_1c_2\cdots c_n$。数字字符 $c_i$ 对应的数值为 $d_i=c_i-\text{'0'}$，题目要求计算

$$
d_1+d_2+\cdots+d_n.
$$

读入字符串并令答案初始为 $0$，然后从左到右遍历每个字符 $c$，执行 `answer += c - '0'`。遍历结束后输出 `answer` 即可。

这里不能把整个数字串读进 `int` 或 `long long`：输入最长有 $100000$ 位，远超内置整数类型的表示范围。按字符串处理时，前导零和中间的零都只是普通数字字符。

主解使用范围 `for` 遍历字符串。独立参考解改为用下标 `for` 循环按位置访问字符，两者读入同一行字符串、累加同一不变量，但遍历方式不同，可以互相检查是否有下标或迭代器使用错误。

## 正确性证明

**引理 1：每个字符都会被转换成正确的数值。**

题面保证每个字符 $c$ 都在 `'0'` 到 `'9'` 之间，而这些字符的编码值连续。因此 `c - '0'` 的值恰好依次为 $0,1,\ldots,9$，与该数字字符对应的数值相同。

**引理 2：循环保持不变量“已处理字符的数值之和等于 answer”。**

初始时没有处理任何字符，`answer = 0`，不变量成立。

假设处理某个字符 $c$ 之前，不变量成立。由引理 1，`c - '0'` 就是 $c$ 对应的数值；执行 `answer += c - '0'` 后，`answer` 恰好增加当前字符的贡献，因此处理完 $c$ 后不变量仍成立。

字符串长度有限，循环会在处理完最后一个字符后终止。此时“已处理字符”就是整个 $s$，所以 `answer` 等于所有数字字符对应数值的总和。程序随后只输出这个值，故算法正确。

## 复杂度分析

设 $n=|s|$。

- 时间复杂度为 $O(n)$：读入并处理每个字符一次。
- 主解和参考解都把输入保存为字符串，需要 $O(n)$ 空间；除输入字符串外的额外空间为 $O(1)$。
- 若改用 `cin.get` 之类逐字符读取，可以连字符串都不保存，额外空间仍为 $O(1)$，但不是本题的必要条件。

答案及所有中间和都不超过 $9n\le 900000$，使用 `long long` 累加不会溢出。

## 边界情况

- $n=1$ 时，`0` 的答案为 $0$，`9` 的答案为 $9$。
- 全零串的答案为 $0$；前导零和连续零不会改变其他数字的贡献。
- 不能遇到字符 `'0'` 就停止。它与 C 字符串结束标志 `'\0'` 不是同一个字符。
- 长度达到 $100000$ 时仍须逐字符处理；全 `9` 串取得最大答案 $900000$。
- $19$ 位数字串有时仍能放入 `long long`，$20$ 位及以上则可能溢出；是否恰好溢出不是可以依赖的前提，统一按字符串处理才正确。
- 输入行末可能只有换行符，也可能没有换行符；按 token 读入（`cin >> s`）对这两种写法都成立，不会把行尾字符算进答案。

## 常见错误与定向数据

按思路、复杂度、实现三层检查如下。

### 思路层

- **把数字和算成数根**：数根会反复压缩到一位，而本题只累加一次。`wrong-digital-root` 在 `99999` 上输出 $9$，正确答案为 $45$。
- **把 `'0'` 当成结束标志**：`wrong-break-zero` 在 `90909` 上只累加到第一个零之前，输出 $9$，正确答案为 $27$。

### 复杂度层

本题没有自然的、值得保留的独立复杂度错解。任何正确算法都必须检查全部 $n$ 个字符，而直接遍历已经同时达到线性时间和常数辅助空间；不存在需要排序、动态规划、重复预处理或子问题枚举的步骤。人为加入无意义的重复扫描来制造超时不能代表本题的典型理解错误，因此不保留这种与教学目的无关的错解。近上限与上限数据仍用于检查完整遍历和运行余量。

### 实现层

- **忘记 `-'0'`**：`wrong-ascii` 累加的是字符编码，在输入 `1` 时得到 $49$ 而非 $1$。
- **循环下标从 $1$ 开始**：`wrong-skip-first` 漏掉首字符，在 `9000` 上输出 $0$ 而非 $9$。
- **把整串读入整数**：`wrong-parse-integer` 会在长数字串上溢出或读入失败；长度 $20$ 的定向数据和 $100$ 个 `9` 能稳定使其产生错误答案，而不是依赖崩溃击杀。

所有 `expected=fail` 错解都应由 checker 判定为错误答案；数据不依赖运行时异常来冒充击杀。
