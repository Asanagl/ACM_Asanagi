# 每行的和题解

## 思路

矩阵元素已经按行给出，不需要保存整个矩阵。外层循环依次处理第 $1$ 行到第 $n$ 行；每进入一行，就新建一个 `long long` 累加器并设为 $0$。内层循环依次读入当前行的 $m$ 个元素，每读入一个就加到累加器中。内层循环结束后，累加器就是当前行的和，立即输出并换行。

## 正确性证明

先证明内层循环会算出当前行的和。使用循环不变量：读完当前行的前 $k$ 个元素后，累加器等于这 $k$ 个元素之和。

- 初始时 $k=0$，累加器为 $0$，等于空前缀的和。
- 假设读完前 $k$ 个元素后不变量成立。读入第 $k+1$ 个元素并累加后，新的累加值等于前 $k$ 个元素之和加上第 $k+1$ 个元素，即前 $k+1$ 个元素之和，所以不变量仍然成立。

当 $k=m$ 时内层循环结束，因此输出的恰好是当前行全部 $m$ 个元素的和。

外层循环按行号递增的顺序执行，并且每行只输出一次，所以程序恰好输出 $n$ 个整数，第 $i$ 个整数就是第 $i$ 行的和。这正好满足题目要求，故算法正确。

最后检查整数范围。任意时刻累加的都是某一行不超过 $1000$ 个元素的部分和，其绝对值不超过 $1000\times10^9=10^{12}$，因此所有中间结果和最终结果都在 `long long` 范围内。

## 复杂度

- 时间复杂度：$O(nm)$。每个元素恰好读入并累加一次。
- 额外空间复杂度：$O(1)$。只保存当前元素、当前行和以及循环变量。

仅读入全部矩阵就需要 $\Omega(nm)$ 时间，因此该渐进时间复杂度已经达到最优。

## 边界情况

- $n=m=1$ 时，唯一元素就是唯一行和。
- $n=1$ 或 $m=1$ 时，仍按同样的双重循环处理，不需要特判。
- 元素可以全为零、全相同或正负相抵，行和也可以是零或负数。
- 每行可能有 $1000$ 个 $\pm10^9$，行和可达到 $\pm10^{12}$；部分和同样可能超出 32 位整数范围。

## 常见错误与错解设计

按三个层次枚举本题的相关错误：

1. **思路层：把行和与列和混淆。** `src/wrong/wrong-b.cpp` 改为逐列累加并输出 $m$ 个列和，混淆了求和对象和输出数量。公开样例及 `colswap-*` 的非对称、非方形数据可以区分两种结果。
2. **复杂度层：没有需要单独保留的自然渐进错解。** 本题只要求对每个输入元素做一次加法，正确算法必须读取全部 $nm$ 个元素，直接双重循环已经达到输入规模下界。保存整个矩阵只会增加空间，并不构成错误；人为重复扫描同一行或加入无意义等待也不是本题自然产生的算法误区，因此不设置伪造的复杂度错解。
3. **实现层：整数溢出或累加器状态错误。**
   - `src/wrong/wrong-a.cpp` 使用 `int` 累加，遇到 `sample-1`、`overflow-pos-*` 或 `overflow-neg-*` 时会产生错误的行和。
   - `src/wrong/wrong-c.cpp` 只在整个程序开始时清零一次，输出的是跨行前缀和。`sample-1` 和一般的多行 `random-small-*` 数据可以稳定区分。

此外还要注意内层循环应恰好执行 $m$ 次，不能使用无符号整数保存负数，每行只能输出一个和，且不能输出调试信息。即使最终答案另存为 `long long`，若累加过程已经在 `int` 中溢出，也无法得到正确结果。

## 数据设计

静态数据包含最小矩阵、单行、单列、方形、全零、全相同、极值与正负相抵、定向卡列和及整数溢出、多个随机矩阵，以及两个 $1000\times1000$ 的近上限矩阵。所有输入均由配置中的固定类型和种子生成，并由主解产生答案。
