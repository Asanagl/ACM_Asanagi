# 空格计数题解

## 思路

使用 `getline` 读入完整的一行。`getline` 会保留行首、行尾以及连续的空格，但不会把行末换行符放入字符串。

从字符串的第一个字符遍历到最后一个字符，每遇到一个 `' '`（ASCII 码为 $32$）就把计数器加 $1$，最后输出计数器。

## 正确性证明

设输入字符串为 $s_0s_1\cdots s_{n-1}$，定义 $I(s_i)$：当 $s_i$ 是空格时为 $1$，否则为 $0$。题目要求的答案为

$$
\sum_{i=0}^{n-1}I(s_i).
$$

**第一步，读入内容完整。** `getline` 读取到第一个换行符为止，并丢弃该换行符。行内空格均被保留，因此程序遍历的恰好是题目定义的字符串。

**第二步，循环不变量成立。** 处理完前 $i$ 个字符后，计数器等于 $\sum_{j=0}^{i-1}I(s_j)$。初始时计数器为 $0$，等于空前缀的答案。若下一个字符是空格，计数器加 $1$；否则不变，因此处理该字符后不变量仍成立。

**第三步，终止时得到答案。** 循环处理完全部 $n$ 个字符后，由不变量可知计数器等于 $\sum_{i=0}^{n-1}I(s_i)$，即输入行中的空格总数。程序只输出这个整数，所以输出也符合要求。

空串对应 $n=0$，循环不执行，计数器保持为 $0$，证明同样成立。

## 复杂度

设 $n=|s|$。

- 时间复杂度：读入和遍历各需要 $O(n)$，总计 $O(n)$。
- 空间复杂度：保存整行需要 $O(n)$；除输入字符串外的辅助空间为 $O(1)$。

答案不超过 $100\,000$，使用 `int` 即可。

## 边界与常见错误

### 思路层

- 把连续空格看成一个“空格段”，每段只计一次，会少计答案。`wrong-runs.cpp` 实现了这个错误，连续空格数据可稳定将其击杀。
- 统计单词数或由单词数推导空格数也不等价：行首、行尾和连续空格都会使这种推导失效。
- 只需统计 ASCII 码为 $32$ 的字符，不能自行替换题目对象。

### 复杂度层

每个字符都可能影响答案，因此至少必须检查整行一次，线性复杂度已经足够。`wrong-quadratic.cpp` 为每个位置重建整个前缀再用 `std::count` 统计，答案正确但需要 $O(n^2)$ 的拷贝与比较；在 $|s|=100\,000$ 的数据上实测约 $4$ 秒（同数据主解约 $0.01$ 秒），远超 $1000$ ms 时限，可稳定触发预期超时。

注意：如果把前缀重扫写成“只保留最后一次结果”的形式（例如每次覆盖一个标量），编译器可能在 `-O2` 下把它强度削减成线性扫描，从而不会超时。本题的错解刻意保留了前缀串的构造，使二次复杂度无法被优化掉。

本题最大字符串仅约 $0.1$ MB，正常实现不会接近 $256$ MiB 内存限制，不需要设置专门的空间错解。

### 实现层

- `cin >> s` 会跳过空白并只读一个非空白片段，不能保留空格，也无法正确区分空行和全空格行。`wrong-cin.cpp` 由含空格数据击杀。
- 循环写成 `i + 1 < s.size()` 会漏掉最后一个字符。`wrong-last.cpp` 由末字符为空格的数据击杀。
- 误用单词读取、先去除首尾空白、只处理非空行，都会破坏输入内容。
- 本题只有一行输入，不应使用多组测试循环输出多个答案。
- 输入字符全部属于 ASCII，不存在 `char` 符号性影响空格比较的问题；答案上界也很小，不存在整数溢出错法。
- 没有多组测试，因此不存在跨测试组清空计数器的问题。

输出时只写答案整数，不要附加说明文字。
