# 矩阵加法题解

## 思路

矩阵加法是逐位置运算：结果只取决于同一位置上 $A$ 与 $B$ 的两个元素，与其他位置完全无关。因此读完输入后，对每个 $1\le i\le n$、$1\le j\le m$ 计算

$$
c_{ij}=a_{ij}+b_{ij},
$$

再按行优先（先行后列）顺序输出即可。不需要排序、搜索或任何额外结构。

主解用两个二维 `vector` 分别保存 $A$ 和 $B$，然后双重循环输出和。独立参考解来自只阅读公开题面的盲审：它用 `scanf`/`printf` 和一维数组，把 $A$ 压平存下后，在读取 $B$ 的第 $k$ 个元素时就地累加得到 $c_k$，最后按 $k=i\cdot m+j$ 的映射输出。两者依据同一定义，但存储方式（二维 vs 压平）和读写接口（`cin`/`cout` vs `scanf`/`printf`）都不同。

## 正确性证明

**引理 1（读入对齐）**：输入先给出完整的 $A$，再给出完整的 $B$，两者都是 $n$ 行、每行 $m$ 个、按行优先排列。因此在行优先序列中第 $k$ 个（从 $0$ 计数）整数分别对应同一个位置 $(i,j)=(k/m+1,\,k\bmod m+1)$。主解用两重循环按同样顺序读入，所以读完后 `a[i][j]` 与 `b[i][j]` 恰为 $a_{ij}$ 与 $b_{ij}$。

**引理 2（每个位置恰好处理一次）**：外层枚举 $i=1..n$、内层枚举 $j=1..m$，一共执行 $n\cdot m$ 次，每个有序位置 $(i,j)$ 恰好出现一次，没有遗漏也没有重复。

**引理 3（数值正确）**：第 $(i,j)$ 次输出的是 $a_{ij}+b_{ij}$。由题面定义，这就是唯一的 $c_{ij}$。

**引理 4（范围安全）**：$a_{ij},b_{ij}\in[-10^6,10^6]$，故 $c_{ij}\in[-2\times10^6,2\times10^6]$，落在 32 位有符号 `int` 内，加法不溢出。

**引理 5（格式正确）**：每行输出恰好 $m$ 个整数，相邻整数之间只输出一个空格（`j>0` 时才输出空格，因此行首行尾都没有多余空格），每行结束后换行。

**定理**：对任意合法输入，主解输出的就是唯一的 $C$，且个数、顺序、格式均符合要求。由引理 1–5 直接得证。参考解只是把引理 1 的"二维下标"改成"压平下标 $k=i\cdot m+j$"，其余论证逐字相同。

## 复杂度

令 $N=nm$，最大 $N=300\times300=90000$。

- 时间复杂度：$O(nm)$。需要读入 $2N$ 个整数、做 $N$ 次加法、输出 $N$ 个整数，已达输入输出下界。
- 额外空间复杂度：$O(nm)$。主解保存两个矩阵约 $2\times90000\times4=720000$ 字节；参考解只保存 $A$，约 $360000$ 字节。

两者都远低于 256 MiB，运行时间在 1 秒时限内有两个数量级以上的余量（实测最大用例主解约 0.1 秒）。

## 边界情况

- $n=m=1$：单元素，行内无分隔符，行尾不多空格。
- $n=1,m=300$ 与 $n=300,m=1$：单行、单列，检验换行位置与循环边界。
- $2\times 300$ 与 $300\times 2$：细长矩阵，行数远小于列数或反之。
- $2\times3$、$3\times2$、$3\times3$：小规模矩形与方阵，其中 $2\times3$ 与 $3\times2$ 互为转置形状，用于发现 $n,m$ 混用。
- 全零、全 $10^6$、全 $-10^6$：覆盖答案 $0$、$+2\times10^6$、$-2\times10^6$。
- $b_{ij}=-a_{ij}$：答案全为 $0$，覆盖正负相消。
- 取值池 $\{-10^6,-10^3,0,10^3,10^6\}$：大量重复元素，检验不会去重或跳位。
- $299\times300$、$300\times297$、$299\times299$：近上限的非方形与方形规模。
- $300\times300$ 随机、极值与正负混合：上限规模，检验性能与输出量。

## 常见错误

按"思路 / 复杂度 / 实现"三层枚举：

**思路层**

- 用减法、乘法或某种"合并"代替逐位置相加（`wrong-subtract`）：映射到错误的位置或错误的运算，样例即错。
- 误以为 $A$、$B$ 按行交替给出，写成"读一行 $A$、读一行 $B$"（`wrong-interleaved`）：从第 2 行起整体错位。

**复杂度层**

- 对每个输出位置重新扫描整个矩阵去找 $a_{ij}$、$b_{ij}$（`wrong-quadratic`）：答案数值正确，但时间是 $O((nm)^2)$，在 $300\times300$ 上限数据上稳定超时。本题是纯逐位置运算，除了这种"反复重扫输入"的写法之外没有别的渐进错误空间，因此复杂度层只保留这一份错解。

**实现层**

- 内层循环写成 `j + 1 < m`，漏掉每行最后一列（`wrong-missing-last`）：输出 token 数不足，checker 报缺失元素。
- 读 $B$ 时把列下标镜像成 `m-1-j`（`wrong-reverse-b`）：在 $m\ge2$ 且行内不对称时给出错误数值，而不是异常退出。
- 把 $n$ 与 $m$ 混用（例如外层用 $m$、内层用 $n$）：在非方形数据上越界或错位；本题所有非方形用例都能暴露它。
- 用 `short` 或更小的类型保存结果：答案可达 $\pm2\times10^6$，会溢出；用 `int` 或更大类型才安全。
- 输出 $n,m$、提示文字或调试信息：答案唯一，多余 token 直接判错。
- 用 `long long` 则是可以正确通过的选择，不算错解。

## 盲审与对拍

主解之前，我先用只含公开题面、样例、约束与判题语义的提示词，请一个独立的只读审查者（模型 `wb2api/deepseek-v4.1-flash`，不提供工作区路径、算法、生成器或任何代码）独立复述任务、给出算法、逐步正确性证明、复杂度、边界、风险与完整 C++17 实现。其结论为：压平一维、边读 $B$ 边累加，$O(nm)$ 时间与 $O(nm)$ 空间，1 s / 256 MiB 下安全；主要风险是输入分块顺序、$n\ne m$、逐 token 比较和整数范围。该结论与本文一致，无分歧，因此以其实现作为 `src/solution2.cpp` 的基础（保留原样，未改动逻辑）。

随后用固定主种子 `12345`，以 `small-random` 类型连续生成小数据，对主解与参考解做逐字节输出比较、并同时经 checker 判定，完成 100 轮差分对拍，全部一致，无有效反例。记录见 `.tmp/12/stress-report.json`。

## 错解击杀与数据设计

- 样例：$2\times3$，含 $0$、正数与负数，可击杀减法错解与交错读取错解，并作为公开样例经 validator 校验。
- 思路层：`wrong-subtract`、`wrong-interleaved` 由样例与多组非方形数据稳定判为答案错误。
- 复杂度层：`wrong-quadratic` 只在 `max-random-1`（$300\times300$）上验证稳定超时，实测约 8 秒，远超 3 秒的判定阈值，因此不是靠意外错误冒充。
- 实现层：`wrong-missing-last`（缺 token）与 `wrong-reverse-b`（错数值）都由 checker 判为答案错误，不依赖运行时崩溃。

所有输入都由 `config.json` 里显式写出的 `type` 与 `seed` 复现；所有标准答案都由验题器运行主解生成，没有手工伪造。
