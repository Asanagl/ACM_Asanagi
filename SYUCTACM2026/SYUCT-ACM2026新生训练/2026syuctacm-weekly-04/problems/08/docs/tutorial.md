# 子串在哪里题解

## 思路

题目要求：在 $s$ 中找 $t$ 第一次出现的起始下标，找不到输出 $-1$。下标从 $0$ 开始，匹配允许重叠。

本题的力量全部集中在"别把问题读错"上。算法本身没有难度：把 $t$ 依次对齐到 $s$ 的每个可能起点，逐个字符比较就行。真正容易翻车的是四个细节：

1. **起点的取值范围是 $0 \le i \le |s|-|t|$，不是 $0 \le i < |s|-|t|$。**
   当 $t$ 正好贴在 $s$ 末尾时，起点恰好是 $|s|-|t|$。写成 `i < n - m` 会漏掉这一类，而这类数据在随机数据里很罕见，本地跑样例往往发现不了。

2. **要的是第一次，不是最后一次，也不是次数。**
   `rfind` 给的是最后一次；数一遍出现次数给的是个数。这两个都能过掉一部分数据，但都答非所问。

3. **匹配允许重叠，所以不能"找到一个就往后跳 $|t|$ 个字符"。**
   $s=\texttt{aaaa}$、$t=\texttt{aa}$ 时起点 $0,1,2$ 都是合法出现，都要考虑，其中最小的是 $0$。

4. **下标从 $0$ 开始。**
   输出 `find` 的结果再加一，就是经典的差一错误。

把"枚举所有起点 + 逐字符比较 + 取第一个成功"写出来，就是

```cpp
for (int i = 0; i + m <= n; ++i) {
    if (s.compare(i, m, t) == 0) { cout << i << '\n'; return 0; }
}
cout << -1 << '\n';
```

而 C++ 的 `std::string::find` 干的正是这件事，所以主解一行就够：`s.find(t)` 返回最小的匹配起点，找不到返回 `string::npos`。

## 算法

主解（`src/solution.cpp`）：

1. 用 `cin >> s >> t` 读入两个字符串。这里用 `>>` 而不是 `getline`，是因为 `>>` 会自动跳过所有空白字符，不依赖运行时对 CRLF 的处理（详见文末"读入层的坑"）。
2. 令 `pos = s.find(t)`。
3. `pos == string::npos` 时输出 `-1`，否则输出 `pos`。

独立参考解（`src/solution2.cpp`）**不使用任何库函数**，手写 KMP：先对 $t$ 求前缀函数 $\pi$，再用 $\pi$ 在 $s$ 上线性扫描，$j$ 累计"当前已匹配的 $t$ 前缀长度"，一旦 $j=m$ 就输出 $i-m+1$ 并立刻返回。两条实现路径（库函数 vs 手写自动机）互不依赖，可以互相交叉验证。

## 正确性证明

只证明下面这段"枚举所有起点"的循环即可。主解用的 `s.find(t)` 与它在**语义**上完全等价：C++ 标准明确规定 `basic_string::find` 返回"最小的、使得从该位置起长度为 `m` 的片段等于 `t` 的下标"，找不到返回 `npos`。也就是说标准保证的是"最小起点"这一结果，**不保证**实现复杂度；本题 $n\le 10^4$，复杂度不构成风险（见下一节）。

设 $n=|s|$、$m=|t|$。对每个 $i\in[0,n-m]$，记 $P(i)$ 为命题"$s[i..i+m-1]=t$"。

**引理 1（枚举范围完整）**：$t$ 在 $s$ 中出现的每个起始下标都落在 $[0,n-m]$ 内。
若 $t$ 从 $i$ 开始出现，则它占用下标 $i,i+1,\dots,i+m-1$，必须全部落在 $[0,n-1]$ 内，故 $i\ge 0$ 且 $i+m-1\le n-1$，即 $i\le n-m$。$\square$

**引理 2（判定可靠）**：对任意 $i\in[0,n-m]$，`s.compare(i, m, t) == 0` 当且仅当 $P(i)$ 成立。
`s.compare(i, m, t)` 取出 $s$ 从下标 $i$ 起的 $m$ 个字符与 $t$ 逐字符比较，相等即返回 $0$；由引理 1 的同一个不等式，这 $m$ 个字符不会越界。故返回 $0$ 与"$s[i..i+m-1]=t$"等价。$\square$

**引理 3（取到的是最小值）**：循环按 $i=0,1,2,\dots$ 递增顺序检查，且第一次成功就 `return`，因此输出的 $i$ 是所有满足 $P(i)$ 的下标中最小的一个。
若更小的 $i'<i$ 也满足 $P(i')$，那么循环在 $i'$ 那一轮就会成功并返回，与"在 $i$ 处才返回"矛盾。$\square$

**引理 4（无解时输出正确）**：若不存在任何 $i$ 使 $P(i)$ 成立，循环跑完不返回，输出 `-1`。
由引理 1，所有可能的出现位置都已被枚举，既然一个都没成功，就确实不存在出现位置，`-1` 正确。$\square$

**定理**：主解对每个合法输入都输出唯一正确答案。
由引理 3（有解时输出最小起点）与引理 4（无解时输出 `-1`），且题目保证答案唯一，故输出与正确答案一致。$\square$

`solution2.cpp` 的 KMP 正确性不在此展开，它的作用是用一条完全不同的实现路径做交叉验证：随机对拍中两者答案必须处处相同。

## 复杂度

**主解**：设 `find` 内部采用最朴素的逐起点比较，最坏情况比较次数为 $(n-m+1)\cdot m$，即 $O(nm)$；最好情况 $O(n)$。`std::string::find` 的实际复杂度标准并未硬性规定，但 $n\le 10^4$ 时任何实现都在毫秒级。额外空间 $O(1)$（不计输入本身）。

**参考解（KMP）**：时间 $O(n+m)$，额外空间 $O(m)$（$\pi$ 数组）。求 $\pi$ 时 $k$ 每轮至多加一、回退时严格减小，回退总次数不超过增长总次数，故为线性；扫描同理。

实测（本机，含进程启动开销）：46 个 secret 数据点上主解最慢一档约 **16–21 ms**（多次测量有波动），远低于 1000 ms；内存占用为两个长度不超过 $10^4$ 的字符串，远低于 256 MiB。上界 $n=m=10^4$ 时，KMP 的 $\pi$ 数组仅 40 KB。

**关于"多项式是否会被卡"**：本题 $n\le 10^4$，最坏 $O(nm)\approx 2.5\times 10^7$ 次比较，实测朴素写法在构造出的最坏数据（`s` 全 `a`、`t` 是 4999 个 `a` 加一个 `b`）上也只需约 50 ms。因此 **本题不存在"复杂度层"错解，也不指望用 TLE 卡掉任何人**，$O(nm)$ 与 $O(n+m)$ 都能通过。数据的作用是保证两种写法都被充分测试，而不是逼人写 KMP。这一点如实说明，不凑错解。

## 边界情况

- **$|s|=|t|=1$**（最小规模）：只有起点 $0$ 一个候选。相等输出 `0`，不等输出 `-1`。数据点 `min-found`、`min-absent`，以及样例外的 `s=a,t=a`、`s=a,t=b` 都验证过。
- **$|s|=|t|$ 且完全相等**：答案是 `0`，如 `equal-found`（也是 `min-found` 的推广）。
- **$|s|=|t|$ 但只差一个字符**：答案是 `-1`，如 `equal-absent`（末尾字符被改）。这是最容易被"找到第一个字符就交差"的写法骗过去的形状：首字符确实存在，但整体不匹配。
- **$t$ 是 $s$ 的前缀**：答案 `0`，如 `prefix-found`、`sample-3`。
- **$t$ 只出现在末尾**：答案恰为 $|s|-|t|$，是上界的临界值，如 `tail-found-*`、`tail-at-upper`。这是"起点上界写成 `i < n - m`"最典型的杀手；同样能抓住该错误的还有 $|s|=|t|$ 的 `min-found`、`equal-found`（此时 $n-m=0$，循环一次都不执行）。
- **$t$ 只出现在下标 1 或 2**：如 `found-at-pos1`、`found-at-pos2`，防止漏掉起点 0 之外的位置、同时检验不会误报 0。
- **重叠出现**：$s=\texttt{a}^{n}$、$t=\texttt{a}^{m}$ 时出现位置是 $0,1,\dots,n-m$ 共 $n-m+1$ 个，答案必须取最小的 $0$，如 `overlap-all-a-*`、`many-occ-*`、`sample-3`。这是"数出现次数"与"取最后一次"错解的墓地。
- **完全无解**：包括 `s` 全为 `a` 而 `t` 以 `b` 结尾的 `absent-basic-*`、周期串上的 `periodic-absent`、以及 $|s|=10^4$ 全 `a` 配"4999 个 `a` 后接 `b`"的 `all-a-max-absent`。最后一类正是朴素算法的最坏形状，但本题限制下仍能轻松通过。
- **近上限规模**：$|s|$ 接近 $10^4$，如 `near-max-found-*`、`near-max-absent-*`、`max-single-*`。`max-single-found`（$|s|=10^4$、$|t|=1$、实测答案为 `1` 或 `5`）还额外覆盖了"$|t|=1$ 时退化为字符查找"这一情形——注意它**故意不取 0**，这样"漏掉起点 0 之后的位置"和"误报 0"两类错误都会被抓到。
- **字符集**：既有二进制字母表（`binary-random-*`、`overlap-all-a-*`），也有更大的字母表（`absent-long`、`max-single-absent`、`near-max-absent-*`，用 `a`–`y` 再插入 `z` 构造）。小字母表能制造大量重叠与回退，大字母表能让"只比首字符"的写法看起来像对，两者都要有。

## 常见错误

### 思路层

| 错误 | 后果 | 对应错解 | 击杀数据（首个 secret 点，实测） |
|---|---|---|---|
| 取**最后一次**出现，用 `rfind` | 多处出现时答案偏大 | `wrong-last-occ` | `overlap-all-a-1`：$|s|=2056$、$|t|=10$，期望 `0`，输出 `2046` |
| 输出**出现次数**而不是位置 | 无解时输出 `0`，有解时输出个数 | `wrong-count-occ` | `min-found`：期望 `0`，输出 `1` |
| 只要 $t$ 的首字符出现就算匹配 | 忽略后续字符，乱报位置 | `wrong-first-char` | `equal-absent`：期望 `-1`，输出 `0` |

### 实现层

| 错误 | 后果 | 对应错解 | 击杀数据（首个 secret 点，实测） |
|---|---|---|---|
| 起点上界写成 `i < n - m`，漏掉右端点 | 只出现在末尾时误判无解 | `wrong-tail-bound` | `min-found`：期望 `0`，输出 `-1` |
| 输出 `find` 结果 **加一**（1 起始） | 有解时位置整体偏大 1 | `wrong-one-based` | `min-found`：期望 `0`，输出 `1` |
| `find(t, 1)`，从下标 1 开始找 | 前缀匹配全部漏掉 | `wrong-skip-zero` | `min-found`：期望 `0`，输出 `-1` |
| 内层比较写成 `j + 1 < m` | 漏比最后一个字符 | `wrong-inner-short` | `min-absent`：期望 `-1`，输出 `0` |

### 复杂度层

**不适用，特此说明。** 如上文所算，$n\le 10^4$ 时朴素 $O(nm)$ 的最坏情况实测约 50 ms，仍远低于 1000 ms。本题没有任何一个错解是靠超时被击杀的，全部是 **checker 判 WA**，且首个失败点都不依赖运行时崩溃。硬凑一个"渐进错误但被测出 TLE"的错解只会得到一份在 1 s 限制下也能通过的假错解，所以不写。

### 补充：读入层的坑（未单列错解）

用 `getline(cin, s)` 读入时，如果输入文件里某行以 CRLF 结尾，`s`/`t` 末尾会残留 `\r`，`t` 永远匹配不上，表现为"有解全判无解"。主解用 `cin >> s >> t` 天然规避（`>>` 会跳过所有空白，包括 `\r`）。

严格说这个坑能否发作取决于平台：在 Linux 上 `getline` 只按 `\n` 切分，CRLF 文件的 `\r` 会留在行尾；在 Windows 上以文本模式读 `stdin` 时，运行时会做 CRLF→LF 转换，`\r` 被吃掉，坑不发作。本题本地生成的 `.in` 文件确实是 CRLF（`61 62 63 0d 0a`），所以在 Windows 上测不出这个问题、换到 Linux 判题就可能出事。这也是主解一律用 `>>` 而不是 `getline` 的原因：不依赖运行时的换行转换行为。若坚持 `getline`，需要手工 `while (!s.empty() && isspace((unsigned char)s.back())) s.pop_back();`。这个错误不需要单独出一个错解文件，`sample-1` 在 Linux 上就会立刻暴露。

## 参考实现（C++17）

主解（`src/solution.cpp`，库函数路径）：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s, t;
    cin >> s >> t;          // >> 跳过所有空白，不依赖 CRLF 转换

    const size_t pos = s.find(t);
    if (pos == string::npos) {
        cout << -1 << '\n';
    } else {
        cout << static_cast<long long>(pos) << '\n';
    }
    return 0;
}
```

参考解（`src/solution2.cpp`，手写 KMP，路径独立）：

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    std::string s, t;
    if (!(std::cin >> s >> t)) {
        return 0;
    }

    const int n = static_cast<int>(s.size());
    const int m = static_cast<int>(t.size());

    std::vector<int> pi(m, 0);          // pi[i] = t[0..i] 的最长真前缀 == 后缀 长度
    for (int i = 1; i < m; ++i) {
        int k = pi[i - 1];
        while (k > 0 && t[i] != t[k]) {
            k = pi[k - 1];
        }
        if (t[i] == t[k]) {
            ++k;
        }
        pi[i] = k;
    }

    int matched = 0;                    // 当前已匹配的 t 的前缀长度
    for (int i = 0; i < n; ++i) {
        while (matched > 0 && s[i] != t[matched]) {
            matched = pi[matched - 1];
        }
        if (s[i] == t[matched]) {
            ++matched;
        }
        if (matched == m) {             // t 是 s[0..i] 的后缀 => 起点 i-m+1
            std::cout << (i - m + 1) << '\n';
            return 0;                   // 首次命中即最小起点
        }
    }

    std::cout << -1 << '\n';
    return 0;
}
```
