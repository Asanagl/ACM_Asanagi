# 反转字符串题解

## 思路

设输入字符串为 $s=s_1s_2\cdots s_n$（$n=|s|$）。题目要求输出 $t=t_1t_2\cdots t_n$，其中

$$
t_i=s_{n+1-i}\qquad(1\le i\le n).
$$

也就是把每一对对称位置（$i$ 与 $n+1-i$）上的字符互换，中间那个位置（$n$ 为奇数时）保持不动。除此之外不删字符、不去重、不做数字与字母之间的任何转换，所以输出长度恒等于 $n$。

本题给出两条互不相同的实现路线，主解与独立参考解各用一条：

- **主解**：双指针原地交换。左下标 $l=0$、右下标 $r=n-1$，当 $l<r$ 时交换 `s[l]` 与 `s[r]`，然后 `++l`、`--r`。全程只额外用了两个计数器。
- **独立参考解**：调用 `<algorithm>` 的 `std::reverse(s.begin(), s.end())`，全部正确性交给标准库，不写任何交换循环。

两条路线做的是同一个对称置换，因此输出必须逐字符一致。

## 正确性证明

**记号。** 记初始字符串为 $s^{(0)}$，处理到一半时的串为 $s$，最终输出的串按题目记号记作 $t$。目标命题是：对每个 $1\le i\le n$ 都有 $t_i=s^{(0)}_{n+1-i}$。

**主解（双指针）的循环不变式。** 设循环已经执行了 $k$ 次，此时 $l=k$、$r=n-1-k$。我们断言：

> (I) 对每个 $0\le j<k$，都有 $s[j]=s^{(0)}[n-1-j]$ 且 $s[n-1-j]=s^{(0)}[j]$；
> (II) 对每个 $k\le j\le n-1-k$，都有 $s[j]=s^{(0)}[j]$。

**初始化：** $k=0$ 时 (I) 中 $j$ 的取值范围为空，条件真空成立；(II) 说的是整串仍等于原串，也就是程序刚读完输入的状态，成立。

**保持：** 设不变式在 $k$ 成立，且循环继续执行意味着 $k<n-1-k$，即左右两个下标不同。由 (II)，当前位置满足 $s[k]=s^{(0)}[k]$ 与 $s[n-1-k]=s^{(0)}[n-1-k]$。交换后

$$
s[k]=s^{(0)}[n-1-k],\qquad s[n-1-k]=s^{(0)}[k],
$$

这正好是 (I) 在 $j=k$ 处要求的两条等式；$j<k$ 的部分 (I) 原本成立且本次未触碰。交换只改动 $k$ 与 $n-1-k$ 两个位置，其余位置不动，所以 (II) 在新区间 $k+1\le j\le n-2-k$ 上仍成立。于是不变式对 $k+1$ 成立。

**终止：** 循环在 $l\ge r$ 时结束。由于每轮 $l$ 加 $1$、$r$ 减 $1$，且 $l+r=n-1$ 始终成立，结束时恰有 $k=\lfloor n/2\rfloor$。

- 若 $n=2m$ 为偶数，则 $k=m$，(II) 的区间 $m\le j\le 2m-1-m=m-1$ 为空，(I) 覆盖 $j=0,\ldots,m-1$，配合其对称项正好覆盖全部 $2m$ 个位置。故对每个 $0\le i\le n-1$ 都有 $s[i]=s^{(0)}[n-1-i]$。
- 若 $n=2m+1$ 为奇数，则 $k=m$，(I) 覆盖 $j=0,\ldots,m-1$ 及其对称位置 $n-1-j$，(II) 只剩中间位置 $j=m$：$s[m]=s^{(0)}[m]$。而该位置的目标值是 $s^{(0)}[n-1-m]=s^{(0)}[m]$，与现状相同，故它也已经"正确"。

两种情形下，输出时整串的每个位置都满足目标等式，即 $t_i=s^{(0)}_{n+1-i}$。

**独立参考解。** `std::reverse(first, last)` 的标准语义是把区间 $[first,last)$ 就地反序，具体做法是对每一对满足 `first` 位置在前的 $(i,\,n-1-i)$ 交换一次，循环到两指针相遇为止——与主解执行的恰好是同一组 $\lfloor n/2\rfloor$ 次交换，只是迭代形式不同（一个用 `while` 加手动指针，一个交给标准库）。既然同一置换作用于同一初始串，结果必然相同。注意"对全部 $n$ 个下标各交换一次"是错的写法：那样每个对称对会被交换两次，净效果是恒等，字符串根本不会变。

**输入输出层面。** `std::cin >> s` 会跳过前导空白并读到一个完整 token，遇到空白停止。由于题面保证输入是单行、无空格、只含 `a`–`z` 与 `0`–`9`，读到的 $s$ 就是题面中的字符串本身，不含行末换行符或回车符。程序随后只输出该串与一个换行，不含长度、提示或其他文本，因此 checker 读到的那个 token 就是 $t$。答案唯一，故输出与标准答案逐字符相同。

## 复杂度

- 时间复杂度：$O(n)$。读入 $n$ 个字符、做 $\lfloor n/2\rfloor$ 次交换、输出 $n$ 个字符，每次操作都是常数时间。
- 空间复杂度：$O(n)$ 用于存放字符串本身（这是输入也是输出缓冲）；除它之外只用常数个下标与临时变量，**额外辅助空间 $O(1)$**。

$n\le 10^6$，字符数据约 $1$ MB，交换至多 $5\times 10^5$ 次，读入加输出约 $2$ MB 字节流。在 1000 ms / 256 MiB 下余量极大。任何正确算法都必须读入并输出全部 $n$ 个字符，因此 $\Omega(n)$ 是本题的时间下界，线性算法已是最优。

## 边界情况

- $|s|=1$：$l=0,r=0$，循环一次都不执行，原样输出。用 `while (l < r)` 或 `for (i = 0; i < n/2; ++i)` 都不会越界。
- $|s|=2$：只交换一对字符，`ab` → `ba`。
- 奇数长度的正中间字符：`abc` → `cba`，中间 `b` 留在原位。若循环条件误写成 `i <= n/2`，偶数长度会多做一次"换回去"的交换（见错解 `wrong-even-mid`）。
- 全同字符（如 $10^6$ 个 `a`）：输出与输入完全相同，不能因此认为"没反转"而加特判——全同串的逆序就是它自己。
- 回文串：本来就是自己的逆序，用于检验程序是否真的执行了置换而不是恒等输出。
- 纯数字且含前导零：`1000` → `0001`，`000000` → `000000`。把字符串当整数读（`stoi`/`atoi`）会丢前导零或直接溢出。
- 长度达到上限 $10^6$ 与近上限 $999999$：用于检验内存与时间，以及是否用了 $O(n^2)$ 的前插写法。
- 输出格式：只允许一个 token 加行末空白，不能打印长度、调试信息或第二行。

## 错解对照

按"思路 / 复杂度 / 实现（下标）"三层枚举本题特有的错误：

| 层次 | 错解 | 错误表现 | 击杀数据 |
|---|---|---|---|
| 思路 | `wrong-sort` | 把"逆序"误解成"降序排序"，丢掉原串的位置信息 | `sample`、`sample-2`、`pal-odd`、`random-*` 等绝大多数数据 |
| 思路 | `wrong-middle-drop` | 反向扫描时把奇数长度的中间字符当作"重复"跳过，输出少一个字符 | `pal-odd`、`nonpal-odd`、`len3`、`random-binary` |
| 思路 | `wrong-a` | 只交换首尾一次，误以为这就是"反转" | `sample`、`sample-2`、`four-distinct`、`digits-long`、`mixed-runs` 等；`n<=3`、全同串、回文串以及"去掉首尾后本身是回文"的串（如 `1000`）会被它蒙对，属正常现象 |
| 复杂度 | `wrong-b` | 用 `reversed.insert(reversed.begin(), c)` 逐字符前插，单次 $O(n)$、总计 $O(n^2)$ | `max-*`、`near-max`、`random-large`（$n=10^6$ 时约 $25$ 秒，TLE） |
| 实现/下标 | `wrong-c` | 从 $n-2$ 开始反向输出，漏掉原串最后一个字符（答案第一个字符） | 全部数据，`min-digit` 就已被击杀 |
| 实现/下标 | `wrong-even-mid` | 循环条件写成 `i <= n/2`，偶数长度时多做一次对称交换，把中间两个字符换回原位 | 所有偶数长度数据，如 `len2-distinct`、`sample` |

六个错解都能正常读入、正常结束进程，不依赖崩溃或运行时异常来"击杀"：

- `wrong-sort`、`wrong-middle-drop`、`wrong-a`、`wrong-c`、`wrong-even-mid` 在小数据上就被 checker 判为答案错误（WA）。
- `wrong-b` 是复杂度层错解，答案逻辑本身正确，在 $n=10^6$ 的数据上超时（TLE），在小数据上则通过——这正是复杂度层错解应有的表现。

`wrong-even-mid` 与 `kill-even-mid`、`wrong-middle-drop` 与 `pal-odd` / `nonpal-odd` 分别构成一一对应的最小反例。

## 独立盲审

公开题面与约束冻结后，另起一个只读会话做盲审：仅向审阅者提供公开题面、约束、样例与 checker 语义，不提供工作区路径、算法、生成器或任何代码，也不允许其调用工具。审阅者（模型 `wb2api/deepseek-v4.1-flash`）独立复述了任务与全部约束，给出的算法是"读入 token + 对称交换（或 `std::reverse`）"，并用三条引理（长度与字符多重集不变、位置映射正确、输出格式合法）完成了闭合证明，复杂度结论为时间 $O(n)$、辅助空间 $O(1)$。其结论与主解一致。

审阅者还独立指出三类风险，与上表的错解设计吻合：

1. 把字符串当整数处理，导致 `1000` → `0001` 这类前导零丢失（对应 `wrong-sort` 一类"思路层"错误的近邻）；
2. 用 `s = ch + s` 或 `insert(begin())` 逐字符前插造成 $O(n^2)$（对应 `wrong-b`）；
3. 下标层错误：`i <= n/2` 在偶数长度下多做一次交换、反向循环漏掉下标 $0$、奇数长度误跳过中点（分别对应 `wrong-even-mid`、`wrong-c`、`wrong-middle-drop`）。

盲审给出的 C++17 实现使用 `std::reverse`，成为 `src/solution2.cpp` 的基础；`src/solution.cpp` 则保留独立的双指针原地写法，两条路线互不依赖。

## 参考实现（C++17）

主解（双指针原地交换，`src/solution.cpp`）：

```cpp
#include <iostream>
#include <string>
#include <utility>

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    std::string s;
    std::cin >> s;

    int left = 0;
    int right = static_cast<int>(s.size()) - 1;
    while (left < right) {
        std::swap(s[left], s[right]);
        ++left;
        --right;
    }

    std::cout << s << '\n';
    return 0;
}
```

独立参考解（`std::reverse`，`src/solution2.cpp`）：

```cpp
#include <algorithm>
#include <iostream>
#include <string>

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    std::string s;
    std::cin >> s;

    std::reverse(s.begin(), s.end());

    std::cout << s << '\n';
    return 0;
}
```
