# 截取一段题解

## 思路

题目要求输出字符串 $s$ 中"第 $l$ 个字符到第 $r$ 个字符"这一段。它只有两个要点：

1. **两种编号的换算。** 题面用 $1$ 起始的编号（第 $1$ 个字符是第一个字符），而 C++ 的 `std::string` 用 $0$ 起始的下标。所以"第 $l$ 个字符"在 C++ 里是 `s[l - 1]`，起点下标要减一。
2. **闭区间的长度。** 区间 $[l,r]$ 同时包含两端，元素个数是 $r-l+1$。很容易误写成 $r-l$（半开区间）或直接写 $r$（把右端点当成起点偏移）。

把这两点合起来，最直接的写法就是

```cpp
s.substr(l - 1, r - l + 1)
```

注意 `substr(pos, count)` 的两个参数分别是**起点下标**和**字符个数**，不是起点和终点。这是本题最容易踩的坑。

## 算法

1. 读入字符串 $s$，读入整数 $l,r$。
2. 计算 C++ 起点下标 `pos = l - 1`。
3. 计算区间字符数 `len = r - l + 1`。
4. 输出 `s.substr(pos, len)`，行末换行。

主解直接用 `substr`；独立参考解 `src/solution2.cpp` 不使用 `substr`，而是用 `for` 循环从 `s[l-1]` 逐个 `push_back` 到结果串，两条实现路径互不依赖，可以交叉验证。

## 正确性证明

设输入字符串长度为 $n$，$1\le l\le r\le n$，算法输出串为 $t$。

**引理 1（起点合法）**：`pos = l - 1` 是合法下标，即 $0\le pos\le n-1$。
由 $l\ge 1$ 得 $pos=l-1\ge 0$；由 $l\le r\le n$ 得 $pos=l-1\le n-1$。$\square$

**引理 2（长度合法）**：`len = r - l + 1` 满足 $1\le len\le n-pos$。
由 $r\ge l$ 得 $len\ge 1$；又 $len=r-l+1$ 且 $pos=l-1$，故 $pos+len=r\le n$，即 $len\le n-pos$。$\square$

**引理 3（取到的字符正好是 $s_l,\dots,s_r$）**：由引理 1、2，`substr` 不会越界，它返回从下标 $pos$ 开始的连续 $len$ 个字符，即下标
$$l-1,\; l,\; \dots,\; l-1+len-1 = r-1,$$
它们依次就是题面中第 $l, l+1, \dots, r$ 个字符，且顺序保持不变。$\square$

**定理**：算法对每个合法输入都输出正确答案。
由引理 3，$t = s_l s_{l+1}\cdots s_r$，正是题面要求的子串；题目给出的区间合法且固定，所以这个子串唯一确定，算法输出与唯一正确答案完全一致。$\square$

## 复杂度

- 时间复杂度：$O(n)$，瓶颈在读入字符串；截取本身是 $O(r-l+1)\le O(n)$。
- 额外空间复杂度：$O(r-l+1)$，用于存放答案子串（不计输入字符串本身）。

$n\le 1000$，两项都远低于 $1000\,\text{ms}$ / $256\,\text{MiB}$ 的限制。

## 边界情况

- **$n=1$**：此时只能是 $l=r=1$，答案就是唯一那个字符，如数据点 `min-1`。
- **$l=r$**（单字符区间）：`len = 1`，答案只有一个字符，如样例 2 与 `single-1..3`。若误写 `r - l` 会输出空串。
- **$l=1$ 且 $r=n$**（整串）：答案是整个字符串，如 `full-1`、`full-2`、`max-full-1`。此时"右端点当长度"的写法会**碰巧正确**，因此不能只靠这一形状判错。
- **贴左端**（$l=1<r$）与**贴右端**（$l>1,r=n$）：`prefix-*`、`suffix-*` 专门覆盖。
- **单字符开头的特殊形状**：`suffix-1/2` 与 `interior-*` 保证 $l>1$，使 `substr(l, ...)` 这类忘记减一的写法必然错位。
- **字符重复**：`repeat-same-*`（整串同一字符）与 `repeat-pattern-*`（周期串）。重复字符下"位置错了但内容看着像对"的错觉最容易出现，必须按位置截取。
- **$n$ 取上限 1000**：`max-full-1`、`max-random-1`、`near-max-1` 覆盖规模上限。

## 常见错误

按"思路 / 复杂度 / 实现"三层枚举本题特有的错误：

**思路层**

| 错误 | 后果 | 对应错解 | 击杀数据 |
|---|---|---|---|
| 把闭区间当成半开区间 $[l,r)$，长度写 `r - l` | 少输出最后一个字符（$l=r$ 时输出空串） | `wrong-exclusive-end` | `sample-1`、`single-*`、`full-*` 等 24 个点判 WA |
| 只用了左端点，忽略右端点（把区间理解成"从 $l$ 到末尾"） | 输出多余的尾部字符 | `wrong-ignore-right` | `sample-1`、`prefix-*`、`interior-*` 等 23 个点判 WA |
| 把 `substr` 第二个参数当成"右端点" | 长度变成 $r$，区间靠右时输出过长 | `wrong-end-as-length` | `sample-1`、`interior-*` 等 21 个点判 WA |

**复杂度层**

本题任何合理实现都是 $O(n)$（$n\le 1000$），不存在能通过"换算法"骗过 1000 ms 的渐进错误；也不存在需要刻意构造的 TLE 错解。**该层不适用，特此说明，不硬凑错解。**

**实现层**

| 错误 | 后果 | 对应错解 | 击杀数据 |
|---|---|---|---|
| 忘记把 $1$ 起始编号减一，`substr(l, ...)` | 整体右移一位，末尾多取/越界 | `wrong-zero-index` | `sample-1`、`suffix-*`、`interior-*` 等 26 个点判 WA |
| 手写循环时上界写成 `i < r - 1` | 漏掉第 $r$ 个字符 | `wrong-loop-drop-last` | `sample-1`、`single-*`、`full-*` 等 24 个点判 WA |
| 把 `l`、`r` 读成 `char` | 读入失败，后续全错 | —— | 由 `min-1` 起立刻判错（未单列错解，仅说明） |

以上 5 个错解全部在静态数据上被 **checker 判 WA/PE** 稳定击杀，首个失败点都是 `sample-1`，**不依赖任何意外的运行时崩溃（RE）**。

## 参考实现（C++17）

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string s;
    int l = 0, r = 0;
    cin >> s >> l >> r;

    // 起点 l-1（0 起始）；长度 r-l+1（闭区间含两端）
    cout << s.substr(l - 1, r - l + 1) << '\n';
    return 0;
}
```
