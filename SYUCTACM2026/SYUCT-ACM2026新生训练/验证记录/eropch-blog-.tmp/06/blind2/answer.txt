• ## 1. 任务、输入、输出与约束复述

  **任务**：给定一个非空字符串 s，长度 n = |s|，输出它的完全逆序串 t，满足对每个 1 ≤ i ≤ n 都有 t_i = s_{n+1−i}。逐字符颠倒位置，但每个字符本身不变：不去重、不增删、不做任何数字/字母语义转换。答案与 s 等长。

  **输入格式**：只有一行，内容为字符串 s（不含空格），行末可能有也可能没有换行符（可能是 LF，也可能是 CRLF）。全文件只有这一组数据。

  **输出格式**：一行，恰好是逆序后的字符串，不含长度、提示或任何多余字符。

  **约束**：
  - 1 ≤ |s| ≤ 1,000,000；
  - s 的每个字符 ∈ {`a`…`z`} ∪ {`0`…`9`}，不含空格、标点、大写字母；
  - 只有一组测试数据；
  - 1000 ms，256 MiB；
  - Judge：从输出中读取恰好一个不含空白的 token，与标准答案逐字符比较，缺字符、多字符、顺序错均为 WA；除该 token 及其后的空白外不得有任何内容；答案唯一。

  样例 1：`abca12` → `21acba`；样例 2：`syuctacm2026` → `6202mcatcuys`。

  ## 2. 算法

  思路：把整行读入一个 `std::string`（长度天然就是 n，且读入时不会截断），去掉行末可能残留的回车符，然后原地对称交换首尾字符。

  伪代码：

  ```
  读入一行 -> s
  while s 非空 且 s 末字符 ∈ {'\n', '\r'}: 删除末字符      // 防御性：兼容 CRLF 与无换行
  if s 为空: 再用 "跳过空白读 token" 的方式读一次 -> s      // 防御性兜底
  for i = 0 to n/2 - 1:                                     // n = s.size()
      交换 s[i] 与 s[n-1-i]
  输出 s，再输出一个 '\n'
  ```

  实现上用 `std::reverse(s.begin(), s.end())`，语义与上面的循环完全一致。

  ## 3. 正确性证明

  设 n = |s|，用 0-based 下标记原串为 s[0..n−1]，输出串为 t[0..n−1]。以下三条性质共同说明输出等于题面要求的答案。

  **引理 1（长度不变、字符集合不变）**：算法的唯一改写操作是交换 s[i] 与 s[n−1−i]。交换是位置的双射置换：任一位置被写入的字符，等于另一位置此前的字符。因此任意时刻串中字符的多重集合（每个字符及其出现次数）保持不变，长度也不变。故输出长度仍为 n，且 s 中每个字符在 t 中出现的次数与在 s 中完全相同——不丢、不增、不去重。这也覆盖了题面对“数字 2 出现两次、c 出现两次都各自保留”的要求。

  **引理 2（位置正确）**：对 0 ≤ i ≤ n−1，最终 t[i] = s[n−1−i]。

  证明：交换循环对每个 i ∈ [0, ⌊n/2⌋−1] 恰好执行一次；循环结束后不再有任何写操作。分三种情形：
  - 若 i < ⌊n/2⌋：位置 i 在它被处理的那一步（第 i 步）被写入 s[n−1−i]，此前位置 i 未被处理过（第 j < i 步只写 j 与 n−1−j，且 n−1−j > i），此后也不再被处理（第 j > i 步写 j 与 n−1−j，均 ≠ i），故最终 t[i] = s[n−1−i]。
  - 若 i > n−1−⌊n/2⌋，即 i 是某个 j < ⌊n/2⌋ 的对称位置 n−1−j：它在第 j 步被写入 s[n−1−j′] 中相对的那个 s[n−1−i] = s[j]，与此后不再变动，结论同式。
  - 若 i = n−1−i（n 为奇数时的中点）：该位置从未被写入，t[i] = s[i] = s[n−1−i]，仍成立（不存在“自己换自己”的错位）。

  （若改用 `std::reverse`，其规定等价于对全部 i 执行 swap(s[i], s[n−1−i])，两点交换的净效果与上述“只做前半”完全相同：重复执行一次对称交换即还原，故结论不变。）

  **引理 3（输出格式合法）**：程序恰好输出 n 个字符（均为 `a`–`z` 或 `0`–`9`，绝无空白，因为交换不产生新字符且引理 1 保证字符来源全部是输入字符）加一个 `'\n'`。由于 `'\r'` 在输入阶段已被剥离，它不会被卷进反转结果而跑到 token 最前面。故输出中不含空白的 token 恰为 t，其后仅有行末空白。

  **定理**：对任意合法输入，程序输出恰为唯一正确答案 t 加一个行末换行。由引理 1 与引理 3，token 长度为 n 且字符集合与 s 一致；由引理 2，其第 i 个字符为 s[n−1−i]（1-based 即 t_i = s_{n+1−i}）。这正是题面对答案的完整定义，而题面保证答案唯一，故输出与标准答案逐字符相同。

  ## 4. 复杂度

  - 时间：读入 O(n) + 反转 O(n) + 输出 O(n)，总计 **O(n)**。
  - 空间：字符串本体 O(n)（这既是输入也是输出缓冲）；除它之外只用到常数个下标/临时字符，辅助空间 **O(1)**。
  - 最坏规模 n = 10^6 时的可行性：字符总量约 1 MB，反转约 5×10^5 次 swap，读入/输出约 2 MB 的字节流；在 1000 ms 内属于毫秒量级，内存占用约 1–2 MiB（含 iostream 缓冲），相对 256 MiB 余量极大。**安全**。

  ## 5. 边界情况与高风险用例

  - n = 1：`a` → `a`；`0` → `0`；`7` → `7`（此时反转不应 `swap` 自己，或需保证 swap 同位置无副作用）。
  - 全同字符：`aaaa` → `aaaa`，`000000` → `000000`（不做去重、不做数值处理）。
  - 纯数字且含前导/尾随零：`1000` → `0001`；`0` 开头必须保留。
  - 交替模式：`a0b0` → `0b0a`；`abab` → `baba`（易在奇偶中点处写错）。
  - 输入无行末换行（EOF 直接结束）：`getline` 仍应读到完整串，不得因 EOF 丢字符。
  - **CRLF 行尾**：若把 `'\r'` 读进串再反转，它会变成输出的第一个字符，token 直接错位 → 必须剥离。
  - 长度恰为 10^6 的单行：任何逐字符 `s = ch + s` 的写法都会超时。
  - 输出后只允许一个换行（或 CRLF），不得额外打印长度、空格、调试信息、多行。
  - 字符串含 `0` 与 `O` 混淆风险：题面只有数字 0 和小写字母，不存在大写 `O`，不要“纠正”字符。

  ## 6. 常见错误

  **思路层**：把串当整数处理——用 `stoll`/`atoi` 读入再输出，导致 `1000` 变成 `1` 或 `0001` → `1`（丢前导零），或长度 10^6 时溢出；或误以为要去重/降序排序；或先输出长度再输出串。

  **复杂度层**：用 `s = s[i] + s`、`s.insert(s.begin(), ch)` 逐字符前插，单次 O(n)、总计 O(n²)，n = 10^6 时约 5×10^11 次字符搬移，必然超时；或用递归 `reverse(s.substr(1)) + s[0]`，既 O(n²) 又爆栈。

  **实现/下标层**：
  - 循环写成 `for (int i = n-1; i > 0; --i)`，漏掉下标 0 的字符，输出少一个；
  - 用 `size_t`/`unsigned` 做 `for (size_t i = n-1; i >= 0; --i)`，i 减到 0 后回绕成巨大值，死循环或越界；
  - 忘记 `ios::sync_with_stdio(false)` 或使用 `endl` 刷缓冲导致 I/O 偏慢（本题规模下通常仍过，但属不必要的风险）；
  - 用 `cin >> s` 与 `getline` 混用前未处理残留换行，读到空串；
  - 未剥离 `'\r'`（Windows 行尾）导致输出首位是回车、token 少一字符；
  - `std::reverse` 后忘记输出换行或多输出空行/提示文字。

  ## 7. 参考程序（GNU C++17）

  ```cpp
  #include <algorithm>
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      std::string s;
      if (!std::getline(std::cin, s)) {
          return 0;
      }
      while (!s.empty() && (s.back() == '\n' || s.back() == '\r')) {
          s.pop_back();
      }
      if (s.empty()) {
          if (!(std::cin >> s)) {
              return 0;
          }
      }

      std::reverse(s.begin(), s.end());

      s.push_back('\n');
      std::cout.write(s.data(), static_cast<std::streamsize>(s.size()));
      return 0;
  }
  ```

  ## 8. 假设、无法证明之处与剩余风险

  - **假设**：输入严格符合题面——单行、无空格、无多余空白、字符仅 `a`–`z`/`0`–`9`、非空、长度 ≤ 10^6。程序在该假设下正确；`getline` 失败或读成空串的分支只是防御性兜底，不构成对合法输入的行为改变。
  - **假设**：Judge 依据题面所述语义工作——取一个不含空白的 token 逐字符比较，并容忍 token 之后的空白。程序只输出“n 个字符 + 一个 LF”，若 Judge 实际上对行末空白也不容忍（与题面矛盾），则任何输出都会失败，这不是算法能规避的问题。
  - **无法证明之处**：无。引理 1–3 与定理只依赖交换置换的性质和字符集约束，对一切合法输入成立，不依赖任何未给出的实现或数据。
  - **剩余风险**：仅剩“评测环境为 Windows 风格 CRLF 且某处保留 `'\r'`”这一实现细节风险，已由剥离逻辑消除；以及极端的 I/O 环境差异（不影响正确性，且关闭同步后余量充足）。除此之外无剩余风险。
