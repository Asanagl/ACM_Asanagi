• ## 1. 任务、输入、输出与约束（复述）

  **任务**：给定一个只由英文字母组成的字符串 s，统计五个元音字母 `a, e, i, o, u` 各自出现的次数。统计不区分大小写：`A` 计入 a，`B` 之外的规则也同理，`E→e`、`I→i`、`O→o`、`U→u`；`y` 和 `Y` **不是**元音，不计入任何一项。

  **输入格式**：恰好一行，一个字符串 s，不含任何空白字符（不含空格、制表符；行末换行之后没有任何内容）。

  **输出格式**：恰好一行，五个非负整数，顺序固定为 `a e i o u` 的次数，相邻整数之间用一个空格分隔，第五个数之后立即结束（只允许一个行末换行，LF 或 CRLF 均可）。不得有额外 token、说明文字或第二行；空白仅作分隔符，数值写法唯一（十进制、无前导多余修饰）。

  **约束**：
  - 1 ≤ |s| ≤ 1,000,000。
  - s 的每个字符都是 `a`–`z` 或 `A`–`Z`；不含空格、数字、标点、非 ASCII 字符。
  - 每个答案都不超过 10^6，因此 32 位整数足够。
  - 资源限制：1000 ms，256 MiB。答案唯一。

  **样例**：`HeLloWorld` → `0 1 0 2 0`；`AEIOUaeiou` → `2 2 2 2 2`；`yes` → `0 1 0 0 0`。

  ## 2. 算法

  一次线性扫描 + 五个计数器。核心是把每个字符规范化为小写形式，再按小写形式归入五个桶之一。

  ```
  读入整行字符串 s（长度 n ≥ 1）
  cnt[0..4] ← 0                     // 依次对应 a e i o u
  for ch in s:                      // 逐字符
      c ← ch OR 0x20                // 对英文字母即"转小写"
      if c == 'a': cnt[0] += 1
      elif c == 'e': cnt[1] += 1
      elif c == 'i': cnt[2] += 1
      elif c == 'o': cnt[3] += 1
      elif c == 'u': cnt[4] += 1
      else: 不做任何事               // 辅音（含 y/Y）与其它字符
  输出 cnt[0], 空格, cnt[1], 空格, cnt[2], 空格, cnt[3], 空格, cnt[4], 换行
  ```

  关键点：

  - 转小写用按位或 `0x20` 而不是 `tolower`，避免本地化/符号扩展问题；在"只含 ASCII 字母"的前提下它与"转小写"完全等价（见引理 1）。
  - 只做一次遍历，不做排序、去重、哈希，也不做任何字符串拼接。
  - 计数器用 64 位仅为稳妥，最大 10^6 远小于 `int` 上限。
  - 输出用手写空格分隔，保证严格是"五个 token + 一个换行"，不多不少。

  ## 3. 正确性证明

  记元音表 `v = (a, e, i, o, u)`，下标 `j ∈ {0,1,2,3,4}`；记 `low(c)` 为字符 c 的小写形式。

  **引理 1（规范化正确）**：对 s 中任一字符 c，程序计算的 `c OR 0x20` 等于 `low(c)`。

  *证明*：由约束，c 只能是 ASCII 大写字母（0x41–0x5A）或小写字母（0x61–0x7A），分两种情形：
  - c ∈ 0x41–0x5A：这些码值的二进制形如 `010x xxxx`，第 5 位（值 0x20）为 0；置位后得到 `011x xxxx` = 0x61–0x7A，正是对应的 `a`–`z`，即 `low(c)`。
  - c ∈ 0x61–0x7A：这些码值第 5 位已为 1，按位或 0x20 是幂等操作，结果仍为 c = `low(c)`。

  两种情形穷尽了所有合法字符，故引理成立。∎

  **引理 2（扫描不变式）**：对任意 k（0 ≤ k ≤ n），在 for 循环已处理完前 k 个字符 `s[0..k-1]` 之后，对每个 j 有
  `cnt[j] = #{ t : 0 ≤ t < k 且 low(s[t]) = v[j] }`。

  *证明*：对 k 施归纳。
  - 基始 k = 0：循环未执行，`cnt` 全为 0，右侧集合为空集，计数为 0，成立。
  - 归纳步：设处理完前 k 个字符后不变式成立，考察处理 `s[k]`。由引理 1，程序得到的 `c = low(s[k])`。`c` 至多等于 `v` 中一个元素（五个元音两两不同）；若它等于某个 `v[j]`，程序恰好把 `cnt[j]` 加 1，其余桶不变，于是第 j 个桶的计数等于旧值 +1，正好等于"前 k+1 个字符中 `low` 为 `v[j]` 的个数"；若 `c` 不等于任何 `v[j]`（即辅音，含 y/Y），所有桶不变，而 `s[k]` 也不属于右侧任何一个集合，等式同样保持。∎

  **定理（输出正确）**：循环结束后，程序输出的第 j 个整数恰为 s 中 `v[j]`（大小写合并）出现的次数。

  *证明*：取引理 2 中 k = n，得 `cnt[j] = #{ t : 0 ≤ t < n 且 low(s[t]) = v[j] }`。而"`low(s[t]) = v[j]`"当且仅当"s[t] 是 `v[j]` 的小写或大写形式"，即 s[t] 属于 `v[j]` 的大小写合并类。故 `cnt[j]` 正是该元音（不分大小写）的出现次数。

  另外，循环对每个下标 t 恰好访问一次、且每次只影响一个桶（或零个桶），不存在重复计数或漏计；因此五个计数之和等于 s 中元音字符的总数，也自洽。

  **输出格式正确**：程序依次打印 `cnt[0..4]`，相邻整数间输出且仅输出一个空格，末尾输出一个换行，之后不再输出任何内容。故选手输出与官方答案都是"五个十进制非负整数 + 单个换行"，逐 token 比较时五个数依次相等，且两侧都在第五个整数后结束，无多余 token；判题语义（唯一答案、允许 LF/CRLF）被满足。∎

  **边界相关的正确性**：n = 1 时不变式在 k = 1 直接给出结果；全为辅音时所有桶保持 0，输出 `0 0 0 0 0`；全为同一元音的大写形式时对应桶为 n，其余为 0。均无需特判。

  ## 4. 复杂度与资源安全性

  - **时间复杂度**：O(n)。每个字符常数次操作（一次按位或、至多五次整数比较/跳转），n ≤ 10^6，即约 10^6 量级的字符处理，加上 O(n) 的读入和常数级输出。在 1000 ms 限制下余量极大（典型运行时间在毫秒级）。
  - **额外空间复杂度**：O(1)（除输入缓冲区外）。计数器为定长 5 元素数组，无动态结构、无递归。输入缓冲 O(n) 字节，n = 10^6 时约 1 MB，加上 iostream 缓冲区，总量约 1–2 MB，远低于 256 MiB。
  - **结论**：最坏规模（|s| = 10^6）在 1000 ms / 256 MiB 下**安全**。

  ## 5. 边界情况与高风险用例

  边界：
  - n = 1：`a` → `1 0 0 0 0`；`A` → `1 0 0 0 0`；`y` → `0 0 0 0 0`；`z` → `0 0 0 0 0`。
  - 零元音：`bcdfghjklmnpqrstvwxz` / `BCDFG` → `0 0 0 0 0`。
  - 全元音且大小写成对：`AEIOUaeiou` → `2 2 2 2 2`（验证"分别计数"而非只数总数）。
  - 只有某一元音达到上限：10^6 个 `A` → `1000000 0 0 0 0`；10^6 个 `u` → `0 0 0 0 1000000`（验证不溢出、不串桶）。
  - 顺序敏感：`uoiea` → `1 1 1 1 1` 正确；若实现把输出顺序写成 `a i u e o` 等顺序错误，只有计数不同的用例才暴露，故测试须包含各元音次数互不相同的串（如 `HeLloWorld`）。

  高风险用例（易错点清单）：
  1. **把 y/Y 当元音**：`yes` → `0 1 0 0 0`；`YyYy` → `0 0 0 0 0`；`Yoyo` → `0 0 0 1 0`。
  2. **只统计小写或只统计大写**：`AAAA` → `4 0 0 0 0`；`aaaa` → `4 0 0 0 0`；`aA` → `2 0 0 0 0`。
  3. **大小写混排 + 混合字符**：`PrOgrAmming` → a:1, e:0, i:1, o:1, u:0（`0 0 1 1 0` 形式需按实际串核对），务必以含大小写混合的真实串做回归。
  4. **CRLF 行尾**：若读入整行后把 `\r` 当字符处理，虽然 `\r` 不匹配任何元音故结果仍正确，但更稳妥的做法是按空白分隔读 token，天然截断 `\r`；本实现采用后者。
  5. **文件末尾无换行**：输入最后一行可能没有 `\n`，按 token 读仍能读到完整串。
  6. **输出多余内容**：任何调试打印、第二行、行尾多余空格（本题容忍度为"仅分隔用空白"，但多余尾随空格在某些严格 checker 上可能被视为额外 token 边界，故不输出）、`\r\n` 之外的自造换行都可能被判错；本实现只输出一次换行。
  7. **超大输入的性能陷阱**：用 `cin` 未解除同步、或逐字符 `cout` 输出（本题只输出 5 个数，无风险）；本实现已 `sync_with_stdio(false)` + `tie(nullptr)`。
  8. **计数类型**：用 `int` 亦够（≤ 10^6），但若实现把多个计数累加进同一变量再拆分则可能出错，故保持五个独立桶。
  9. **空输入防护**：题面保证 n ≥ 1；程序仍对读入失败做了保护，避免未定义行为。

  ## 6. 完整程序（GNU C++17）

  ```cpp
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      std::string s;
      if (!std::cin >> s) {
          std::cout << "0 0 0 0 0\n";
          return 0;
      }

      long long cnt[5] = {0, 0, 0, 0, 0};
      for (char ch : s) {
          char c = static_cast<char>(static_cast<unsigned char>(ch) | 0x20u);
          switch (c) {
              case 'a': ++cnt[0]; break;
              case 'e': ++cnt[1]; break;
              case 'i': ++cnt[2]; break;
              case 'o': ++cnt[3]; break;
              case 'u': ++cnt[4]; break;
              default: break;
          }
      }

      for (int j = 0; j < 5; ++j) {
          if (j) std::cout << ' ';
          std::cout << cnt[j];
      }
      std::cout << '\n';
      return 0;
  }
  ```
