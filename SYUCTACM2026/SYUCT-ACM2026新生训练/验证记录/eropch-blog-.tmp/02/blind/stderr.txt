  Notation: Let the input after the optional terminator be s = s_0 s_1 … s_{n-1}, n = |s|.

  Precondition from the input spec: the input byte stream is exactly s, optionally followed by one '\n', then EOF; all s_i ∈ [32,126].

  Lemma 1 (read correctness). After `std::getline(std::cin, s)`, the program variable s equals s_0…s_{n-1}.
  Proof: getline first clears the string, then extracts characters one by one and appends each until it either sees the delimiter '\n' (which it extracts but does not append) or reaches EOF. By the precondition, the first '\n' in the stream, if it exists, is exactly the terminator right after s_{n-1}; before it the stream contains exactly s. If no '\n' exists, the stream ends right after s_{n-1} (or is empty). In the empty-input case getline extracts no character and (since C++11) leaves s as the cleared empty string. Therefore the stored string is exactly s. Note getline does not skip whitespace and preserves leading/trailing spaces, unlike `operator>>`. ∎

  Lemma 2 (count correctness). At loop exit, cnt = |{i : s_i = ' '}|.
  Proof: invariant after processing the first k characters: cnt equals the number of j < k with s_j = ' '. Base k=0. Step: the k-th character c = s_k is tested; if c = ' ' cnt increases by 1, else unchanged; both match the definition of the count over j < k+1. The range-for visits k = 0..n-1 exactly once. At k = n the invariant gives the claim. Moreover, `c == ' '` is true exactly when the byte value is 32: ' ' has value 32 in ASCII, all codes are distinct, and all input codes are in [32,126] so even a signed char holds a non-negative value → no sign/locale pitfalls (unlike isspace, which also accepts '\t','\n','\r','\f','\v' and is locale-dependent and UB for negative char). ∎
