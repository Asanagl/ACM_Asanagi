• # 盲审报告：空格计数

  ## 1. 任务、输入输出与约束复述

  **任务**：给定一行文本 s，统计其中 ASCII 码为 32 的空格字符的个数。每个空格都要单独计一次，不做任何裁剪或合并——连续空格按个数算，行首、行尾的空格同样算。

  **输入**：标准输入中恰好有一行，内容就是 s。行末的换行符是行分隔符，不属于 s，不计数。除这一行和它的行末换行之外没有别的内容；不会有多行，也不会有前置空行。

  **字符范围**：每个字符都是可打印 ASCII，32 ≤ code ≤ 126。因此 s 里唯一可能出现的空白字符就是空格（32）；题面明确不含制表符，也不含回车等其它空白。

  **长度**：0 ≤ |s| ≤ 100000。

  **输出**：一个非负整数（空格总数），后跟一个换行符。答案唯一，不能有说明文字、不能有第二行。

  **三种情形要特别说清**：

  - **空串**：输入是一个空行（或 0 字节的文件，等价于空行），s = ""，答案是 0。这不是“读失败”或“无输入”，程序必须正常输出 0。
  - **全空格**：s 的每个字符都是空格，答案是 |s|，最大可达 100000。
  - **连续空格**：一段长度 L 的连续空格贡献 L，而不是 1。样例 1 的 `a  b   c` 是 2 + 3 = 5；样例 3 的 `  a   b ` 是行首 2 + 中间 3 + 行尾 1 = 6。

  **判定语义**：checker 从标准答案和选手输出中各读一个非负整数，要求两者在该整数之后立即结束（允许末尾空白/换行），不得有额外内容；数值相等才 AC。所以输出 `5\n` 合法（末尾换行属于允许的空白），输出 `ans=5` 或输出两行都不合法。

  ## 2. 算法与正确性证明

  ### 算法

  1. 用 `std::getline(std::cin, s)` 把整行读入 `std::string s`：它不跳过空白，保留行首/行尾空格，并把行末 `'\n'` 取走且不存入。
  2. 计数器 `cnt = 0`。
  3. 顺序扫描 s 的每个字符 c，若 `c == ' '`（ASCII 32）则 `cnt` 加一。
  4. 输出 `cnt` 和一个换行，结束。

  关键选择：用 `getline` 而不是 `cin >> s`（后者遇空白即停，只能读到第一个“单词”）；用 `c == ' '` 而不是 `isspace`（后者会连带统计 `\t \n \v \f \r`，且依赖 locale、对负值 char 还是未定义行为）。

  ### 证明

  记读入后参与统计的字符为 s = s₀s₁…s_{n-1}，n = |s|。由输入格式，输入字节流恰好是 s，后面可选地跟一个 `'\n'`，然后 EOF；且所有 sᵢ ∈ [32,126]。

  **引理 1（读入正确）**：`getline` 之后，变量 s 恰好等于题面的 s₀…s_{n-1}。

  *证明*：`getline` 先清空目标串，然后逐字符提取并追加，直到遇到分隔符 `'\n'`（提取但不追加）或到达 EOF。由前置条件，流中若存在 `'\n'`，它只能是紧跟在 s_{n-1} 之后的那个行末换行；它之前的内容恰好是 s。若不存在 `'\n'`，则流在 s_{n-1} 之后（或一开始就）结束。空输入时 `getline` 一个字符都没提取到，按 C++11 起的语义目标串已先被清空，故 s 为空串，正好对应题面的空串。整个过程不跳过任何空白，因此行首、行尾空格都被保留。∎

  **引理 2（计数正确）**：循环结束时 cnt = |{ i : sᵢ = ' ' }|。

  *证明*：取循环不变式“处理完前 k 个字符后，cnt 等于 s₀…s_{k-1} 中空格个数”。k = 0 时 cnt = 0，成立。归纳步：第 k 个字符 c = s_k 被测试一次，等于 `' '` 则 cnt 加 1，否则不变，两种情形都恰好等于前 k+1 个字符中的空格数。范围 for 按顺序恰好访问 k = 0…n-1 各一次。取 k = n 即得结论。另外，`c == ' '` 成立当且仅当字节值为 32：`' '` 的编码就是 32，输入字符编码互不相同，且全部 ≤ 126，所以即使 char 是有符号类型也不会出现负值，比较是精确的字节比较，不受 locale 影响。∎

  **引理 3（输出合法）**：程序只输出 cnt 的十进制表示和一个 `'\n'`，随后结束。

  *证明*：0 ≤ cnt ≤ n ≤ 100000，非负且不溢出 `long long`；`cout` 输出其十进制数字；程序中只有这一条输出语句，`return 0` 触发刷新并终止。于是 checker 读到一个非负整数、其后只有允许的末尾空白、随即到达流尾，符合判定要求。∎

  **定理**：对任意满足题面约束的输入，程序输出恰好等于 s 中 ASCII-32 字符的个数，即唯一正确答案。

  **三种情形的推论**：
  - n = 0：循环体一次不执行，cnt = 0。
  - 全空格：每个字符都通过测试，cnt = n。
  - 连续空格：算法没有“段”的概念，逐位置独立判定，长度 L 的连续段贡献 L，与逐字符定义一致。

  ## 3. 复杂度与资源判断

  - **时间**：读入 O(n)（n ≤ 10⁵ 字节的拷贝），扫描 O(n) 次字符比较，输出 O(log n) 位数字。总量约 10⁵ 次操作，即使算上 iostream 常数也在毫秒级。**1000 ms 非常从容**（余量约三个数量级以上）。
  - **额外空间**：`std::string s` 至多 10⁵ 字节 ≈ 98 KiB，加上常数个变量和标准流缓冲区（几 KiB）。相对 256 MiB（268435456 字节）占比不到 0.05%，**完全从容**。若改写成流式逐字符统计（见下），额外空间可降到 O(1)。

  ## 4. 边界条件、常见错误与风险用例

  ### 必测边界

  | 输入（`\n` 表示行末换行） | 说明 | 期望 |
  |---|---|---|
  | 0 字节文件 | s = "" | 0 |
  | `\n` | 空行 | 0 |
  | `" "` | 单个空格 | 1 |
  | `"   "` | 全空格 | 3 |
  | `"a"` | 无空格 | 0 |
  | `" a"` | 行首空格 | 1 |
  | `"a "` | 行尾空格 | 1 |
  | `" a "` | 两端都有 | 2 |
  | `"a  b   c"` | 连续空格（样例 1） | 5 |
  | `"  a   b "` | 样例 3 | 6 |
  | `"!~"` | 与 32 相邻的可打印字符 | 0 |
  | 10⁵ 个空格 | 最大值 | 100000 |
  | 10⁵ 个 `a` | 最大长度、零答案 | 0 |
  | `"ab  "`（无行末换行） | EOF 收尾 | 2 |

  ### 常见错误

  1. **`cin >> s` / `scanf("%s")`**：遇空格停止，答案几乎恒为 0 或单词内空格数，样例 1 立刻暴露。
  2. **`gets` / 定长 `char` 缓冲**：`gets` 已从 C++ 移除且不安全；`fgets` 需 ≥ 100002 字节缓冲，否则截断。
  3. **`scanf("%[^\n]", buf)`**：空行时返回 0、缓冲区内容不定；写成 `scanf(" %[^\n]", …)` 时格式串里的空格还会吃掉行首空格。
  4. **`isspace` / `isblank`**：语义不对（会算 `\t\r` 等），且传入负值 char 是未定义行为、结果受 locale 影响。
  5. **把“段数”当答案**：样例 1 会输出 2 而非 5。
  6. **先 trim 再数**：去掉首尾空格后样例 3 会输出 3 而非 6。
  7. **读数失败就提前返回**：`getline` 后写 `if (!cin) return 0;`，在 0 字节输入时会**一个数都不输出**，checker 拿不到整数 → WA/RE。这是本题最隐蔽的坑：空输入恰恰是合法输入，正常应输出 0。注意 `cin` 的 failbit 不影响 `cout` 输出。
  8. **输出杂质**：多输出一行、输出 `ans=5`、或用 `printf("%d", long long值)` 造成类型不匹配的未定义行为。
  9. **用 `char c` 接 `getchar()/cin.get()`**：EOF(-1) 与 char 比较会在 0xFF 字节处误判（本题输入不含 0xFF，但写法本身错误），应使用 `int`。
  10. **自己写多行循环累加**：题面保证只有一行，单次 `getline` 才是对“仅有一行”最直接的实现；循环累加在遇到额外行时会偏离语义。

  ### 环境风险

  - **CRLF 行尾**：若文件用 `\r\n`，`getline` 会把 `'\r'`（13）留在串尾。由于只比较 32，答案不变——但用了 `isspace` 或做 trim 的解法会因此偏一位。本题声明输入无其它空白，此风险仅是防御性提示。
  - **文件末尾无换行**：正常，`getline` 在 EOF 处返回已读内容。
  - **0 字节输入**：合法，必须输出 0（见错误 7）。
  - **最大全空格行**：同时压测计数上限与 I/O，答案 100000，需保证计数器非负且不溢出。

  ## 5. 参考程序（C++17，单文件）

  ```cpp
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      std::string s;
      std::getline(std::cin, s);   // 空行/空输入时 s 为空串，无需特判

      long long cnt = 0;
      for (char c : s) {
          if (c == ' ') ++cnt;     // 只认 ASCII 32
      }

      std::cout << cnt << '\n';
      return 0;
  }
  ```

  编译：`g++ -std=gnu++17 -O2 -o sol sol.cpp`。

  等价的 O(1) 额外空间写法（不保存整行，逐字符读到底），本题同样正确：

  ```cpp
  #include <iostream>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      long long cnt = 0;
      int c;
      while ((c = std::cin.get()) != EOF && c != '\n') {
          if (c == ' ') ++cnt;
      }

      std::cout << cnt << '\n';
      return 0;
  }
  ```

  两版都满足：空串输出 0、全空格输出 |s|、连续空格逐个计数、只输出一个整数加一个换行，因而在 1000 ms / 256 MiB 下按题意与 checker 语义均可 Accepted。
