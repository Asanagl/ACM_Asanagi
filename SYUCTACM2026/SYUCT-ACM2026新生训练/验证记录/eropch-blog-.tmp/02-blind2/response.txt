• ## 1. 任务、输入、输出与全部约束的复述

  **任务**：给定一行文本 $s$，统计 $s$ 中 ASCII 码为 32 的空格字符（`' '`）的个数。这是逐字符的字面计数：每个空格字符各算一次，不做任何"压缩""合并""去重"。

  **输入格式**：输入仅有 1 行，内容就是 $s$。行末的换行符 `'\n'` 不属于 $s$，不计入答案。输入行可能为空，此时 $s$ 是空串。除该行及其行末换行外，输入中没有任何其他内容。

  **输出格式**：向标准输出写入一个十进制非负整数，即 $s$ 中空格字符的个数，其后跟一个换行符。答案唯一，不得输出任何说明文字、多个整数或第二行。

  **数据范围**：$0 \le |s| \le 100\,000$；每个字符的 ASCII 码在 $[32, 126]$ 内（可打印 ASCII，可以含空格）；除行末换行外没有其他空白字符，$s$ 中不含制表符。资源限制：时间 1000 ms，内存 256 MiB，语言标准 gnu++17。

  **三种容易被误处理的情形如何计数**：

  - **空串**（$|s| = 0$）：答案是 $0$。注意这对应两种输入形态——文件 0 字节（连换行都没有），或文件内容只有一个换行符（一个"空行"）。两种都必须输出 $0$。
  - **全部由空格组成**（$s$ 由 $k$ 个空格构成）：答案是 $k$，即 $|s|$。不能因为"整行都是空白"就输出 $0$，也不能输出 $1$。
  - **连续多个空格**：一段连续的 $m$ 个空格贡献 $m$，逐个计数，绝不合并为一个。同理，行首的空格段落、行尾的空格段落都要计入，不能"跳过前导空白"或"忽略行尾空白"。

  ## 2. 算法

  单次整行读入 + 单趟线性扫描：

  1. 用 `std::getline(std::cin, s)` 把整行一次性读入 `std::string s`（遇到行末 `'\n'` 即停止，并把该 `'\n'` 取出丢弃，不放入 `s`）。`s` 预先初始化为空串，因此"0 字节输入"这种情况下也保持为空串。
  2. 令计数器 `cnt = 0`。
  3. 用 range-for 遍历 `s` 的每个字符 `c`：若 `c == ' '`，则 `++cnt`。
  4. 输出 `cnt` 后跟 `'\n'`。

  关键点有两个：读入必须是"整行"读入（保留前导、行尾空格），比较必须是"恰好等于 `' '`"（不是 `isspace`）。

  ## 3. 正确性证明

  设题面定义的字符串为 $s = s_0 s_1 \cdots s_{n-1}$，$n = |s| \in [0, 10^5]$。由输入格式约定，输入字节流 $B$ 只可能是下列三种形态之一：$B = s\,\text{'\n'}$（$n \ge 0$）、$B = s$ 且紧接 EOF（$n \ge 1$）、或 $B$ 为空（$n = 0$）。

  **引理 1（读入阶段拿到的正是题面定义的字符串）**：执行 `std::string s; std::getline(std::cin, s);` 之后，`s` 恰好存放 $s_0 s_1 \cdots s_{n-1}$。

  *证明*，对 $B$ 的三种形态分情形讨论：

  - **情形 A：$B = s\,\text{'\n'}$。** `getline` 的 sentry 构造成功（流中仍有字符可取），随后先清空目标串 `s`（此时它本来就是空的），再从流中逐字符提取并依次追加到 `s`，直到提取到分隔符 `'\n'` 为止；该 `'\n'` 被提取并**丢弃**，不追加到 `s`。被提取并追加的字符恰好是 $s_0, \dots, s_{n-1}$，顺序不变，故 `s` $= s_0\cdots s_{n-1}$。特别地，$n = 0$ 时（输入只有一个空行）第一个被提取的就是 `'\n'`，立即丢弃，`s` 仍为空串，与题面 $s$ 为空串一致。同时这也说明**换行符永远不进入 `s`**，因此不可能被计入答案。
  - **情形 B：$B = s$，无行末换行，直接 EOF。** `getline` 在分隔符前遇到 EOF，已提取的 $n$ 个字符全部追加到 `s` 并返回；`s` $= s_0\cdots s_{n-1}$。置位 `eofbit`/`failbit` 不影响结果（我们不依赖返回值）。
  - **情形 C：$B$ 为空（0 字节）。** sentry 失败（无字符可取），`getline` 不进行任何提取即返回，`s` 保持其初始化值——空串；这与题面在 $n=0$ 时定义的 $s$ 相同。即使某实现先清空再失败，结果同样是空串。

  三种情形穷尽了输入流的所有可能形态，故 `s` 恒等于题面定义的字符串。$\blacksquare$

  **引理 2（每个字符恰被访问一次）**：`for (char c : s)` 等价于对区间 $[\texttt{s.begin()}, \texttt{s.end()})$ 的自增迭代，按索引顺序访问 $0, 1, \dots, n-1$ 各一次。循环体内不修改 `s`，因此 `s.size()` 与迭代器不失效，循环恰好执行 $n$ 次。

  *证明*：`std::string` 是连续存储容器，`begin()` 到 `end()` 的距离为 $n$，迭代器每次 `++` 前进一个元素，故迭代器恰好取得 $n$ 个互不相同的元素且覆盖全部下标；循环内无对 `s` 的写操作，故区间不变。$\blacksquare$

  **引理 3（计数阶段不变式）**：记 $C_k = |\{\, j : 0 \le j < k,\ s_j = \text{' '} \,\}|$。则对每个 $k \in [0, n]$，第 $k$ 次迭代开始前有 `cnt` $= C_k$。

  *证明*（对 $k$ 归纳）：$k = 0$ 时 `cnt` $= 0 = C_0$。设第 $k$ 次迭代开始前 `cnt` $= C_k$；该次迭代取到字符 $s_k$，当且仅当 $s_k = \text{' '}$ 时 `cnt` 自增 $1$，因此迭代结束后 `cnt` $= C_k + [s_k = \text{' '}] = C_{k+1}$，即第 $k+1$ 次迭代开始前不变式成立。$\blacksquare$

  **定理（输出正确且格式合规）**：程序输出的整数恰为 $s$ 中空格字符的个数，且输出中不含其他内容。

  *证明*：循环执行 $n$ 次后终止（有限性显然），由引理 3（$k = n$）得 `cnt` $= C_n$，而 $C_n$ 按定义正是 $s$ 中空格字符的个数。由引理 1，这个数就是题面所定义字符串中的空格数；由引理 2 与"仅当 `c == ' '` 才自增"的判定，**每个空格字符恰好被计入一次、非空格字符恰好被计入零次**，既不漏（行首、行尾、连续空格一视同仁，因为没有任何跳过或规约逻辑）也不重（每个下标只被访问一次，且每次访问最多自增 $1$）。`cnt` 从 $0$ 起只增不减，故是非负整数。最后 `std::cout << cnt << '\n'` 只写出 `cnt` 的十进制表示和紧随的一个换行符，无前缀、无后缀、无第二行，符合 Judge 语义。$n = 0$ 时循环体执行 $0$ 次，输出 `0`，与样例 2 一致。$\blacksquare$

  ## 4. 复杂度

  - **时间**：$O(n)$，其中 $n = |s| \le 10^5$。只有一趟 $10^5$ 次字符比较，加上约 $10^5$ 字节的输入输出，实际耗时在毫秒量级以下（通常 < 5 ms）。相对 1000 ms 有约两个数量级以上的余量，**非常从容**。
  - **额外空间**：$O(1)$ 辅助空间（一个计数器、一个循环变量）。总空间是 `std::string` 的约 $n+1$ 字节即约 100 KB，加运行时开销，远低于 256 MiB（余量约三个数量级），**非常从容**。

  ## 5. 边界情况与高风险用例清单

  | # | 用例（`\n` 表示行末换行） | 期望输出 | 考察点 |
  |---|---|---|---|

  | 2 | 仅 `\n`（空行） | `0` | 空串的标准形态 |
  | 3 | `" "` + `\n`（单个空格） | `1` | 不能被当成"空行"而输出 0 |

  | 7 | 行尾空格 `"a  \n"` | `2` | 尾随空格不能裁 |

  ## 6. 常见错误清单

  1. **`cin >> s`（或 `scanf("%s", buf)`）**：格式化输入默认开启 `skipws`，会先跳过行首全部空白，然后读到下一个空白字符就停止。于是 `"  a   b "` 只得到 `"a"`，输出 `0`（应为 `6`）；`"   "` 这类全空格行什么都读不到并置 `failbit`，输出 `0`（应为空格数）。也就是说"行首空格""连续空格""行尾空格"三类信息在读入阶段就已经永久丢失，事后无法补救。这正是题面说明中明确警告的错误。
  2. **用 `getline` 读了整行，却又做了归一化**：例如用 `stringstream` 拆词、`erase(remove_if(...))` 去空格、`regex` 压空白——等价于把"计数"改成"分词"，连续空格会塌缩。
  3. **用 `isspace(c)` 判空格**：`isspace` 还接受 `'\t'`、`'\n'`、`'\r'`、`'\v'`、`'\f'`，本题只应统计 ASCII 32；遇 CRLF 行尾就会多算。应写 `c == ' '`。
  4. **把行末换行也算进去**：例如用 `getchar()` 循环到 EOF 而不是到 `'\n'`，或 `cin.get()` 到 EOF 后把 `'\n'` 也计了数（若用 `c == '\n'` 判定则直接错）。本题语义是换行不属于 $s$。
  5. **固定缓冲区溢出**：`char buf[100000]` 或 `char buf[100]; cin.getline(buf, 100);` ——长度上限是 $100\,000$，缓冲区至少要 $100\,002$ 字节，否则越界是未定义行为（可能 RE 或静默出错）。用 `std::string` 可彻底规避。
  6. **使用 `gets`**：C++14 起已从标准移除，gnu++17 下不可用（或依赖非标准扩展），且不安全。
  7. **空输入处理错误**：例如 `do { ... } while (...)` 结构、或用 `while (!cin.eof())` 驱动读入，会在空输入或多读一轮时出现"非预期的一次空迭代"，导致行为依赖实现细节；本解法初始化 `s` 为空且只调用一次 `getline`，天然规避。
  8. **多处/多行读入**：本题只有一行，若写成 `while (getline(cin, line))` 累加，一旦判题文件多出空行就会算错；即便不会，也让语义变得不必要地脆弱。
  9. **输出格式违规**：输出 `ans = 5`、`5 5`、`5\n\n`、或多输出一行摘要，均不被接受；`std::count(s.begin(), s.end(), " ")` 这类把字符写成字符串字面量的笔误则是编译错误（应写 `' '`）。
  10. **混用 `sync_with_stdio(false)` 与 `scanf/getline`**：本题不需要 `scanf`，全部用 C++ 流即可；若混用需先关闭同步再统一用流，避免缓冲不一致。

  ## 7. 完整、可直接编译的 C++17 程序

  ```cpp
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      std::string s;                 // 初始化为空串：0 字节输入时仍为空串
      std::getline(std::cin, s);     // 读入整行，行末 '\n' 被取出并丢弃

      int cnt = 0;                   // |s| <= 100000，int 足够
      for (char c : s) {
          if (c == ' ') ++cnt;       // 只统计 ASCII 32，逐字符各计一次
      }

      std::cout << cnt << '\n';      // 仅一个整数 + 行末换行
      return 0;
  }
  ```

  编译：`g++ -std=gnu++17 -O2 -o main main.cpp`。

  ## 8. 假设、无法证明之处与实现风险

  本解法仅依据给定题面推导，未参考任何外部材料。明确列出的假设，全部直接来自题面的输入/数据范围条款：

  - **假设输入恰好只有一行**（题面明示）。若判题文件违反此约定、在第一行之后还有内容，程序只读第一行——仍符合题意，因为题意本身就说"除这一行之外没有其他内容"。
  - **假设行终止符是 `'\n'` 或文件直接结束**。若实际是 CRLF，`'\r'` 会留在 `s` 末尾；它不等于 `' '`，故计数不受影响（见用例 14）。若使用 `isspace` 就会出错，本解法不会。
  - **假设 `int`（至少 32 位）足以容纳答案**：答案 $\le 10^5$，成立。
  - **无法证明的部分**：唯一无法从题面内部证明的是判题机实际文件内容与题面一致；这一条对任何解法都同样成立，且不属于本程序的实现缺陷。

  实现风险：无实质风险。仅有一处可提及的细节——不检查 `getline` 的返回值是有意为之：返回值失败的两条路径（sentry 直接失败 / 提取到 EOF）都使 `s` 为空串，对应正确答案 `0`，因此无需分支处理。

  除上述对题面约定的依赖外，**无**。
