• ## 1. 任务与输入输出（复述）

  **任务**：给定一个只含十进制数字字符的非空字符串 `s`，把每个字符换成它代表的数值（`'0'`→0，`'1'`→1，……，`'9'`→9），求所有这些数值的和并输出。注意：整个串不能当作一个整数来处理，因为它的长度可达 100000 位，任何内置整数类型都存不下；这里只关心“每一位的值相加”的结果。

  **输入格式**：输入只有一行，是一个长度为 `n` 的字符串 `s`，只由 `'0'`–`'9'` 组成，不含空格或其他任何字符；允许前导零（例如 `000123` 是合法输入）。除此之外输入中没有别的内容。

  **输出格式**：输出一个十进制整数，等于 `s` 中所有数字字符对应数值之和。答案唯一，不能输出任何多余文本、多个整数或空输出。

  **约束**：
  - `1 <= |s| <= 100000`，`s` 非空；
  - `s[i] ∈ {'0',…,'9'}`，无空白、无其他字符；
  - 答案上界 `9 × 100000 = 900000`；
  - 资源限制：时间 1000 ms，内存 256 MiB，语言标准 gnu++17，仅标准库；
  - 样例：`12345` → `15`；`10203` → `6`（中间的 0 必须照常读入并参与累加，只是贡献为 0，不能因此提前结束）。

  ## 2. 算法

  1. 用**字符串**方式读入整行数字串（`std::cin >> s`，因为题面保证无空格，且这样能自动跳过行尾的 `\r`、`\n`）。
  2. 设累加器 `sum = 0`。
  3. 从左到右遍历 `s` 的每一个字符 `c`，执行 `sum += c - '0'`。
  4. 遍历结束后输出 `sum`。

  核心依据：C++ 标准保证基本执行字符集中 `'0'`–`'9'` 的编码是连续的，因此 `c - '0'` 恰好等于字符 `c` 的数值。

  ## 3. 正确性证明

  记 `n = |s|`，记 `val(c) = c - '0'`；因为 `'0'`–`'9'` 编码连续且 `c` 必为数字字符，所以 `val(c)` 正好是 `c` 所代表的数值，且 `0 <= val(c) <= 9`。

  记 `S_k = Σ_{j=0}^{k-1} val(s[j])`（`S_0 = 0`），于是 `S_n` 就是题目要求的答案。

  **循环不变式**：在处理完前 `i` 个字符后，`sum = S_i`。

  - **初始（i = 0）**：尚未处理任何字符，`sum = 0 = S_0`，成立。
  - **保持**：设第 `i` 次迭代（0 起始）开始时 `sum = S_i`。该次迭代读取 `s[i]`（因 `i < n`，下标合法），执行 `sum ← sum + val(s[i]) = S_i + val(s[i]) = S_{i+1}`。迭代结束时不变式对 `i+1` 成立。
  - **终止**：循环恰好执行 `n` 次后结束，此时 `i = n`，由不变式得 `sum = S_n`，即全部数字字符数值之和。
  - **输出**：程序把 `S_n` 以十进制写出，且只写出这一个数，满足 Judge 语义。

  **无溢出**：每次 `val(c) ≤ 9`，共 `n ≤ 100000` 项，故 `S_n ≤ 900000 < 2^31 - 1`，即使使用 `int` 也不会溢出；使用 `long long` 只带来额外余量，不改变结果。

  **完备性**：循环对每个下标恰好访问一次，包含所有 `'0'`（它们贡献 0 但不会被跳过或触发提前终止），因此不存在漏加或多加。

  ## 4. 复杂度

  - **时间**：`O(n)`，每个字符一次减法、一次加法；`n ≤ 100000`，远低于 1000 ms 限制。
  - **额外空间**：`O(1)`（不计输入串本身的 `O(n)` 存储）。输入的 `std::string` 约占 100 KB 量级，远低于 256 MiB。

  ## 5. 边界与高风险用例

  | 用例 | 期望输出 | 风险点 |
  |---|---|---|
  | `0` | `0` | 长度为 1，且是零 |
  | `9` | `9` | 长度为 1 的最大数字 |
  | `000000` | `0` | 全 0，必须全部读完，结果为 0 而非崩溃/空输出 |
  | `000123` | `6` | 前导零不得被当作“八进制/无效数字” |
  | `10203` | `6` | 内部含 0，不得 break/continue 错位 |
  | `100000` | `1` | 内部连续多个 0 |
  | `9`×100000 | `900000` | 答案最大值，恰好等于题面上界 |
  | `0` + `9`×99999 | `899991` | 前导零 + 接近最大值 |
  | 任意 100000 位随机串 | 见计算 | 最长串，验证不超时、不越界 |
  | 每位都是 5、长度 100000 | `500000` | 中等量级，验证累加不溢出 |

  额外提示：**绝不要**用 `long long`/`int` 直接 `cin >> x` 读入，100000 位数必然溢出（对 `long long` 是未定义/截断行为）；也不要因读到 `'0'` 就提前结束或跳过。

  ## 6. C++17 程序

  ```cpp
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      std::string s;
      if (!(std::cin >> s)) return 0;   // 题面保证输入非空，这里仅作防御

      long long sum = 0;
      for (std::string::size_type i = 0; i < s.size(); ++i) {
          sum += s[i] - '0';
      }

      std::cout << sum << '\n';
      return 0;
  }
  ```

  ## 7. 假设、无法证明之处与实现风险

  - **假设**：输入确实只有一行数字串（题面已保证非空、无空格），因此用 `cin >> s` 读取一个 token 就等价于读完整行。
  - **相对不确定点**：题面说“仅写入一个十进制整数”。本题解在整数后输出一个换行符 `\n`，这是竞赛输出的通行惯例，绝大多数 Judge 会忽略行尾空白；若某 Judge 采用逐字节严格比对且标准答案文件不带换行，则理论上会不一致（这是格式约定问题，不是算法问题）。
  - **实现风险（已规避）**：若改用 `getline(cin, s)` 且输入文件为 CRLF 行尾，`'\r'` 会残留在串尾，`'\r' - '0' = -35` 会污染答案；本实现用 `cin >> s`（`'\r'` 属于空白，会被截断）避免了该问题。若自行实现读取，需同样注意 `\r`、`\n` 的过滤。
  - **超出题面范围**：空输入时程序不输出任何内容，这违反了“必须输出一个整数”；但题面明确保证 `|s| >= 1`，该分支不可达。

  其余部分（`c - '0'` 的可移植性、答案不溢出、复杂度）均有标准与计算支撑，**无其他无法证明之处**。
