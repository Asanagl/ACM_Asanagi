• # 1. 任务与约束的独立复述

  **任务**：给定非空字符串 $s$（只含小写字母 `a`–`z`）和两个小写字母 $x,y$，把 $s$ 中**所有**等于 $x$ 的字符替换为 $y$，其他字符原样保留，输出长度与位置都不变的替换结果。

  形式化：设 $s=s_0s_1\cdots s_{n-1}$，输出 $t$ 满足
  $$t_i=\begin{cases}y,& s_i=x\\ s_i,& s_i\ne x\end{cases}\qquad (0\le i<n)$$

  **约束**：
  - $1\le n=|s|\le 10^5$，$s$ 的每个字符都在 `a`–`z` 内；
  - $x,y$ 各为单个小写字母，**允许** $x=y$；
  - 输入恰好两行：第一行 $s$（无空格），第二行 `x y`（单个空格）；
  - 只有一组测试数据；时间 1000 ms，空间 256 MiB。

  **输出与判题**：恰好一行结果字符串，接着可接一个行结束符（LF 或 CRLF）。Checker 与官方答案**逐字符精确比较**，拒绝空输出、多余 token、任何多余非空内容。因此不能输出长度、提示语、前后空格，也不能把答案拆成多行。

  **两个退化情形必须正确处理**：
  - $x=y$：任何字符都没被改变，输出须与 $s$ 完全相同；
  - $s$ 中不含 $x$：什么都不改，输出须与 $s$ 完全相同（注意仍要把整串输出，不能输出空）。

  # 2. 算法

  单次线性扫描 + 原地改写：

  1. 读入 $s$（第一行，无空格，用格式化读入即可）；
  2. 读入 $x$、$y$；
  3. 令 $i$ 从 $0$ 到 $n-1$：若 $s_i=x$ 则令 $s_i=y$，否则不动；
  4. 输出 $s$ 并换行。

  不需要 `find`、不需要构造新串、不需要特殊判断 $x=y$ 或"不存在 $x$"——这两种情形在逐字符判定下自动成立。

  # 3. 逐步正确性证明

  **循环不变式**：在第 $k$ 轮循环开始前（$0\le k\le n$），$s_0\cdots s_{k-1}$ 已等于目标输出 $t_0\cdots t_{k-1}$，且 $s_k\cdots s_{n-1}$ 尚未被处理、仍是原始输入的后缀。

  - **初始（$k=0$）**：前缀为空，整个串是原始输入，成立。
  - **保持**：第 $k$ 轮检查 $s_k$。若 $s_k=x$，赋 $s_k\leftarrow y$，于是该位等于 $t_k=y$；若 $s_k\ne x$，不改动，该位仍为原字符，等于 $t_k=s_k$。两种情况都有 $s_k=t_k$，前缀扩展到 $k+1$ 位，后缀缩为 $k+1$ 起，不变式在 $k+1$ 成立。
  - **终止（$k=n$）**：前缀覆盖整串，即 $s=t$，输出正是要求的字符串。

  **终止性**：$k$ 从 $0$ 严格递增至 $n$，循环恰好执行 $n$ 次，必然结束。

  **两个退化情形**：若 $x=y$，赋值 $s_i\leftarrow y$ 写回的是同一个值，输出恒等于输入；若 $s$ 中无 $x$，条件从不成立，输出恒等于输入。二者都符合题面要求。

  **与 Judge 一致性**：题面规定答案唯一，$t$ 由 $s,x,y$ 唯一确定。程序输出为 $t$ 加上一个 `'\n'`，不含其他字符，故严格满足"恰好一行 + 允许的行结束符"，逐字符比较必然通过。

  # 4. 复杂度

  - **时间**：读入 $O(n)$，扫描 $O(n)$，输出 $O(n)$，总计 $O(n)$。$n\le 10^5$，实际指令量约 $10^5$ 量级，远低于 1000 ms。
  - **空间**：$s$ 占 $O(n)$ 字节（$\le 100$ KB），其余为 $O(1)$ 变量。总计 $O(n)$，远低于 256 MiB。

  # 5. 边界条件、实现风险、高风险用例

  **必须成立的边界**：
  1. $n=1$ 且该字符就是 $x$；
  2. $x=y$（整串不变）；
  3. $s$ 中不含 $x$（整串不变，仍须输出整串）；
  4. $s$ 全为 $x$（整串变成 $y$ 的重复）；
  5. $s$ 长度取到 $10^5$（缓冲区/性能）；
  6. 输入行尾为 CRLF 或无结尾换行（不能把 `'\r'` 读进 $s$ 带出来）。

  **实现风险点**：
  - **用 `getline` 读 $s$ 时把 `'\r'` 读进来**：若测试数据以 CRLF 存盘而在不做文本转换的环境下判题，`getline` 得到的 $s$ 末尾会多一个 `'\r'`，输出随之多一个 `'\r'`，逐字符比较直接失败。用 `cin >> s` 可规避——`'\r'` 属于空白字符，会被当作分隔符跳过。
  - **定长 `char` 数组开小**：用 `scanf("%s", buf)` 时若 `buf` 开成 100000，长度 $10^5$ 的串再加上 `'\0'` 会越界写，属未定义行为，可能在本机"看起来对"、在判题机上崩溃。
  - **多余输出**：任何"结果是："、长度数字、末尾空格、额外的空行，都会被"恰好一行"的语义判错。
  - **未初始化/读入失败**：若第二行解析失败，`x,y` 是未定义值（本程序对 `x,y` 做了默认初始化以兜底）。
  - **UTF-8 BOM**：若数据文件带 BOM，BOM 字节会被当作 $s$ 的首字符，导致比较失配（见第 7 节，程序里做了无害的防御性剥离）。

  **我认为高风险的用例**（自测时优先跑）：
  - `s` = `a` 重复 $10^5$ 次，第二行 `a b`（同时压性能和"全部替换"）；
  - `s` = `a`，第二行 `a a`（$n=1$ 且 $x=y$ 的双退化）；
  - `s` = `zzz`，第二行 `a b`（$x$ 不存在，输出必须原样等于输入）；
  - `s` = `banana`，第二行 `a o`（对照样例，暴露"只换第一个"）；
  - 以上任一用例以 **CRLF** 行尾、且**末行不带换行符**保存各跑一次（暴露 `getline` 残留 `'\r'` 与读入问题）。

  # 6. 常见错误分三层

  **思路层**
  - *只替换第一处出现*：写 `s[s.find(x)] = y;` 或 `s.replace(s.find(x),1,1,y);`。
    **稳定暴露的输入特征**：$x$ 出现至少 2 次，如 `banana` / `a o`，正确答案 `bonono`，错解给 `bonana`。
  - *误以为 $x=y$ 需要"删除"或输出空串*：把"替换成自己"当成无操作之外的语义，如 `if (x==y) return 0;`。
    **稳定暴露的输入特征**：样例 2 `abacaba` / `a a`，正确输出是整串，错解输出空行或什么都不输出。
  - *用 `find` 循环但搜索位置不前进*：`while ((p=s.find(x))!=npos) s[p]=y;` —— $x\ne y$ 时第 1 次改完 $s[p]$ 就不再是 $x$ 但仍有别的 $x$，看似能走；一旦 $x=y$，`find` 永远找得到，**死循环**且无输出。
    **稳定暴露的输入特征**：`aaa` / `a a`。

  **复杂度层**
  - *每次替换后都从头 `find`*：`p=0; while((p=s.find(x,p))!=npos){ s[p]=y; p=0; }`，最坏 $O(n^2)$。
    **稳定暴露的输入特征**：$s$ 为 $10^5$ 个 `a`，第二行 `a b`（约 $10^{10}$ 次字符比较，必然超 1000 ms）。
  - *逐字符拼接构造答案* `ans = ans + c;`（或用 `substr` 拼接分片），每次复制旧内容，同样 $O(n^2)$。
    **稳定暴露的输入特征**：同上，长度取满的用例；小数据（如 $n\le 1000$）上不会暴露，所以必须用 $10^5$ 的满长度串测。
  - *边扫描边用 `erase/insert` 维持位置*：长度不变时虽不致命，但每次搬移是 $O(n)$，累计 $O(n^2)$。
    **稳定暴露的输入特征**：满长度串 + $x$ 大量出现。

  **实现层**
  - *`getline` 残留 `'\r'`（CRLF 输入）*：输出末尾多一个控制字符。
    **稳定暴露的输入特征**：把样例文件以 CRLF 保存后判题（逐字符比较在最后一两位失配）。
  - *`scanf("%s", buf)` 的缓冲区开成正好 $10^5$*：末尾 `'\0'` 越界写。
    **稳定暴露的输入特征**：$s$ 长度恰为 $10^5$（用 `char buf[100000]` 时越界）；长度 99999 时反而"正常"。
  - *输出格式违规*：`printf("%s", s);` 后又 `printf("\n")` 再打印一行调试信息，或 `cout << s.size() << "\n" << s << "\n";`。
    **稳定暴露的输入特征**：任意用例（多一行就足以被"恰好一行"拒绝）。
  - *把 $x$ 与下标混淆*：`if (i == x) s[i] = y;`（`char` 与 `int` 隐式互转，能编过但语义全错）。
    **稳定暴露的输入特征**：小写字母 ASCII 码与下标碰撞几乎不发生，实际表现为"几乎不替换"，用 `banana` / `a o` 即可看出。
  - *循环边界写成 `i <= s.size()`* 并配合 `s[i]` 写入：越界写 `'\0'` 位置（少数实现下会截断/崩溃）。
    **稳定暴露的输入特征**：满长度串 + $x$ 出现在末尾，如 `s` 以 `a` 结尾且 `x=a`。

  # 7. 假设与无法证明之处

  - 假设输入严格符合题面：恰好两行，第二行确实是一个小写字母、一个空格、一个字母。若第二行有多余空白，`cin >> x >> y` 仍能正确取到两个字符，属安全。
  - 假设首行不以空行开头、$s$ 非空（题面保证）。若首行为空，`cin >> s` 会把第二行的 $x$ 当成 $s$ —— 该情形不在题面范围内，无法也不需处理。
  - 假设数据文件不带 UTF-8 BOM。这是唯一我无法从题面证明的隐含前提（题面未提及编码/BOM）。为此程序中加了三字节 BOM 的无害剥离：合法 $s$ 不可能以 `EF BB BF` 开头，故该分支在正常数据上恒不触发，也不会引入错误。
  - 假设判题机不会对末尾缺失换行报错。程序仍然显式输出 `'\n'`，两种约定下都安全。
  - 其余（答案唯一性、$x=y$、$x$ 不存在的语义）均由题面直接给出，已在上文证明，无未证部分。

  # 8. 完整 C++17 程序

  ```cpp
  #include <bits/stdc++.h>
  using namespace std;

  int main() {
      ios::sync_with_stdio(false);
      cin.tie(nullptr);

      string s;
      if (!(cin >> s)) return 0;

      if (s.size() >= 3 &&
          (unsigned char)s[0] == 0xEF &&
          (unsigned char)s[1] == 0xBB &&
          (unsigned char)s[2] == 0xBF) {
          s.erase(0, 3);
      }

      char x = 'a', y = 'a';
      if (!(cin >> x >> y)) return 0;

      for (char &c : s)
          if (c == x) c = y;

      cout << s << '\n';
      return 0;
  }
  ```

  要点：`cin >> s` 天然跳过 CRLF 里的 `'\r'`，避免把控制字符带进答案；扫描是原地改写、$O(n)$ 时间 $O(1)$ 额外空间；输出恰好一行加一个 `'\n'`，无任何多余 token。
