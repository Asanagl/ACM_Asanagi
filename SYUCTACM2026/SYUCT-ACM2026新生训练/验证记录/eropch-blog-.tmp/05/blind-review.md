• ## 1. 题意复述

  选手需要处理**一组**输入：

  - 读入一个长度为 \(1\) 到 \(100000\) 的小写字母字符串 \(s\)。
  - 读入两个小写字母 \(x,y\)。
  - 将 \(s\) 中**每一个**等于 \(x\) 的字符改成 \(y\)，其他字符不变。
  - 输出替换后的字符串，且只能输出这一行结果。

  形式化地说，结果字符串 \(t\) 与 \(s\) 等长，并对每个位置 \(i\) 满足：

  \[
  t_i=
  \begin{cases}
  y,&s_i=x\\
  s_i,&s_i\ne x
  \end{cases}
  \]

  输出是唯一确定的。\(x=y\) 时字符串不变；没有 \(x\) 时也应原样输出。

  ## 2. 最合适的算法

  直接遍历字符串一次，原地修改：

  1. 读入 \(s,x,y\)。
  2. 从左到右检查 \(s\) 的每个字符。
  3. 如果当前字符等于 \(x\)，就将其赋值为 \(y\)。
  4. 遍历结束后输出整个字符串。

  这最适合本题，因为：

  - 每个位置的处理完全独立，不需要排序、查找表或其他数据结构。
  - 只需一次线性扫描，已经达到输出长度为 \(n\) 所必需的线性量级。
  - 原地修改不需要额外结果数组。
  - 不需要单独处理 \(x=y\)：此时赋值前后字符相同，自然得到正确答案。
  - 每个位置只访问一次，不会因修改后的字符而重复替换。

  ## 3. 正确性证明

  设输入字符串为 \(s_0s_1\cdots s_{n-1}\)，题目要求的目标字符串为 \(t\)，其中 \(t_i\) 按上面的分段公式定义。

  **第一步：读入正确。**

  输入格式保证 \(s\) 不含空白，第二行的 \(x,y\) 以空格分隔。使用格式化输入分别读入一个字符串和两个字符，即可得到这三个值。

  **第二步：建立循环不变量。**

  处理位置 \(i\) 之前，满足：

  - 位置 \(0\) 到 \(i-1\) 已经等于目标字符串 \(t\) 的对应字符；
  - 位置 \(i\) 到 \(n-1\) 仍保持输入时的原值。

  开始时 \(i=0\)，两个已处理区间和未修改区间的条件显然成立。

  **第三步：证明每次迭代保持不变量。**

  处理位置 \(i\) 时，该位置尚未被修改，因此当前字符就是原始的 \(s_i\)：

  - 若 \(s_i=x\)，算法将其改为 \(y\)，恰好等于 \(t_i\)。
  - 若 \(s_i\ne x\)，算法不作修改，当前字符仍为 \(s_i\)，也恰好等于 \(t_i\)。

  算法不访问、不修改其他位置，所以处理完位置 \(i\) 后，已处理区间扩展为 \(0\) 到 \(i\)，其余位置仍保持原值，不变量继续成立。

  **第四步：由终止状态得到完整正确性。**

  遍历结束时，所有位置都已处理。根据不变量，字符串的每个位置都等于 \(t\) 的对应位置，因此整个字符串就是题目要求的唯一结果。

  最后只输出该字符串和换行，不增加其他内容，符合判定规则。

  特别地：

  - \(x=y\) 时，匹配位置的赋值仍是同一个字符，所以所有字符不变。
  - 没有 \(x\) 时，所有位置都进入“不修改”分支。
  - \(x\) 位于首尾时，范围遍历同样覆盖这些位置。
  - \(|s|=1\) 时只需执行一次上述判断，结论不变。

  ## 4. 复杂度

  令 \(n=|s|\)。

  - **时间复杂度：\(O(n)\)**。读入、一次遍历和输出均为线性时间。
  - **额外空间复杂度：\(O(1)\)**。除输入字符串本身外，只使用两个字符及少量循环状态。
  - 若把存储输入字符串也计入，总空间占用为 **\(O(n)\)**。

  对于 \(n\le100000\)，线性算法在 1000ms / 256MiB 下没有压力。

  ## 5. 本题特有的常见错误

  ### 思路层面

  **只替换第一个或部分 \(x\)，误解“所有”。**

  检测输入：

  ```text
  banana
  a o
  ```

  正确输出是 `bonono`。只替换第一个 `a` 会得到 `bonana`。输入特征是同一个字符串中至少出现两次 \(x\)。

  **误以为要把 \(x,y\) 互换。**

  题目只要求把 \(x\) 改成 \(y\)，原本等于 \(y\) 的字符不应改变。

  检测输入：

  ```text
  ab
  a b
  ```

  正确输出是 `bb`；双向交换会得到 `ba`。输入特征是字符串中同时含有 \(x\) 和 \(y\)。

  ### 复杂度层面

  这一层面**适用，但不是本题固有的难点**。

  一种不合理的实现是：每次只替换一个 \(x\)，随后重新从头扫描整个字符串，或者为每次替换重新构造完整字符串。若大量位置都是 \(x\)，这可能退化为 \(O(n^2)\)。

  稳定放大该问题的输入特征：

  ```text
  s 为 100000 个 a
  第二行为 a o
  ```

  所有位置都需要替换，反复扫描或复制的总工作量可达到平方级，在 1000ms 限制下存在超时风险。如果还保存所有中间字符串，空间也可能失控；而原地单次遍历没有这些问题。

  ### 实现层面

  **循环下标漏掉首尾。**

  检测输入：

  ```text
  aba
  a o
  ```

  正确输出是 `obo`。这里 \(x\) 同时出现在首、尾，能暴露从 `1` 开始、使用错误的 `i < n-1` 等边界错误。

  **反复查找并替换，在 \(x=y\) 时没有进展。**

  如果实现不断查找下一个 \(x\)，再把它替换成相同的 \(y\)，却没有推进查找位置，就可能陷入死循环。

  检测输入：

  ```text
  a
  a a
  ```

  正确输出是 `a`，程序应立即结束。

  **读入或输出格式错误。**

  第二行包含空格，应分别读出两个字符，不能把整行当作一个字符；输出时也不能附加调试文字或空格。例如：

  ```text
  a
  a b
  ```

  输出必须恰好是结果行 `b`，不能是 `ans=b`、`b ` 或额外空行。

  ## 6. C++17 参考实现

  ```cpp
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      std::string s;
      char x, y;

      if (!(std::cin >> s >> x >> y)) {
          return 0;
      }

      for (char &c : s) {
          if (c == x) {
              c = y;
          }
      }

      std::cout << s << '\n';
      return 0;
  }
  ```

  ## 结论

  这份公开题面**不存在实质歧义或隐藏的判定陷阱**。替换对象、未匹配字符、\(x=y\)、无匹配、输入组数和唯一输出要求都已明确，样例及其解释也正确。

  两个都正确、合理的实现不会产生不同输出；可能的差异只来自上述误读或实现错误，而不是题面模糊。
