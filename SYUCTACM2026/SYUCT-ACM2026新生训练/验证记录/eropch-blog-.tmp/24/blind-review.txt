• ## 1. 任务复述

  给定一个 \(n\times m\) 的棋盘，每个格子只能染成 `A` 或 `B`，并满足：

  - 左右相邻的两个格子颜色不同；
  - 上下相邻的两个格子颜色不同；
  - \((1,1)\) 必须是 `A`。

  输入只有一组数据：两个整数 \(n,m\)，其中 \(1\le n,m\le1000\)。

  输出恰好 \(n\) 行，每行恰好 \(m\) 个字符，表示整个棋盘。不能输出其他字符，并且必须与唯一的合法方案完全一致。

  ## 2. 算法思路

  按照题面的 1 开始编号，格子 \((i,j)\) 的颜色由 \(i+j\) 的奇偶性决定：

  \[
  color(i,j)=
  \begin{cases}
  \text{A}, & i+j\text{ 为偶数},\\
  \text{B}, & i+j\text{ 为奇数}.
  \end{cases}
  \]

  因此，第一行是 `ABAB...`，第二行是 `BABA...`，之后逐行交替。

  逐行构造一个长度为 \(m\) 的字符串并输出即可，不需要保存整个棋盘。

  ## 3. 正确性证明

  ### 构造满足左上角要求

  左上角为 \((1,1)\)，此时：

  \[
  i+j=1+1=2
  \]

  是偶数，所以构造出的颜色为 `A`。

  ### 构造满足左右相邻颜色不同

  考虑任意左右相邻格子 \((i,j)\) 和 \((i,j+1)\)。

  它们的行列编号之和分别为：

  \[
  i+j,\qquad i+j+1
  \]

  二者相差 1，奇偶性必然不同。因此一个被染为 `A`，另一个被染为 `B`，颜色不同。

  ### 构造满足上下相邻颜色不同

  考虑任意上下相邻格子 \((i,j)\) 和 \((i+1,j)\)。

  它们的行列编号之和分别为：

  \[
  i+j,\qquad i+j+1
  \]

  同样相差 1，奇偶性不同，所以颜色必然不同。

  ### 输出格式正确

  程序外层循环执行 \(n\) 次，每次输出一行；内层循环为每行填入 \(m\) 个字符，且每个字符只能是 `A` 或 `B`。因此输出恰好是 \(n\) 行、每行 \(m\) 个字符。

  ### 合法方案唯一

  任意合法方案中，\((1,1)\) 已被固定为 `A`。

  对于任意格子 \((i,j)\)，可以从 \((1,1)\) 先向右走到 \((1,j)\)，再向下走到 \((i,j)\)。这条路径共经过：

  \[
  (j-1)+(i-1)=i+j-2
  \]

  条相邻边。

  每经过一条边，由于相邻格子颜色不同，下一格的颜色都被上一格唯一确定。因此，从固定的 `A` 出发，沿这条路径逐格推导，\((i,j)\) 的颜色唯一确定。

  路径每前进一步，\(i+j\) 增加 1，所以颜色也正好按照 \(i+j\) 的奇偶性交替，与我的构造一致。

  因此，任何合法方案都必须等于该构造；结合前面已经证明构造合法，可知合法方案恰好只有一个。

  ## 4. 复杂度分析

  - **时间复杂度：** \(\Theta(nm)\)。每个格子恰好生成并输出一次；由于输出本身就有 \(nm\) 个字符，该复杂度已达到渐进下界。
  - **额外空间复杂度：** \(\Theta(m)\)。只保存当前行，不保存整个棋盘。
  - **输出总量：** \(\Theta(nm)\) 个字符。

  ## 5. 边界情况

  - **\(n=1,\ m>1\)：** 只有一行，输出 `ABAB...`。不存在上下相邻格，只需保证左右交替。
  - **\(m=1,\ n>1\)：** 只有一列，依次输出 `A`、`B`、`A`……。不存在左右相邻格。
  - **\(n=m=1\)：** 输出单独一行 `A`，相邻格条件自然成立。
  - **\(n=m=1000\)：** 共输出 \(1{,}000{,}000\) 个棋盘字符。`i+j` 最大只有 2000，不会发生整数溢出；当前行仅含 1000 个字符，内存开销很小。
  - **行数或列数为偶数：** 不需要额外处理，奇偶公式会自动决定每行起点和终点，不依赖最后一列或最后一行的颜色。

  ## 6. C++17 实现

  ```cpp
  #include <iostream>
  #include <string>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      int n, m;
      if (!(std::cin >> n >> m)) {
          return 0;
      }

      for (int i = 1; i <= n; ++i) {
          std::string row(m, 'A');
          for (int j = 1; j <= m; ++j) {
              row[j - 1] = ((i + j) % 2 == 0) ? 'A' : 'B';
          }
          std::cout << row << '\n';
      }

      return 0;
  }
  ```

  对于输入 `3 4`，程序输出严格为：

  ```text
  ABAB
  BABA
  ABAB
  ```

  ## 7. 隐含假设与易错点

  除了题面保证的合法输入外，不依赖其他隐藏条件。实现按常规竞赛输入输出约定处理：只有一组 \(n,m\)，输入中的空白字符由 `>>` 自动跳过，每行末尾输出换行，不输出多余空格或提示文字。

  最容易出错的地方是：

  - 混用 1 开始的棋盘编号和 0 开始的字符串下标。这里计算颜色时使用 \(i,j\)，写入字符串时才使用 `j-1`。
  - 把奇偶规则写反，导致左上角变成 `B`。
  - 每一行都输出相同字符串，没有让相邻行交替。
  - 输出多余空格、额外行或调试信息，导致格式或逐字符比对失败。
  - 一次性保存整个棋盘，虽然在本题范围内也可行，但没有必要；逐行输出更节省内存。
