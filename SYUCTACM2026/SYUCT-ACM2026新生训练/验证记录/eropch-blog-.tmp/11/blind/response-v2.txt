• ## 1. 任务、输入格式、输出格式与全部约束（复述）

  **任务**：给定一个 $n$ 行 $m$ 列的整数矩阵，把它“原样”抄写一遍输出——第 $i$ 行第 $j$ 个输出整数必须等于输入的 $a_{i,j}$，位置、数值、正负号都不变。本题输出唯一，不接受任何别的构造。

  **输入格式**：第一行两个整数 $n,m$。随后 $n$ 行，每行 $m$ 个整数，即 $a_{i,1}\dots a_{i,m}$。同一行内相邻整数恰好一个空格，行末无空格，最后一行末尾有换行符，没有空行或额外内容。

  **输出格式**：只输出 $n$ 行，每行 $m$ 个整数（**不**输出第一行的 $n,m$）。行内相邻整数恰好一个空格，行首行尾无空格，每行（含最后一行）以换行符结束，不得有任何其他内容。任何数值/顺序/个数/空格/换行偏差均为错误答案。

  **约束**：$1\le n\le 100$，$1\le m\le 100$，$-1000\le a_{i,j}\le 1000$，元素总数 $n\times m\le 10000$。时间 1000 ms，内存 256 MiB，语言标准 gnu++17。

  ## 2. 算法

  按输入顺序读出全部 $n m$ 个整数，并按 **行优先（第 1 行从左到右，再第 2 行……）** 的次序立即输出，用“行内除最后一个元素外都跟一个空格、每行最后一个元素后跟换行”的方式拼接。

  具体地，双重循环 $i=1..n$、$j=1..m$：读入一个整数 $a$，输出 $a$；若 $j<m$ 输出一个空格，否则输出换行。

  （也可以先把矩阵存进 `int a[100][100]` 再输出；本文采用流式版本，因为它额外空间为 $O(1)$，且行为完全由输入唯一确定。）

  ## 3. 正确性证明

  记第一行之后的输入整数序列为 $t_1,\dots,t_{nm}$。由输入格式，第 $k=(i-1)m+j$ 个整数恰好是 $a_{i,j}$，即 $t_{(i-1)m+j}=a_{i,j}$。

  **引理 1（读入对应）**：循环共执行 $nm$ 次，第 $(i,j)$ 次迭代用 `cin >> a` 读到的正是 $t_{(i-1)m+j}$。因为 `>>` 逐个跳过空白并读取下一个整数记号，按行优先顺序消耗记号，与循环的 $(i,j)$ 枚举顺序一致；输入保证记号总数恰为 $nm$ 且格式合法，所以不会多读也不会少读，且不会有溢出（$|a|\le1000<2^{31}$）。

  **引理 2（输出字节结构）**：设第 $(i,j)$ 次迭代输出的数值记为 $s_{(i-1)m+j}=a_{i,j}$。程序在每次迭代输出 $s_k$ 后，恰输出一个字节 $b_k$：$b_k=\texttt{' '}$ 当 $j<m$，$b_k=\texttt{'\backslash n'}$ 当 $j=m$。故整个输出流为
  $$S=s_1b_1s_2b_2\cdots s_{nm}b_{nm}.$$
  除此之外程序不向标准输出写任何字符（不输出 $n,m$）。

  **定理 1（每个元素输出且仅输出一次）**：映射 $(i,j)\mapsto k=(i-1)m+j$ 是从 $\{1..n\}\times\{1..m\}$ 到 $\{1..nm\}$ 的双射。程序对每个 $k$ 有且仅有一次迭代，输出且仅输出一个数值记号 $s_k$；而由引理 1，$s_k=a_{i,j}$ 其中 $(i,j)$ 是 $k$ 的原像。故 $nm$ 个元素全被输出，无一遗漏，也无一重复。

  **定理 2（位置不变）**：输出记号的下标顺序恰为 $k=1,2,\dots,nm$，即行优先顺序；故第 $k$ 个输出记号位于第 $\lceil k/m\rceil$ 行第 $((k-1)\bmod m)+1$ 列，与输入 $a_{i,j}$ 的行列位置一致；输出中不交换任何两个元素。

  **定理 3（数值与符号不变）**：`cout << a`（$a$ 为 `int`）输出 $a$ 的标准十进制表示：非负值无符号位、无前导零（$0$ 输出为单个 `0`），负值输出 `-` 加其绝对值，不带 `+`。该表示与输入中该整数的表示所承载的数值完全相同，故数值与正负号均不变。

  **定理 4（格式合法）**：
  - 换行符个数：$b_k=\texttt{'\backslash n'}$ 当且仅当 $m\mid k$，$1\le k\le nm$ 中共有 $n$ 个这样的 $k$，且都位于每 $m$ 个记号之后 ⇒ 输出恰为 $n$ 行，每行恰含 $m$ 个记号，最后一行也以换行结束。
  - 空格：每行内非末位记号后恰有一个空格，共 $m-1$ 个，全部位于相邻记号之间 ⇒ 行内相邻整数间恰好一个空格；行首记号之前是换行符（首行为流开头），行末记号之后是换行符而非空格 ⇒ 无行首、行尾空格。
  - 无其他输出 ⇒ 不输出 $n,m$，无多余文字或空行。

  **推论（输出唯一）**：$S$ 由引理 2 的形式与定理 2、3 的取值完全确定，仅依赖输入矩阵，故程序输出即题面要求的唯一输出。

  ## 4. 复杂度

  - 时间：$O(nm)$ 次读入 + $O(nm\log_{10}1000)=O(nm)$ 次写出，总计 $O(nm)\le 10^4$ 次记号操作，远低于 1000 ms。
  - 额外空间：$O(1)$（仅 `n, m, i, j, a` 几个整型变量；不存储矩阵）。若改为存储版本则为 $O(nm)$ 个整数 $\approx 40$ KB，同样远低于 256 MiB。

  ## 5. 边界情况与高风险用例

  | 用例 | 关注点 | 期望行为 |
  |---|---|---|
  | `1 1` / `5` | 最小规模 | 输出一行 `5` + 换行，无空格 |
  | `1 1` / `-1000` | 最小值、单元素 | 输出 `-1000`+换行，符号保留 |
  | `1 5` / `7 -3 0 42 -56`（样例 2） | 仅 1 行 | 一行 5 个数，行内 4 个空格，末尾仅换行 |
  | `4 1` / `3 -2 3 0`（样例 3） | 仅 1 列 | 每行一个数，**行内不得出现空格**（$j<m$ 恒假） |
  | `3 4`（样例 1） | 负数、0、重复（`0` 两次、`5` 两次、`8` 两次）、边界值 `±1000` | 完全原样，重复元素不得合并或去重 |
  | 全 `0` 矩阵 | `0` 必须输出为 `0`，不能是 `-0`、`0.0`、空 | 逐个 `0` |
  | 全 `1000` / 全 `-1000` | 上/下界、最大书写长度 | 位数完整，`-` 不丢 |
  | `100 100` 全 `-1000` | 最大规模、最大输出量（约 60 KB） | 10000 个记号、100 行，时间/内存充裕 |
  | 末行末元素为负数 | 末行换行 + 符号 | `... -7\n` |
  | `m=1, n=100` | 每行仅 1 个数 | 100 行，每行一个数，无空格、无空行 |
  | CRLF 输入 | `>>` 会跳过 `\r`，不受影响 | 正常 |

  高风险点集中在“行末/行尾空格”与“最后一行是否换行”，代码用 `j+1<m` 决定分隔符、`else` 分支写 `'\n'` 同时解决这两点。

  ## 6. 完整 C++17 程序

  ```cpp
  #include <iostream>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      int n, m;
      if (!(std::cin >> n >> m)) return 0;

      for (int i = 0; i < n; ++i) {
          for (int j = 0; j < m; ++j) {
              int a;
              std::cin >> a;
              std::cout << a;
              if (j + 1 < m) std::cout << ' ';
              else           std::cout << '\n';
          }
      }
      return 0;
  }
  ```

  编译：`g++ -std=gnu++17 -O2 -o main main.cpp`。

  ## 7. 假设、无法证明之处与实现风险

  **假设**：输入严格符合题面格式（仅含空白分隔的整数，共 $1+nm$ 个记号），且判题环境为标准非交互式、stdin/stdout 重定向/OJ 管道；输出平台使用 `\n` 作为换行（题面如此规定）。

  **无法证明之处**：无（上述 4 条定理在“输入合法”这一前提下闭合）。若输入本身违约（例如记号不足），流式写法可能产生部分输出——但题面保证输入合法，故不影响判题。

  **实现风险（低）**：
  - `ios::sync_with_stdio(false)` 与 `cin.tie(nullptr)` 仅影响性能与自动刷新，不影响最终字节序列；程序退出时 `cout` 会刷新，输出不会丢失。
  - 使用 `int` 无溢出风险（$|a_{i,j}|\le1000$）。
  - 若某判题器异常地要求 CRLF 行尾（题面明确要求换行符，常规判题按 LF 比较），则可能不符；这是环境层面的假设，与本算法正确性无关。
