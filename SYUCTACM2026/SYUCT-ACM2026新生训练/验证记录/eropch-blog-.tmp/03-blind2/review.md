## 主代理审查

盲审独立复述了任务、输入/输出格式、长度范围与字符集、大小写合并规则、`y/Y` 非元音、输出顺序与 Judge 的严格 EOF 语义，与冻结题面一致；无越界假设。

其算法为：逐字符扫描，先把 `A`–`Z` 用算术折叠为小写（`c - 'A' + 'a'`），再 `switch` 命中五个元音之一，否则忽略；用 64 KiB `fread` 分块读取，边读边统计，额外空间 O(1)。

正确性证明用「已处理前缀」上的循环不变式：
1. 基础：空前缀五个计数为 0；
2. 归纳：大小写折叠保持“是否等于某元音（任一大小写）”的判定不变，折叠后的字符至多命中一个 `case`，恰好给该元音加 1，其余不变；非元音不改任何计数；
3. 终止：`fread` 返回 0 时恰好处理完 n 个字符；
4. 输出：按 `a e i o u` 顺序打印五个整数，无额外 token。

该证明闭合，且明确论证了折叠不改变元音身份、`y/Y` 不命中、每个字符至多加一次。

复杂度：时间 Θ(n)（n ≤ 10^6 时百万次简单分支），额外空间 O(1)（5 个计数 + 固定缓冲区），含输入也不到 1 MB；1000 ms / 256 MiB 下余量充足，结论正确。

边界清单覆盖：无元音、全元音、大小写混合、`y/Y`、长度 1、长度 10^6 全 `a`（1000000 不溢出 int）、末尾无换行、`tolower` 负 `char` 的 UB 风险、输出格式。

主代理逐行审查其 C++17：
- 只用 `<cstddef>`、`<cstdio>`，`fread`/`printf` 均为标准接口；
- `char c = g_buf[k];` 后再比较，`c >= 'A'` 等比较对 ASCII 平台安全，无 `tolower` 调用；
- `switch` 的 5 个 `case` 互斥，`default: break;` 明确；
- `int cnt[5]` 上限 10^6，不溢出；
- 输出 `"%d %d %d %d %d\n"` 恰好五个整数，符合 checker 的严格 EOF。

未发现缺陷。与主解（`string` + `tolower(unsigned char)` + `vowels.find`）在实现路径上确实独立：一个流式 `fread` + 算术折叠 + `switch`，一个整串读入 + `tolower` + `string::find` 查表；两者对合法输入的语义一致。
