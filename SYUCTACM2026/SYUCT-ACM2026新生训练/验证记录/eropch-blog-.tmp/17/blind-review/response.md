• ## 1. 任务与完整约束

  给定一个 \(n\) 行 \(m\) 列的整数矩阵，需要将**每一行独立地左右逆序**，并满足：

  - 第 \(i\) 行由
    \[
    a_{i,1},a_{i,2},\ldots,a_{i,m}
    \]
    变为
    \[
    a_{i,m},a_{i,m-1},\ldots,a_{i,1}.
    \]
  - 行与行之间的先后顺序不变。
  - 不能把矩阵拼接成一维后整体逆序，也不能交换不同行。
  - 当 \(m=1\) 时，每行逆序后不变。
  - 当 \(m\) 为奇数时，每行正中间的元素位置不变。

  输入约束：

  - \(1\le n\le 100\)；
  - \(1\le m\le 100\)；
  - 每个元素都是整数，且 \(-1000\le a_{i,j}\le 1000\)；
  - 第一行输入 \(n,m\)，随后输入 \(n\) 行，每行 \(m\) 个整数。

  输出约束：

  - 输出 \(n\) 行，每行 \(m\) 个整数；
  - 同行整数用一个空格分隔；
  - 答案唯一，Judge 按整数序列逐项比较，空白仅用于分隔，因此必须保证输出的整数数量及顺序完全正确。

  资源限制为 **1000 ms、256 MiB**。

  ## 2. 算法与正确性证明

  ### 算法

  逐行处理，不需要保存整个矩阵：

  1. 读入 \(n,m\)。
  2. 对每一行：
     - 按原顺序读入该行的 \(m\) 个整数，存入数组 `row`；
     - 从下标 \(m-1\) 到 \(0\) 依次输出数组元素；
     - 输出换行。
  3. 重复直到处理完 \(n\) 行。

  ### 正确性证明

  采用数学下标从 \(1\) 开始、程序数组下标从 \(0\) 开始的记法。

  **第一步：读入后的数组内容正确。**

  对第 \(i\) 行，程序依次读入 \(m\) 个元素，因此读入完成后，对于任意 \(0\le j<m\)，有：

  \[
  \texttt{row}[j]=a_{i,j+1}.
  \]

  **第二步：单行的输出顺序符合要求。**

  程序按照 \(j=m-1,m-2,\ldots,0\) 的顺序输出，所以输出序列为：

  \[
  \texttt{row}[m-1],\texttt{row}[m-2],\ldots,\texttt{row}[0].
  \]

  代入第一步的结论，得到：

  \[
  a_{i,m},a_{i,m-1},\ldots,a_{i,1}.
  \]

  这正是第 \(i\) 行左右逆序后的结果。

  等价地，若输出的第 \(k\) 个元素记为 \(b_{i,k}\)，其中 \(1\le k\le m\)，则程序输出的是 `row[m-k]`，故：

  \[
  b_{i,k}=a_{i,m-k+1}.
  \]

  因此每个原元素 \(a_{i,j}\) 恰好出现在输出位置 \(k=m-j+1\)，不会遗漏或重复。

  **第三步：行顺序正确，且不存在跨行混合。**

  外层循环依次处理第 \(1,2,\ldots,n\) 行。每一行都被完整读入并立即完整输出，然后才读取下一行。因此：

  - 行的先后顺序保持不变；
  - 不会把矩阵整体逆序；
  - 不会交换行；
  - 不会将一行的元素输出到另一行。

  **第四步：输出数量及终止性正确。**

  每行恰好输出 \(m\) 个整数，共处理 \(n\) 行，所以总共恰好输出 \(nm\) 个整数。所有循环的迭代次数均有限，程序必然终止。

  综上，程序输出的整数数量、顺序以及每行内容均与题目要求完全一致，正确性得证。

  ## 3. 复杂度、边界与测试重点

  ### 复杂度

  - **时间复杂度：** \(O(nm)\)。每个元素只读入一次、输出一次。
  - **额外空间复杂度：** \(O(m)\)。只保存当前行，不保存整个矩阵。

  最多只有 \(100\times100=10000\) 个元素，当前行最多保存 \(100\) 个 `int`，资源消耗远低于题目限制。

  ### 边界条件

  - \(n=1\)：只处理一行。
  - \(m=1\)：逆序循环只输出一个元素，矩阵不变。
  - \(n=m=1\)：读入并输出同一个整数。
  - 奇数列：中间元素自然保持在中间，无需特判。
  - 偶数列：所有元素按逆序输出，无需特判。
  - 负数、零、重复元素：只改变位置，不改变元素值。
  - \(-1000\) 和 \(1000\)：均可由 `int` 正常表示。
  - 最大值规模 \(n=m=100\)：循环和存储均在限制内。

  ### 实现风险与重点测试

  主要实现风险：

  1. 错把整个矩阵当成一维序列整体逆序。
  2. 错把行顺序也逆序。
  3. 逆序遍历时使用无符号类型，并以 `j >= 0` 为条件，可能导致下标下溢或死循环。下面程序使用有符号 `int`，避免了这一问题。
  4. 输出时列数或顺序错误。程序每行固定输出 \(m\) 个整数，并且不输出多余行内尾随空格。

  建议重点测试：

  - 三个公开样例。
  - 单行：`n=1,m=4`。
  - 单列：`m=1`，确认不交换行。
  - 单个元素：`n=m=1`。
  - 奇数列与偶数列各一组。
  - 含负数、零和重复元素的行。
  - 能区分“逐行逆序”和“整体逆序”的测试，例如：
    ```text
    2 3
    1 2 3
    4 5 6
    ```
    应输出：
    ```text
    3 2 1
    6 5 4
    ```
  - \(100\times100\) 的最大规模矩阵，并包含 \(-1000\)、\(1000\)。

  ## 4. 完整 C++17 程序

  ```cpp
  #include <iostream>
  #include <vector>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      int n, m;
      std::cin >> n >> m;

      std::vector<int> row(m);

      for (int i = 0; i < n; ++i) {
          for (int j = 0; j < m; ++j) {
              std::cin >> row[j];
          }

          for (int j = m - 1; j >= 0; --j) {
              if (j != m - 1) {
                  std::cout << ' ';
              }
              std::cout << row[j];
          }
          std::cout << '\n';
      }

      return 0;
  }
  ```

  ## 5. 假设、无法证明之处与高风险点

  - 仅假设输入严格符合题面约束，并且评测环境支持标准 C++17；没有对输入合法性格式做额外防御，因为题目已经保证输入合法。
  - 在此前提下，算法正确性已经完整证明，**没有无法证明的部分**。
  - 没有算法或复杂度方面的高风险点。
  - 实现层面最需要注意的是“只逆序每一行、不逆序行顺序”，以及无符号逆序下标可能下溢；上述程序已分别通过逐行处理和使用有符号 `int` 下标规避。
