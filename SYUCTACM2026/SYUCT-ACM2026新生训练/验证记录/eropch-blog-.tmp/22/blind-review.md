  ## 1）任务与约束的独立复述

  **输入**
  - 第一行三个整数 `n m q`：`1 ≤ n,m ≤ 100`，`1 ≤ q ≤ 1000`。
  - 接下来 `n` 行、每行 `m` 个整数，第 `i` 行第 `j` 个数是 `a[i][j]`，`-10^9 ≤ a[i][j] ≤ 10^9`。
  - 接下来 `q` 行、每行四个整数 `r1 c1 r2 c2`，满足 `1 ≤ r1 ≤ r2 ≤ n`、`1 ≤ c1 ≤ c2 ≤ m`（询问保证非空）。

  **下标约定**：行、列下标均从 **1** 开始，且为**闭区间**。

  **输出**：恰好 `q` 行，第 `k` 行是一个整数，等于

  $$
  A_k=\sum_{i=r_1}^{r_2}\sum_{j=c_1}^{c_2} a_{i,j}
  $$

  包括四条边界元素；`r1=r2` 或 `c1=c2` 时同样成立（单行、单列、单格均合法）。

  **评测语义**：答案唯一（由输入唯一确定），因此只需逐行输出精确值；按顺序比较，任何位置不同即 WA，多输出 token 也 WA，token 间空白不计。故程序不得输出任何多余内容（无调试信息、无额外行），且必须是精确整数，不能用浮点。

  **规模提示（题面明示）**：单次答案绝对值可达 `10^13`，必须用 64 位整型；并且题面明确说“对每次询问直接枚举格子累加即可通过”，不强制用前缀和。

  ## 2）算法（从零推导）

  ### 观察

  若对每次询问直接枚举 `(r1..r2)×(c1..c2)` 的格子，最坏 `q·n·m = 1000×100×100 = 10^7` 次加法，完全可以接受。但更稳妥、也更标准的做法是**二维前缀和**：把“每次询问的矩形和”化为“四次前缀和的加减”，一次询问 O(1)。

  ### 前缀和的定义

  令（`n+1` 行 × `m+1` 列）

  $$
  P[i][j]=\sum_{x=1}^{i}\sum_{y=1}^{j}a_{x,y},\qquad 0\le i\le n,\ 0\le j\le m,
  $$

  并约定 `P[0][j] = P[i][0] = 0`（空矩形和为 0）。

  ### 构造（递推）

  按 `i` 从 1 到 `n`、`j` 从 1 到 `m` 顺序填写：

  $$
  P[i][j]=a_{i,j}+P[i-1][j]+P[i][j-1]-P[i-1][j-1]
  $$

  理由：矩形 `[1..i]×[1..j]` 的格子可以拆成“上面一块 `[1..i-1]×[1..j]`”∪“左边一块 `[1..i]×[1..j-1]`”∪“单格 `(i,j)`”，前两块在 `[1..i-1]×[1..j-1]` 上被重复计数一次，故减去。这就是容斥。

  ### 询问（容斥）

  $$
  A=P[r_2][c_2]-P[r_1-1][c_2]-P[r_2][c_1-1]+P[r_1-1][c_1-1]
  $$

  ### 流程

  1. 读 `n,m,q`；
  2. 逐行逐列读 `a[i][j]`（读入即用，不另存原矩阵），边读边按上式填 `P`；
  3. 对每次询问读四个整数，套用上面的四加减公式，`printf("%lld\n", A)` 输出。

  > 也可以完全不用前缀和、直接双重循环枚举格子求和（题面允许）；两种写法输出完全相同。下面给出的是前缀和版本，因为它的复杂度与 `q` 无关、且公式化后便于严格证明。

  ## 3）逐步正确性证明

  **引理 1（前缀不变式）**：按上述顺序填完后，对一切 `0≤i≤n, 0≤j≤m` 有 `P[i][j] = Σ_{x=1..i} Σ_{y=1..j} a[x][y]`（空范围取 0）。

  *证明*：对 `i+j` 归纳。`i=0` 或 `j=0` 时初始化即为 0，与定义一致。设 `i,j≥1` 且更小的 `i+j` 均成立。设
  `U = [1..i-1]×[1..j]`，`V = [1..i]×[1..j-1]`，`W = [1..i-1]×[1..j-1]`，`S = [1..i]×[1..j]`。
  显然 `U ∪ V ∪ {(i,j)} = S` 且三者互不相交；而 `U ∩ V = W`。于是

  $$
  \sum_S a=\sum_U a+\sum_V a+a_{i,j}=\big(\sum_U a+\sum_V a-\sum_W a\big)+a_{i,j},
  $$

  右边括号内正是 `P[i-1][j]+P[i][j-1]-P[i-1][j-1]`（由归纳假设），故递推式算出的值等于真实和。∎

  **引理 2（询问公式）**：对任意合法询问，四加减公式给出的值恰为 `A`。

  *证明*：考虑任意格子 `(i,j)`（`1≤i≤n, 1≤j≤m`）在公式右边被计入的系数：

  $$
  [i\le r_2][j\le c_2]-[i\le r_1-1][j\le c_2]-[i\le r_2][j\le c_1-1]+[i\le r_1-1][j\le c_1-1]
  =\big([i\le r_2]-[i\le r_1-1]\big)\big([j\le c_2]-[j\le c_1-1]\big).
  $$

  （这一步只是把四项按行条件、列条件分组提取公因子。）由于 `r1≤r2`，`[i≤r2]-[i≤r1-1] = 1` 当且仅当 `r1≤i≤r2`，否则为 0；列同理。故系数为 1 当且仅当 `(i,j)` 落在询问矩形内，否则为 0。又由引理 1，公式右边等于 `Σ_{i,j} 系数(i,j)·a[i][j]`，即恰好等于 `A`。∎

  **定理**：程序对第 `k` 次询问输出的整数等于题面定义的 `A_k`，且输出恰为 `q` 行、无多余 token。

  *证明*：由引理 1 保证 `P` 表正确（读入顺序与递推依赖的 `P[i-1][j]、P[i][j-1]、P[i-1][j-1]` 均已就绪，因为按行主序填写）；由引理 2 保证每行结果正确。题面保证每次询问满足 `1≤r1≤r2≤n`、`1≤c1≤c2≤m`，因此下标 `r1-1, c1-1 ∈ [0, n-1]×[0, m-1]`、`r2,c2 ∈ [1,n]×[1,m]`，所有访问都在 `P` 的合法范围内，不会越界。程序循环恰 `q` 次，每次用 `"%lld\n"` 输出一个整数，故输出恰好 `q` 个整数 token，与评测的按序比较语义一致；又因为答案唯一，正确输出即为唯一可接受的输出。∎

  ## 4）复杂度与资源

  - **时间**：读入并建表 O(nm)，每次询问 O(1)，共 **O(nm + q)**。代入上界 `10^4 + 10^3 = 1.1×10^4` 次基本运算，外加约 `1.1×10^4` 个整数的读写，量级在微秒到毫秒级，远低于 1000 ms。
    （即使改成题面允许的直接枚举，也是 `O(nmq) ≤ 10^7`，同样在 1000 ms 内。）
  - **额外空间**：只保留 `(n+1)×(m+1)` 个 `long long`，即 `101×101×8 ≈ 81.6 KB`（不加原矩阵）。远小于 256 MiB。
  - **溢出安全（关键）**：`|P[i][j]| ≤ n·m·10^9 = 10^13`；询问公式的中间量最坏量级约 `4×10^13`，均远小于 `long long` 上界 `≈9.22×10^18`，不会溢出。反之若用 `int`（上界 `2.1×10^9`）必然在样例第一问（`6×10^9`）就错。

  ## 5）边界条件、实现风险与高风险用例

  **必须覆盖的边界**
  1. 单格询问：`r1=r2, c1=c2` → 公式退化为 `P[r][c]-P[r-1][c]-P[r][c-1]+P[r-1][c-1]=a[r][c]`。
  2. 单行 `r1=r2`、单列 `c1=c2`（样例第 6、7 问即是）。
  3. 整矩阵询问（样例第 1 问）。
  4. 触碰边界的询问：`r1=1` 或 `c1=1`，此时用到 `P[0][*]`/`P[*][0]`，必须为 0（用 `n+1 × m+1` 的 1-indexed 表天然满足）。
  5. 全 0、全负、正负相消得到 0 或负值的答案（输出 `0` 或负数，不能规范化成别的形式）。
  6. 极值：`n=m=100` 且全为 `10^9` 时答案为 `10^13`；全为 `-10^9` 时为 `-10^13`。
  7. `q=1`、`n=m=1` 的最小规模。

  **实现风险清单**
  - `int` 存前缀或答案 → 溢出（最高危）。
  - 下标错位：把 `P` 建成 `n×m`、或忘记 `r1-1/c1-1` 的减一。
  - 用 `scanf("%d")` 读 `long long`（未定义行为）；这里矩阵元素用 `%lld`。
  - 输出多余内容（调试打印、`Case #x:`、多打的空行/提示语）→ 按题面判 WA。
  - 浮点/大整数替代 → 精度错误，绝不使用。
  - 把闭区间当半开区间，漏掉第 `r2` 行或第 `c2` 列。
  - 读入顺序错误（先读全部询问再建表，或建表时用到尚未读入的格子）。

  **自认为高风险的用例**
  - `1 1 2 / -1000000000 / 1 1 1 1 / 1 1 1 1` → 应输出两行 `-1000000000`（检验负值与单格）。
  - `100 100 1` 全 `10^9` 且询问 `1 1 100 100` → 应输出 `10000000000000`（检验 `long long` 与 `10^13` 量级）。
  - `100 100 1` 全 `-10^9`，同一询问 → 应输出 `-10000000000000`。
  - 交替正负、答案恰为 `0` 的构造（检查是否误用无符号或误判 `0`）。
  - 大量 `r1=1,c1=1` 与 `r2=n,c2=m` 混合的询问（检查边界 `P[0][*]`）。
  - 样例本身（我手工核对过 7 行输出全部吻合：`6000000000 / 2000000000 / 2000000000 / 1000000000 / 2000000000 / 1000000000 / 1000000000`）。

  **明确声明**：本回答未能编译或运行任何代码（禁止使用工具），上述样例吻合性为手工推演而非实测；若实际评测出现差异，应首先怀疑我的代码书写细节（如格式符、下标）而非算法结论。此外，我假设输入严格遵守题面格式与范围（无多余行、无 `n=0`、询问必非空），这来自题面，无法在无工具条件下验证。

  ## 6）完整 C++17 单文件程序

  ```cpp
  #include <cstdio>
  #include <vector>

  int main() {
      int n, m, q;
      if (std::scanf("%d %d %d", &n, &m, &q) != 3) return 0;

      // P[i][j] = 左上角 (1,1) 到 (i,j) 的闭矩形元素和，P[0][*] = P[*][0] = 0
      std::vector<std::vector<long long>> P(n + 1, std::vector<long long>(m + 1, 0));

      for (int i = 1; i <= n; ++i) {
          for (int j = 1; j <= m; ++j) {
              long long x;
              std::scanf("%lld", &x);
              P[i][j] = x + P[i - 1][j] + P[i][j - 1] - P[i - 1][j - 1];
          }
      }

      for (int k = 0; k < q; ++k) {
          int r1, c1, r2, c2;
          std::scanf("%d %d %d %d", &r1, &c1, &r2, &c2);
          long long ans = P[r2][c2] - P[r1 - 1][c2] - P[r2][c1 - 1] + P[r1 - 1][c1 - 1];
          std::printf("%lld\n", ans);
      }

      return 0;
  }
  ```

  要点回顾：`long long` 全程；1-indexed 的 `(n+1)×(m+1)` 前缀表消除边界特判；每问恰好一行输出、无任何多余 token；时间 `O(nm+q)`、空间约 82 KB，稳过 1000 ms / 256 MiB。
