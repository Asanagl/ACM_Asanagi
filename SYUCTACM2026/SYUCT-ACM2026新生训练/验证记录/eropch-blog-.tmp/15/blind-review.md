• ## 1. 独立复述任务

  题目给出一个 $n$ 行 $m$ 列的整数矩阵（$1\le n,m\le 200$，每个元素在 $[-10^9,10^9]$ 内，可以为负、可以为 0、可以重复）。要求输出一行三个整数：

  - 第一个：整个矩阵所有元素中的**最大值**本身（不是它的下标）；
  - 第二个、第三个：该最大值**第一次出现**的位置的行号和列号。

  “第一次出现”的规则是**行优先序**：把所有格子的位置按 (行号, 列号) 做字典序比较，先比行号（小者靠前），行号相同再比列号（小者靠前）。也就是说，从第 1 行开始逐行往下、每行内从左到右扫描，最先遇到最大值的那一格就是答案位置。由于行优先序是位置集合上的全序，“达到最大值的格子中行优先序最小者”是唯一确定的，因此答案三元组唯一。行号、列号均以 **1 为起始**。

  输入格式：第一行为 `n m`；随后 $n$ 行每行 $m$ 个用空格分隔的整数。输出恰好三个整数，空格分隔，行末换行，不得有任何多余内容（评测按 token 比对，多一个 token 即判错）。

  ## 2. 算法设计

  核心观察：题目要的位置定义本身就等于“按行优先序扫描时的第一个最大值”。因此**不需要先求最大值再回头找位置**，一次扫描即可同时确定值和位置。

  需要维护的量（只有 3 个，与矩阵规模无关）：

  - `best`：到目前为止扫描过的所有元素中的最大值；
  - `bi`、`bj`：在已扫描部分中，取到 `best` 的**行优先序最小**的那个位置。

  更新规则：对当前格子 $(i,j)$ 的值 $x$，**当且仅当 $x > best$（严格大于）**时执行 `best = x; bi = i; bj = j;`；若 $x \le best$ 则什么都不做。

  为什么必须是严格大于：当 $x = best$ 时，说明最大值此前已经出现过，而当前格子行优先序更靠后，不可能是“第一次出现”，所以不能覆盖。若写成 `>=`，就会把位置更新成最后一次出现的位置，正是本题最典型的错误。

  初始化：`best = LLONG_MIN`（不要取 0，因为最大值可能是负数），`bi = bj = 1`。由于所有元素 $\ge -10^9 >$ `LLONG_MIN`，第一个读到的格子必然触发更新，`bi,bj` 会被正确地置为 `1,1`。

  循环顺序：**外层枚举行 $i$ 从 1 到 $n$，内层枚举列 $j$ 从 1 到 $m$**。这个顺序恰好就是题目定义的行优先序，于是“第一个满足条件的格子”与“行优先序最小的位置”重合，正确性由扫描顺序直接保证。若把循环写反（外层列、内层行），遇到并列最大值时会得到“列优先序最小”的位置，例如最大值同时出现在 $(1,3)$ 与 $(2,1)$ 时会错答 $(2,1)$。

  另外采用**边读边扫**（不存矩阵），因为每个元素的处理只依赖当前最优值，不需要回看。

  ## 3. 逐步正确性证明

  记矩阵按行优先序展开的格子序列为 $p_1,p_2,\dots,p_{nm}$（$p_{(i-1)m+j}=(i,j)$，值记为 $v_k$）。算法在循环中依次处理 $p_1,p_2,\dots$，处理完 $p_t$ 后记状态为 $(\text{best}_t, \text{pos}_t)$。

  **不变量 $I(t)$**（对 $1\le t\le nm$）：处理完 $p_t$ 后，

  1. $\text{best}_t=\max\{v_1,\dots,v_t\}$；
  2. $\text{pos}_t$ 是集合 $S_t=\{p_k: 1\le k\le t,\ v_k=\text{best}_t\}$ 中行优先序最小的位置。

  **基础情形 $t=1$**：处理 $p_1=(1,1)$ 时，$v_1>\text{LLONG\_MIN}$ 必成立，故 $\text{best}_1=v_1$，$\text{pos}_1=(1,1)$。而 $S_1=\{p_1\}$，其最小元就是 $p_1$，$I(1)$ 成立。

  **归纳步**：设 $I(t)$ 成立，处理 $p_{t+1}$（值 $x=v_{t+1}$）。分两种情形：

  - 若 $x>\text{best}_t$：由归纳假设 $\text{best}_t$ 是前 $t$ 个元素的最大值，故 $x$ 严格大于它们全部，于是 $\text{best}_{t+1}=x=\max\{v_1,\dots,v_{t+1}\}$，且 $S_{t+1}=\{p_{t+1}\}$（因为前面没有任何元素等于 $x$），其最小元即 $p_{t+1}$，与算法赋值一致。
  - 若 $x\le \text{best}_t$：则 $\max\{v_1,\dots,v_{t+1}\}=\text{best}_t$，最大值数值不变；此时 $S_{t+1}=S_t\cup\{p_{t+1}\}$（当 $x=\text{best}_t$）或 $S_{t+1}=S_t$（当 $x<\text{best}_t$）。两种情况下 $p_{t+1}$ 都是序列中**最后**加入的位置，它在行优先序中严格大于 $S_t$ 的所有元素。因此 $S_{t+1}$ 的最小元仍为 $S_t$ 的最小元，即算法保留的 $\text{pos}_t$。

  两种情形都与算法的赋值行为一致，故 $I(t+1)$ 成立。由归纳法，$I(t)$ 对所有 $t$ 成立。

  **终止**：循环处理完全部 $nm$ 个元素即 $t=nm$，由 $I(nm)$ 得 $\text{best}=\max$ 全体元素，$\text{pos}$ 是所有达到该最大值的格子中行优先序最小者，正是题目要求的“第一次出现”的位置；输出的 $(\text{best},\text{bi},\text{bj})$ 与题目定义完全一致。

  **唯一性**：行优先序是有限位置集合上的全序（任意两个不同位置可比且反对称），故非空集合 $S_{nm}$ 的最小元唯一存在，算法输出与题面要求的唯一答案相同，不存在歧义。

  ## 4. 时间与空间复杂度

  - 时间：每个格子做一次读入、一次比较、最多一次常数次赋值，总计 $O(nm)$，最坏 $200\times200=4\times10^4$ 次比较。常数极小，$10^3$ ms 时限下余量极大（实际运行在毫秒级）。
  - 空间：除若干标量（`n,m,i,j,best,bi,bj`）外不使用任何与输入规模相关的存储，额外空间 $O(1)$。即使把矩阵完整存下也只有 $4\times10^4\times4$ B $\approx160$ KB，远小于 256 MiB；本解连这点也不占。

  结论：**满足** 1000 ms / 256 MiB。

  ## 5. 边界条件与常见易错点

  - **重复最大值**：必须用严格大于 `x > best` 判定。用 `>=` 会得到最后一次出现的位置。例如
    ```
    2 3
    1 2 7
    7 0 0
    ```
    最大值 7 出现在 $(1,3)$ 与 $(2,1)$，虽然 $(2,1)$ 列号更小，但行号更大，行优先序靠后，正确输出是 `7 1 3`。
  - **全负**：`best` 初值绝不能取 0。用 `LLONG_MIN`（或直接把第一个元素作为初值）即可。样例 2、3 就是这一类。
  - **$1\times1$**：循环只走一格，输出该元素本身与 `1 1`。样例 3 即此情形。
  - **单行（$n=1$）**：行号恒为 1，退化为行内从左到右找第一个最大值。
  - **单列（$m=1$）**：列号恒为 1，退化为从上到下找第一个最大值。
  - **最大值在最后一行最后一列**：只有该处更新，输出 $(n,m)$，不要因为“位置靠后”而怀疑；只要它严格大于此前所有值就应当更新。
  - **最大值在首行首列**：第一个元素即触发更新，之后所有元素都不严格大于它，位置保持 `(1,1)`，正确。
  - **整矩阵所有元素相等**：任何位置都不满足严格大于，答案必为 `值 1 1`（包括全为负数、全为 0 的情形）。
  - **输出格式**：只输出三个数加换行，不要打印“最大值是”之类提示、不要多打空行或多打行列以外的数（评测按 token 严格比对，多余 token 判错）；行末不要多余空格。
  - **数据类型**：坐标最大 200，`int` 足够；数值在 $\pm10^9$ 内 `int` 也够，但用 `long long` 承接（配合 `LLONG_MIN` 初值和 `%lld`）更稳妥、零风险。
  - **读入效率**：`scanf`/关闭同步的 `cin` 均可，$4\times10^4$ 个整数不会成为瓶颈。

  ## 6. 我认为高风险的用例

  1. **并列最大值分处不同行且列号顺序“诱导错误”**：如上面的 `7` 在 $(1,3)$ 与 $(2,1)$，用来抓住“用列号优先”或“用 `>=` 覆盖”的错误。
  2. **同一行内并列最大值**：
     ```
     1 5
     9 1 9 9 9
     ```
     正确 `9 1 1`（若写成 `>=` 会输出 `9 1 5`）。
  3. **全等矩阵（含全负）**：
     ```
     3 3
     -7 -7 -7
     -7 -7 -7
     -7 -7 -7
     ```
     正确 `-7 1 1`；同时检验“初值取 0”的错误（会输出 0 之类的废话或永远不更新）。
  4. **最大值只在最后一行最后一列**：
     ```
     2 2
     1 2
     3 4
     ```
     正确 `4 2 2`，检验是否误以为必须“提前”更新。
  5. **$1\times1$ 且值为 $-10^9$**：正确 `-1000000000 1 1`，同时检验下界与初值。
  6. **单行 / 单列的最大值在中段且重复**：如 `1 4 / 2 8 8 1` → `8 1 2`；`4 1 / 2 / 8 / 8 / 1` → `8 2 1`。
  7. **最大值恰好是 0**：如 `2 2 / -3 -1 / 0 -2`，正确 `0 2 1`，用来抓住“初值 0 + 严格大于”导致永远不更新、位置停留在 (1,1) 的经典 bug。

  ## 7. 完整程序（GNU C++17，单文件，标准输入输出）

  ```cpp
  #include <cstdio>
  #include <climits>

  int main() {
      int n, m;
      if (std::scanf("%d %d", &n, &m) != 2) return 0;

      long long best = LLONG_MIN;
      int bestRow = 1, bestCol = 1;

      for (int i = 1; i <= n; ++i) {
          for (int j = 1; j <= m; ++j) {
              long long x;
              std::scanf("%lld", &x);
              if (x > best) {          // 严格大于：保证保留“第一次出现”
                  best = x;
                  bestRow = i;
                  bestCol = j;
              }
          }
      }

      std::printf("%lld %d %d\n", best, bestRow, bestCol);
      return 0;
  }
  ```
