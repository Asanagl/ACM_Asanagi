• ## 1. 任务、输入、输出与约束复述

  **任务**：给定一个由整数构成的 n 行 m 列矩阵 a。把满足“位于第 1 行、或第 n 行、或第 1 列、或第 m 列”的格子称为边框格子，求所有边框格子中元素的总和。位于四个角的格子同时属于两条边，但只能被计算一次。

  **输入格式**：第一行给出两个正整数 n 和 m，二者之间用一个空格分隔，分别表示行数和列数。随后给出 n 行，每行包含 m 个整数，同一行的整数之间用一个空格分隔；第 i 行第 j 个数就是 a_{i,j}。整个输入恰好包含 n·m 个矩阵元素。

  **输出格式**：向标准输出写入且仅写入一行，内容为一个十进制整数，表示所有边框格子元素之和。本题答案唯一，不能输出其他任何内容、多个整数，也不能缺少输出。

  **全部约束**：

  - 1 ≤ n ≤ 500，1 ≤ m ≤ 500；
  - 对每个元素，-10^7 ≤ a_{i,j} ≤ 10^7；
  - 输入恰好包含 n·m 个矩阵元素；
  - 资源限制：时间 1000 ms，内存 256 MiB，语言标准 gnu++17；
  - 边框格子个数不超过 1996，因此答案绝对值不超过 1996 × 10^7 = 1.996 × 10^10，该值超出 32 位有符号整数范围，必须用 64 位有符号整数保存；
  - Judge 语义：标准输出中必须恰好有一个十进制整数，其数值精确等于边框元素之和；多余文本、多个整数、缺失输出均不接受。

  ## 2. 算法

  逐格扫描，对每个格子做一次“是否属于边框”的布尔判定，只有判定为真时才累加：

  1. 读入 n、m，令 64 位有符号整数 `sum = 0`；
  2. 对 i = 1..n 和 j = 1..m 依次读入 a_{i,j}；
  3. 若 `i == 1 || i == n || j == 1 || j == m`，则 `sum += a_{i,j}`，否则跳过；
  4. 扫描结束后输出 `sum`。

  关键设计：对每个格子只做**一次**“四条边条件的逻辑或”判定，而不是先把四条边分别求和再减去四个角。前者天然避免了角落格子被重复累加，也不需要对 n=1 或 m=1 等情况做特殊处理。

  ## 3. 正确性证明

  记谓词 P(i,j) 为 `(i == 1) ∨ (i == n) ∨ (j == 1) ∨ (j == m)`。由题面定义，格子 (i,j)（1 ≤ i ≤ n，1 ≤ j ≤ m）是边框格子当且仅当 P(i,j) 为真。记边框格子集合为 B。

  **引理 1（枚举不重不漏）**：两层循环恰好把每个有序对 (i,j) ∈ {1..n} × {1..m} 处理一次。证明：外层 i 从 1 到 n 每个值取一次；对每个固定的 i，内层 j 从 1 到 m 每个值取一次；一次迭代的 (i,j) 由当次循环变量的取值唯一确定，不同迭代的循环变量取值不同，故对应的 (i,j) 互不相同；总迭代次数为 n·m，正好等于有序对的总数。因此每个格子被读入并判定恰好一次。

  **引理 2（循环不变式）**：设 S 为已处理过的格子集合，则在任意时刻有
  `sum = Σ_{(i,j)∈S} a_{i,j} · [P(i,j)]`，
  其中 [P] 在 P 为真时取 1、为假时取 0。

  证明（对迭代次数归纳）：
  - 初始 S = ∅，`sum = 0`，等于空和，成立。
  - 每步读入一个新格子 (i,j)（由引理 1，它不属于此前的 S），当且仅当 P(i,j) 为真时把 a_{i,j} 加进 `sum`。这等价于加上 a_{i,j}·[P(i,j)]，故不变式保持。
  - 循环终止时 S 为全部 n·m 个格子，不变式给出
    `sum = Σ_{1≤i≤n, 1≤j≤m} a_{i,j} · [P(i,j)]`。

  **定理（每个边框格子恰好计入一次）**：对任意 (i,j) ∈ B，由 B 的定义 P(i,j) 为真，[P(i,j)] = 1；又由引理 1 该格子在所有求和中恰好出现一次（有序对不重复），故它向最终 `sum` 贡献且仅贡献 a_{i,j} 一次。

  **定理（任何非边框格子都不被计入）**：若 (i,j) ∉ B，则 i ≠ 1、i ≠ n、j ≠ 1、j ≠ m 同时成立，P(i,j) 的四个析取项全为假，[P(i,j)] = 0，该格子在最终和中贡献 0；程序在读到它时也不会执行加法。

  **角落只算一次**：角落格子（如 (1,1)）同时使两个析取项为真，但 [P] 是对该格子的**单一** 0/1 判定，且该格子只被枚举一次，因此只累加一次。这一点正是采用“逐格逻辑或判定”而非“四边分别求和”的原因：后者会把角落算两次，必须再减去四角，容易在退化维度上出错。

  **退化维度的一致性**：
  - 若 n = 1，则对每个格子都有 i = 1，P 恒真，全部格子被计入；这与“只有一行时每个格子都在边框上”一致。
  - 若 m = 1，同理全部格子被计入。
  - 若 n = 2，则不存在满足 1 < i < 2 的行，每个格子都满足 i = 1 或 i = 2，P 恒真；这与“两行都是边框行、故所有格子都是边框格”一致。m = 2 同理。
  - 1×1 时四个条件全真，但只累加一次。

  **算术正确性（无溢出）**：n、m ≥ 2 时边框格子数为 2n + 2m − 4 ≤ 2·500 + 2·500 − 4 = 1996；n = 1 或 m = 1 时边框格子数为 n·m ≤ 500。故任一时刻 `sum` 的绝对值不超过 1996 × 10^7 = 1.996 × 10^10，远小于 2^63 − 1 ≈ 9.22 × 10^18。`long long` 的每次加法都是精确整数运算，不会溢出或舍入，所以程序输出等于数学上的精确和。

  综上，程序输出恰为所有边框格子元素之和，且每个边框格子恰好计入一次、任何非边框格子都不计入。

  ## 4. 复杂度

  - 时间复杂度：Θ(n·m)。每个格子被读入一次并做 O(1) 次比较与（可能的）一次加法；读入本身已是 Θ(n·m)，无法更优。最大 250 000 个格子，在 1000 ms 内非常充裕。
  - 额外空间复杂度：O(1)。只使用 n、m、`sum`、当前读入值 x 几个标量，不存储整个矩阵（输入流缓冲区不计入算法额外空间）。远低于 256 MiB。

  ## 5. 边界情况与高风险用例清单

  - **只有 1 行（n = 1）**：所有格子都在第 1 行（同时也是第 n 行），谓词恒真，答案应为整行之和。例：`1 3 / 1 2 3` → 6。若错误地写成“第一行 + 最后一行 − 角”而未合并同一行，会重复累加整行。
  - **只有 1 列（m = 1）**：同理，答案应为整列之和。例：`3 1 / 1 2 3` → 6。
  - **1×1**：唯一格子同时满足四个条件，但只能算一次。例：`1 1 / -7` → -7（题面样例 2）。
  - **只有 2 行（n = 2）**：两行都是边框行，所有格子都属于边框，谓词对所有 i 为真。例：2×3 全为 -1 → -6。若用“内部行排除”的思路而不注意内部行数为 0，容易漏算或越界。
  - **只有 2 列（m = 2）**：同理，所有格子都属于边框。
  - **2×2**：四个格子全是角落，各算一次，答案等于四元素之和。
  - **负数与全负矩阵**：直接累加，不能取绝对值、不能跳过负数，也不能用无符号类型。例：3×3 全为 -10^7 时边框 8 格，答案 -8×10^7。
  - **答案溢出 32 位**：500×500 全为 10^7 时，边框 1996 格，答案 19 960 000 000 > 2^31−1 ≈ 2.147×10^9；反向全为 -10^7 时答案 -19 960 000 000。必须用 `long long` 保存 `sum` 与读入值；用 `int` 会溢出并产生错误结果（有符号溢出还是未定义行为）。
  - **答案恰为 0**：例如边框元素正负抵消，须正常输出 `0`，不能因“和为 0”而误判为无输出。
  - **元素取边界值 ±10^7**：读入用 64 位类型可避免任何中间计算问题。
  - **最大规模 500×500**：250 000 个整数，输入可达数 MB；需关闭 `cin` 与 stdio 同步以保证 1000 ms 内读完。
  - **行末空格与换行差异**：用 `>>` 读取会自动跳过任意空白，对行末多余空格、`\r\n` 等稳健。
  - **角落重复计数**：3×4 样例答案 13（四角 1、4、-1、-4 各只算一次）；任何实现都应验证该样例。

  ## 6. 完整 C++17 程序

  ```cpp
  #include <iostream>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      int n, m;
      std::cin >> n >> m;

      long long sum = 0;
      for (int i = 1; i <= n; ++i) {
          for (int j = 1; j <= m; ++j) {
              long long x;
              std::cin >> x;
              if (i == 1 || i == n || j == 1 || j == m) {
                  sum += x;
              }
          }
      }

      std::cout << sum << '\n';
      return 0;
  }
  ```

  ## 7. 假设、无法证明之处与实现风险

  **假设**：

  - 输入严格符合题面：第一行两个正整数，随后恰好 n·m 个在 [-10^7, 10^7] 内的整数，无缺失、无多余、无非法字符；程序不做输入合法性校验。
  - Judge 按数值比较输出，允许整数后跟一个换行符（题面要求“输出一行”，换行是常规且符合“一行”的写法）。
  - 目标平台 `long long` 至少 64 位（C++ 标准保证，gnu++17 在主流平台成立）。
  - 250 000 次格式化读取在关闭同步后可在 1000 ms 内完成。

  **无法证明之处**：在题面保证的输入范围内，正确性、恰好一次计数、非边框排除、复杂度与无溢出均已给出证明，无未能证明的命题。

  **实现风险**：

  - 若实际 Judge 采用逐字节严格比较且不允许末尾换行（与常规 OJ 语义不符），需去掉 `'\n'`；按题面“输出一行”的常规语义，当前写法安全。
  - 若输入实际违反题面（如元素个数不足），`std::cin` 会读失败并使后续读取得到未定义值；题面保证不会发生，故未处理。
  - 未使用 `bits/stdc++.h` 等非标准头文件，仅依赖 `<iostream>`，可移植性与编译兼容性无风险。
