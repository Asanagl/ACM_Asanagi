• ## 1. 任务、输入格式、输出格式与约束（复述）

  **任务**：给定一个 $n$ 行 $m$ 列的整数二维数组，求出每一列所有元素之和，并按列号从小到大的顺序输出这 $m$ 个和。

  **输入格式**：第一行两个整数 $n$ 和 $m$。随后是 $n$ 行，每行 $m$ 个整数；第 $i$ 行第 $j$ 个数记作 $a_{i,j}$，即数组第 $i$ 行第 $j$ 列的元素。所有整数以空白（空格或换行）分隔。

  **输出格式**：输出**一行**恰好 $m$ 个十进制整数，用一个空格分隔，第 $j$ 个数等于 $\sum_{i=1}^{n} a_{i,j}$。不输出任何其他文本；个数、顺序、数值均须正确；行末换行与多余空白不影响判定。

  **约束**：
  - $1 \le n \le 1000$，$1 \le m \le 1000$，且 $n$ 与 $m$ 可以不相等（不保证方阵）。
  - $-10^9 \le a_{i,j} \le 10^9$，元素可为负数、零、重复值。
  - 每个列和的绝对值不超过 $10^{12}$。
  - 资源限制：时间 1000 ms，内存 256 MiB，语言标准 gnu++17（仅标准库）。
  - 答案唯一。

  ## 2. 算法

  一次读入，边读边累加：

  1. 读入 $n, m$；
  2. 开一个长度为 $m$ 的 64 位整型数组 `col[0..m-1]`，全部置 0；
  3. 按行优先顺序逐个读入全部 $n\times m$ 个整数。设当前读入的是第 $i$ 行（$i$ 从 1 开始）的第 $j$ 个（$j$ 从 1 开始），则执行 `col[j-1] += x`，即“读到第几个数就加到第几列”；
  4. 读完后，按 $j = 1,2,\dots,m$ 输出 `col[j-1]`，相邻两数之间插入一个空格，末尾输出一个换行。

  这是我在本题中给出的全部实现。（按要求，此为独立作答，未参考任何其他实现或数据。）

  ## 3. 正确性证明

  **记号约定。** 题面规定输入为 $n$ 行、每行恰 $m$ 个整数，第 $i$ 行第 $j$ 个数是 $a_{i,j}$。因此，在读完 $n,m$ 之后，输入的第 $k$ 个整数（从 1 开始计数）就是 $a_{i,j}$，其中 $k=(i-1)m+j$，$1\le i\le n$，$1\le j\le m$。这就是题面所称的“行优先”顺序。我把它作为输入约定赋给输入流，其正确性由输入格式本身保证。

  **引理 1（读到的数确实属于哪一列）。** 程序的双重循环按 $i=1..n$、$j=1..m$ 递增枚举。在进入迭代 $(i,j)$ 之前，程序已经读过的整数个数恰为 $(i-1)m+(j-1)$ 个（对 $i$ 与 $j$ 的双重归纳：每完成一次内层迭代多读 1 个，每完成一行多读 $m$ 个）。因此迭代 $(i,j)$ 读到的整数是输入的第 $(i-1)m+j$ 个整数，也就是 $a_{i,j}$。所以“读到的数”与“列号 $j$”之间的对应关系是正确的，不会错位。

  **引理 2（累加不变量）。** 对每个 $t\in[0,n]$ 与每个 $j\in[1,m]$ 成立：
  $$\texttt{col}[j]=\sum_{k=1}^{t} a_{k,j}.$$
  *归纳证明。*
  - 基础：$t=0$ 时全部 `col[j]` 为 0，即空和，成立。
  - 归纳步：假设 $t-1$ 时成立。第 $t$ 行的内层循环对 $j=1,2,\dots,m$ 依次执行一次 `col[j] += a_{t,j}`（由引理 1，读到的正是 $a_{t,j}$；该语句只写 `col[j]` 这一个位置，且每行对每个 $j$ 恰执行一次）。执行后
    $\texttt{col}[j]=\sum_{k=1}^{t-1} a_{k,j}+a_{t,j}=\sum_{k=1}^{t} a_{k,j}$，其余位置未被该次语句修改，故对所有 $j$ 同时成立。$\square$

  **推论 A（每列恰好累加 $n$ 个元素）。** 固定 $j$，内层语句 `col[j] += …` 在每一行恰好被执行 1 次，共 $n$ 行，故对 `col[j]` 恰好执行 $n$ 次加法；总加法次数为 $n\cdot m$，恰等于输入元素总数，因此没有元素被重复计入，也没有元素被遗漏。由引理 2 取 $t=n$：
  $$\texttt{col}[j]=a_{1,j}+a_{2,j}+\cdots+a_{n,j}.$$

  **推论 B（不混入其他列的元素）。** 由引理 1，第 $(i,j)$ 次读取的值是 $a_{i,j}$，而它被写入的数组下标恒为 $j$（下标只由当前内层循环变量 $j$ 决定，与行号或数值无关）。若 $j'\ne j$，则 $a_{i,j'}$ 在迭代 $(i,j')$ 中被写入 `col[j']`，从不写入 `col[j]`。因此 $\texttt{col}[j]$ 的 $n$ 个加数全部且仅仅是第 $j$ 列的 $n$ 个元素。

  **引理 3（输出内容与顺序）。** 输出循环按 $j=1,2,\dots,m$ 严格递增枚举，对每个 $j$ 恰好执行一次打印，且打印的值是 `col[j]`（此时已等于 $\sum_{i} a_{i,j}$）。当且仅当 $j>1$ 时先打印一个空格，因此相邻两个整数之间恰有一个空格，第一个整数前无空格，整数总个数恰为 $m$，末尾换行（按判题语义不影响结果）。故输出的第 $j$ 个整数正是第 $j$ 列的和。

  **定理。** 程序输出的整数序列恰为 $\left(\sum_{i=1}^n a_{i,1},\ \sum_{i=1}^n a_{i,2},\ \dots,\ \sum_{i=1}^n a_{i,m}\right)$，个数为 $m$，顺序与列号一致。又题面保证答案唯一，故结论唯一且正确。

  **数值不溢出（正确性的一部分）。** 任一时刻 $\texttt{col}[j]$ 是某一列不超过 $n$ 个元素的子集和，而任一列和的绝对值上界为 $n\cdot 10^9\le 10^{12}$，且由三角不等式可知任意前缀和绝对值 $\le 10^{12}$；$10^{12}<2^{63}-1\approx 9.22\times10^{18}$，故使用 `long long` 全程无溢出（用 32 位 `int` 则会错，例如样例 3 的 $3\times10^9$）。

  ## 4. 复杂度

  - 时间：读入 $n\cdot m$ 个整数并各做一次加法，输出 $m$ 个整数，总计 $O(nm)$，最大约 $10^6$ 次基本操作，远低于 1000 ms。
  - 额外空间：`col` 数组 $O(m)$，其余为常数；不存储整个矩阵。总计 $O(m)\le 1000$ 个 `long long`，约 8 KB。

  ## 5. 边界与高风险用例清单

  | 用例 | 输入 | 期望输出 | 考察点 |
  |---|---|---|---|
  | 1×1 | `1 1` / `-7` | `-7` | 最小规模，唯一元素既属第 1 行又属第 1 列 |
  | 仅 1 行 | `1 3` / `-2 0 5` | `-2 0 5` | $n=1$，每列只有 1 项；负、零混合 |
  | 仅 1 列 | `4 1` / `1` `-1` `0` `1000000000` | `1000000000` | $m=1$，不得输出多余空格外内容或多于 1 个数 |
  | 非方阵（宽） | `2 3` / `1 2 3` / `4 5 6` | `5 7 9` | 输出 $m=3$ 个数而非 $n=2$ |
  | 非方阵（高） | `3 2` / `1 2` / `3 4` / `5 6` | `9 12` | 输出 $m=2$ 个数而非 $n=3$ |
  | 全负数 | `2 2` / `-1 -2` / `-3 -4` | `-4 -6` | 负和、符号输出 |
  | 全零 | `2 2` / `0 0` / `0 0` | `0 0` | 零值输出，不得省略任何 0 |
  | 重复值 | `3 2` / `5 5` / `5 5` / `5 5` | `15 15` | 精确计数，不得漏加或多加 |
  | 超出 32 位 | 样例 3：`3 2` / `1000000000 1` / `1000000000 -1` / `1000000000 0` | `3000000000 0` | 必须用 64 位，`int` 会溢出 |
  | 极值负和 | `1000 1`，1000 行全为 `-1000000000` | `-1000000000000` | 下界 $-10^{12}$，64 位仍安全 |
  | 极大正和 | `1000 1`，1000 行全为 `1000000000` | `1000000000000` | 与“绝对值不超过 $10^{12}$”一致，仍需 64 位 |
  | 列和抵消 | `2 2` / `1000000000 -1000000000` / `-1000000000 1000000000` | `0 0` | 大数相加为 0，不得被误判为“缺输出” |
  | 最大规模 | $n=m=1000$，$10^6$ 个随机数 | — | 性能与 IO 缓冲；输出恰好 1000 个数 |
  | 换行/空格形式异常 | 第 $i$ 行内容跨多行或被多个空格分隔 | 同正常情形 | 用 `>>` 按空白切分，不依赖行结构 |

  ## 6. 完整 C++17 程序

  ```cpp
  #include <iostream>
  #include <vector>

  int main() {
      std::ios::sync_with_stdio(false);
      std::cin.tie(nullptr);

      int n = 0, m = 0;
      if (!(std::cin >> n >> m)) return 0;

      std::vector<long long> col(m, 0);

      for (int i = 0; i < n; ++i) {
          for (int j = 0; j < m; ++j) {
              long long x = 0;
              std::cin >> x;
              col[j] += x;
          }
      }

      for (int j = 0; j < m; ++j) {
          if (j > 0) std::cout << ' ';
          std::cout << col[j];
      }
      std::cout << '\n';

      return 0;
  }
  ```

  ## 7. 假设、无法证明之处与实现风险

  **依赖的假设**
  1. 输入恰为 $n,m$ 加上 $n\cdot m$ 个整数，且这 $n\cdot m$ 个数按“先行后列、行内从左到右”的顺序排列（题面输入格式已给定）。程序不校验元素总数；若输入不合法（缺数或多出数），行为未定义，但这不是本题需要处理的输入。
  2. 数字之间由任意空白（空格、制表、换行）分隔；由于使用 `>>`，即使换行位置与题面的行结构不同也能正确解析，这与“输入第 $k$ 个数即 $a_{i,j}$”的约定一致。
  3. gnu++17 环境下 `long long` 至少 64 位（C++ 标准保证），足以容纳 $10^{12}$ 级数值。
  4. 第一行可以成功读入 $n,m$；否则程序静默正常退出（不产生输出），属不可达分支。

  **无法证明之处**：无。在题面给定的输入约定下，第 3 节的论证是闭合的：在每列恰好累加 $n$ 个元素、不混入其他列元素以及输出顺序和个数方面，没有遗留的未证环节。

  **实现风险（均已评估为低）**
  - IO 性能：最坏 $10^6$ 个整数，使用关闭同步与解除 `cin` 绑定的 `std::cin` 通常在数十毫秒内完成，远低于 1000 ms。若极端判题机上仍需更快，可换成基于 `getchar` 的手写读入，但当前规模下不是必要手段。
  - 溢出：已论证 $|$部分和$|\le 10^{12}$，`long long` 安全；**唯一真实风险是把 `col` 或 `x` 误声明为 `int`**，本实现已避免。
  - 输出格式：仅输出 $m$ 个整数与分隔空格，末尾一个换行；不输出任何提示文本，符合“不得输出其他文本、不得缺少或多出整数”的要求。
